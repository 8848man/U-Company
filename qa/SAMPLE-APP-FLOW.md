# 샘플 앱 흐름 점검 (QA-50)

U컴퍼니로 작은 앱을 처음부터 끝까지 만들어 보는 수동 점검이다. A는 토큰 없이 모의 AI로 흐름만, B는 실제 Claude/Codex로 같은 목표를 돌린다. 배경: [완주율·사용성 개선 라운드](../sdd/completion-usability-rounds.md), [ADR-0052](../sdd/architecture/decisions/ADR-0052.md)~[ADR-0054](../sdd/architecture/decisions/ADR-0054.md). 엔진 흐름 자체는 `cargo test --locked --lib engine_e2e`가 이미 자동으로 확인한다. 이 점검은 **실제 Windows 앱 화면**과 **실제 AI**를 본다.

## 0. 준비 (한 번)

1. 저장소가 `feature/completion-usability-rounds` 브랜치인지 확인한다: `git -C D:\projects\utopia_company branch --show-current`.
2. Node.js(모의 AI용)와 기존 개발 준비물(README의 Node 22, Rust, Tauri 준비물)이 있는지 확인한다: `& D:\projects\utopia_company\v3\start-windows.ps1 -CheckOnly`.
3. 시험용 **빈 폴더**를 저장소 밖에 하나 만든다. 예: `D:\projects\u-sample-todo-mock`. Git으로 시험하려면 그 폴더에서 `git init -b main` 후 빈 커밋(`git commit --allow-empty -m init`)을 만들어 둔다. 일반 폴더로 둬도 된다.

## A. 모의 AI로 끝까지 (토큰 없음, 약 2분)

1. 별도 데이터로 v3를 연다: `& D:\projects\utopia_company\v3\start-windows.ps1 -DataDir .run-data\sample-mock`.
2. 프로젝트 폴더를 고른다(준비 3의 폴더). 홈에 **첫 목표 준비** 카드가 보이고 `AI 연결`이 `!`이어야 한다.
3. `AI 연결하기` → `AI 추가` → **토큰 없이 흐름만 시험하기**에서 `끝까지 완주`를 두고 `모의 AI 추가`. 토스트가 "모의 AI를 등록하고 AI가 없는 팀원에게 배정했습니다"이고 AI 연결 목록에 `모의 AI (테스트용, 토큰 없음)`이 보여야 한다.
4. 홈으로 돌아가면 첫 목표 준비의 세 줄이 모두 `✓`(일반 폴더면 Git만 `!`, 그래도 진행 가능)이어야 한다.
5. `샘플 앱 만들어 보기 →`를 눌러 목표 문장을 채우고 보낸다.
6. 대화에 진행 줄(분석 → 계획)이 나오고 **계획 카드**가 뜬다. 확인할 것:
   - 작업 2개 · 팀원 수 · 파일 5개
   - "승인하면 AI를 약 N번 불러요 (작업 2 · QA 1 …)"와 토큰·다시 고치기 한 줄
   - 승인 전 프로젝트 폴더에 새 파일이 **없다**
7. `승인`. 팀 작업 → 합치기 → QA 진행 줄 뒤 목표가 완료된다.
8. 결과 칸 맨 위에 **바뀐 파일 5개**(`todo.js`, `todo.test.js`, `index.html`, `style.css`, `main.js`), **해 보는 법**(index.html 더블클릭, `node --test`), `폴더 열기`가 있어야 한다.
9. `폴더 열기`로 탐색기가 열리고, `index.html`을 더블클릭해 할 일 추가·완료 표시·삭제·새로고침 후 유지가 되는지 본다. 그 폴더에서 `node --test`가 통과해야 한다.

### A-2. 복구 경로 (선택)

AI 연결 › AI 추가에서 모의 AI 방식을 바꿔 다시 추가한 뒤(같은 연결이 바뀜), **목표 문장을 조금 바꿔** 새 목표로 보낸다(같은 문장이면 "한 번 실패"가 다시 나오지 않는다).

| 방식 | 기대 화면 |
| --- | --- |
| QA가 한 번 실패 | QA 실패 → "PM이 QA 지적을 고칠 재작업…" → 재작업 → QA 통과 → 완료. 재작업 1/2 |
| 계획 형식이 한 번 틀림 | "계획 형식이 맞지 않아 PM에게 한 번 더 받았어요" 한 줄 뒤 계획 카드 |
| QA 실패 후 고칠 때 새 파일이 필요 | 금색 테두리 **고칠 때 새 파일이 필요해요** 카드(README.md). `파일 추가 승인` → 같은 대화에서 완료, `계획 v2` 구분선 없음. 다른 목표로 `거절` → 목표가 멈추고 설정 › 프로젝트의 **목표가 멈춘 이유**에 "새 파일 승인이 필요함 1번" |

## B. 실제 AI로 같은 목표

1. 새 빈 폴더(예: `D:\projects\u-sample-todo-real`)와 새 데이터로 연다: `-DataDir .run-data\sample-real`.
2. AI 연결에서 Claude 또는 Codex를 등록하고 로그인 상태를 확인한다. 첫 목표 준비가 모두 `✓`인지 본다.
3. A와 같은 `샘플 앱 만들어 보기` 목표를 보내고 계획 카드를 승인한다.
4. 끝날 때까지 개입 없이 둔다. 멈추면 `지금 할 일`의 `해결 요청`을 한 번 써 본다.
5. 아래 기록표를 채운다. 실제 AI는 파일 이름·개수가 A와 달라도 된다. 결과 칸의 해 보는 법대로 앱이 실제로 동작하는지가 기준이다.
