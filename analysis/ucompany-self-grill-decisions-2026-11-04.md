# uCompany Self grill 후속 결정안 — 2026-11-04

## 결정의 효력

세 서브 에이전트가 [Self grill 93문항](ucompany-self-grill-2026-11-04.md)의 제품(`P`), 엔진(`E`), UX·승인(`U`, `G`) 항목을 나눠 검토했고, Codex가 소유 SDD·코드·QA와 충돌하는 권고를 대조했다. 아래는 **검증·정정·보류의 작업 우선순위 결정안**이다. 제품 규칙의 변경, 프로젝트 파일 쓰기 승인, AI 전송 승인, 위험 명령 승인, 외부 행동 승인이 아니다. 현행 규칙은 [Product](../sdd/product.md), [Security](../sdd/security.md), [Validation](../sdd/validation.md)가 소유한다. 아직 고객 실험이나 실제 Windows·제공자 시험을 새로 수행하지 않았다.

`유지·검증`은 현행 계약을 바꾸지 않고 실행 증거를 얻는다. `가설 시험`은 제품 가치를 수치와 사용자 행동으로 판정한다. `정정`은 현재 코드·QA 기준과 어긋난 기록을 확인해 바로잡는다. `보류`는 선행 증거 전까지 확장하거나 완료를 주장하지 않는다. **권고를 채택해도 질문이 닫히지는 않는다.** 원본 결과가 있어야 닫힌다.

## 우선 실행 순서

1. **승인과 원장:** E21·G02/03의 실제 전송 내용/목적지, E03–E05·E08–E12·E16의 선점·통합·QA·재전송 방지를 실행 증거로 확인한다. 승인 버튼은 실제 CEO만 누른다.
2. **실제 앱 완주:** QA-39에서 Windows 목표→계획→승인→병렬 문서→산출물별 QA→인수와 중단·재시작·충돌을 기록한다. QA-36/37/38과 QA-50의 열린 상태도 유지한다.
3. **고객 효용:** 같은 자료와 평가표로 단일 AI 사용 방식과 비교하고 잠재 고객 5–10명의 실제 목표에서 결정 변화, 사람의 활성 시간, 근거 오류, 유료 의사를 기록한다. 이 수는 학습용 제안이며 성공 선언 기준이 아니다.
4. **기록 정정:** U16의 QA-39 시작 스크립트 드리프트, E15의 재사용 충돌 스냅샷 과거 설명, E21의 v4 전송 미리보기 과거 설명을 현재 코드와 시점에 맞춰 정정한다. U17의 v2 문구는 실제 도달 경로 확인 후 정정한다.
5. **확장 보류:** 대표 고객군 확정, 가격, 범용성, 외부 조사·게시·고객 연락, 네이티브 세션 자동 재개, 성능 달성 주장은 각 선행 증거와 별도 CEO 결정을 기다린다.
