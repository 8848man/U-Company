# uCompany Self grill — 2026-11-04

## 목적과 판정 방법

제품의 주장에 가장 불리한 질문을 먼저 묻는다. 각 질문은 결함 확정이 아니라 **반증 가능한 검증 과제**다. `P0`는 대표 사용 사례나 완료 주장을 하기 전에 답할 질문, `P1`은 파일럿과 인수 품질을 좌우할 질문, `P2`는 확장 전에 답할 질문이다. 질문을 많이 만드는 것 자체를 진척으로 세지 않는다. 원본 결과와 사용자 행동으로 닫힌 항목만 해결로 센다.

이번 검토는 SDD, 워크로그, QA와 일부 현행 코드의 **읽기 전용 대조**다. 고객 인터뷰, 실제 제공자 호출, Windows 데스크톱 QA, Rust 시험 실행은 이번에 하지 않았다. 작업 폴더에는 이미 여러 수정·미추적 파일이 있었고, 이 검토는 그 내용을 고치거나 완료로 판정하지 않는다. 소유 규칙은 [Product](../sdd/product.md), [Security](../sdd/security.md), [Validation](../sdd/validation.md), [v3 개선안](../sdd/v3-improvement-plan.md)을 따른다. 실제 검증 상태는 [열린 v3 검증](../worklog/programs/v3-first-package/open-verification.md), [WLG-063](../worklog/milestones/WLG-063.md), [수동 QA](../qa/MANUAL-QA.md)를 대조했다.

**현재 잠정 결론:** uCompany는 목표·위임·승인·격리 통합·QA·복구의 계약을 상세하게 정의했으나, 첫 고객이 기존 방식보다 적은 조율 노력으로 더 나은 실제 결정을 내리고 비용을 지불한다는 증거는 아직 제시되지 않았다. QA-39와 v2 QA-36/37/38이 열려 있고, WLG-063의 Rust 실행·v3 빌드 실패는 코드 존재와 실제 통과를 구별해야 한다는 신호다. 이는 제품 가치가 없다는 판정이 아니다.

## 먼저 닫을 압박 질문과 중단 기준

1. **실사용 가치:** P01–P06, P11–P14를 실제 고객 과제로 확인한다. 단일 AI 대비 개선이 관찰되지 않으면 역할·화면 범위를 줄이고 고객 문제를 다시 고른다.
2. **진실한 인수:** P21–P25, P28, E16, U07–U09를 원문 대조와 사용자 행동으로 확인한다. 근거가 부정확하거나 QA PASS가 과장되면 “검증됨” 표시를 제한한다.
3. **실행 가능성:** E03–E05, E08–E12, E18, E20–E21, U01–U03를 실행 가능한 환경에서 검증한다. Windows QA-39가 끝나기 전에는 파일럿 종단 완료를 주장하지 않는다.
4. **증거 정리:** 현재 코드에는 `reuseConflicts` 전달 경로가 보인다([model.rs](../src-tauri/src/model.rs), [storage.rs](../src-tauri/src/storage.rs), [v3 App](../v3/src/App.tsx)). [WLG-063](../worklog/milestones/WLG-063.md)의 앞선 미연결 진술은 시점이 다른 기록으로 읽어야 한다. 실제 화면 전달은 여전히 미검증이다. v4 AI 전송 미리보기 역시 현행 코드에 경로가 있으므로 과거 “없다”는 기록을 현재 결함으로 단정하지 않고 실제 payload·목적지·호출 수로 판정한다.

**현재 닫힌 문항: 0/93.** 이는 전 항목이 실패했다는 뜻이 아니라, 이번 읽기 전용 검토에서 새 실행·고객 증거를 얻지 않았다는 뜻이다. 각 ID를 닫을 때 시험 환경, 원본 자료, 예상/실제 결과, 승인·호출·파일 변경 원장을 함께 기록한다.
