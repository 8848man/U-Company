Utopia Company · WLG-091 · 2026-11-17

uCompany 개발 업무의 CLI 에이전트 입력 토큰 배수:
10월 3.3~4.2배 → 11월 1.2~1.7배

uCompany가 같은 개발 업무를 Claude Code(claude-opus-5-5)와 Codex CLI(gpt-6-sol)에 맡겼을 때, 각 CLI가 기록한 입력 토큰을 비교했다. 10월 레벨 4·5 기록과 11월 측정을 대조했고, 배수는 크게 줄었다. 다만 같은 과제로 지침만 바꾼 Before·After 측정에서는 집중 지침의 효과가 드러나지 않았다. 줄어든 주된 이유는 과제 크기와 Claude의 내부 응답 횟수로 보인다.

이 배수가 뜻하는 것: 이 앱에서 업무를 어느 CLI 에이전트에 맡길지 판단하는 자료다. 모델 효율 비교도, 비용 비교도 아니다. 두 회사는 토크나이저가 달라 같은 글도 토큰 수가 다르게 세어지고, CLI마다 매 응답에 붙는 기본 지침·도구 정의가 다르며, 구독 한도와 캐시 할인 계산도 다르다(아래 한계 참고).

CLI 에이전트 입력 토큰 배수 (Claude Code ÷ Codex CLI)

입력은 각 CLI가 기록한 총 입력 토큰이다(각 회사 토크나이저 기준). Claude는 기본 입력 + 캐시 생성 + 캐시 읽기, Codex는 캐시를 포함한 입력이다. 앱과 CLI 측정 행은 개발 업무 한 건만 비교한다. CLI 측정은 중앙값.

모델 이름은 각 CLI의 세션 로그에 기록된 값이다(Claude message.model, Codex turn_context.model). 추론 강도는 둘 다 medium이다(Claude Code effortLevel, Codex model_reasoning_effort, 2026-11-17 설정 기준. 10월 실행 당시 값은 기록이 없다). 앱은 모델·추론 강도를 따로 지정하지 않고 각 CLI 기본 설정으로 호출한다. CTO·PM·QA는 모두 Claude 연결이며 이 비교에 넣지 않았다.

10월: Claude가 응답을 1.7배 더 하고(28·25회 대 17·15회), 응답당 입력도 2.0~2.5배였다. 긴 작업에서 문맥이 쌓이며 응답당 입력이 10만~14만까지 커졌다.
11월: Claude 응답 횟수가 Codex와 같거나 더 적다(0.6~0.8배). 응답당 입력 비는 약 1.8~2.1배로 남았다. Claude는 작은 과제에서도 응답마다 약 4만 토큰, Codex는 약 2.2만 토큰이 기본으로 들어간다. 이 기본량은 모델보다 각 CLI의 시스템 지침·도구 정의 크기와 토크나이저 차이에서 오는 것으로 보이며, 이번 측정으로는 둘을 나누지 못한다.

고정 과제 Before·After: 실행별 입력

같은 헬프데스크 과제와 같은 요청문에서 집중 지침 한 단락만 끄고 켰다. 점 하나가 실행 한 번, 세로 막대가 중앙값이다. 16회 모두 숨은 합격 시험 4/4를 통과했고 선언 밖 파일 변경은 없었다.

지침 효과는 확인되지 않았다. 중앙값 배수는 Before 1.17배, After 1.41배다. 실행 간 편차(Claude 15.5만~29.8만, Codex 10.1만~22.8만)가 조건 간 차이보다 크다. 이 과제는 응답 4~10회로 끝나서, 탐색을 줄이는 지침이 작동할 여지가 거의 없다.

측정 값 표

한계

  • 모델 효율 비교가 아니다. Claude Code와 Codex CLI라는 에이전트 전체(모델 + CLI 지침·도구 + 실행 방식)를 앱이 쓰는 그대로 비교했다. 같은 모델이라도 다른 CLI에서 돌리면 숫자가 달라진다.
  • 토큰 단위가 다르다. 두 회사의 토크나이저가 달라 같은 글자도 토큰 수가 다르다. 배수 일부는 처리량이 아니라 단위 차이일 수 있으며, 이번 측정으로 그 몫을 분리할 수 없다.
  • 토큰은 비용·한도와 같지 않다. 토큰 가격, 캐시 할인, 구독 한도 계산이 제공자마다 다르다. 원래 문제였던 한도 소모를 비교하려면 한도 사용률을 따로 재야 한다. Codex 로그에는 한도 사용률이 1% 단위로 남지만 작은 실행 한 번으로는 움직이지 않았고(63% 유지), Claude Code 로그에는 이 값이 없다.
  • 모델 급이 같은지 확인하지 않았다. Opus 5.5는 Anthropic의 상위 모델이다. gpt-6-sol이 OpenAI 라인업에서 어느 급인지는 이 측정에서 확인하지 않았다.
  • 과제가 다르다. 10월은 13~15개 파일의 레벨 4·5, 11월은 6개 파일의 할 일 앱과 2개 파일의 고정 과제다. 3.3~4.2배에서 1.7배로 준 것을 집중 지침의 효과라고 말할 수 없다.
  • 같은 과제 Before·After는 작은 과제 하나뿐이다. 레벨 4·5 크기 과제에서 지침을 끄고 켠 비교는 사용량이 커서 하지 않았다. 지침이 큰 과제의 탐색 횟수를 줄이는지는 아직 측정되지 않았다.
  • CLI 버전이 바뀌었다. 모델은 같지만 Claude Code 2.1.296→2.1.325, codex-cli 0.159.3→0.169.0이다. CLI 자체의 시스템 지침·도구 변화가 섞여 있다.
  • 반복 횟수가 적다. 앱 측정은 각 1쌍, CLI 측정은 조건마다 3~5회다. 첫 라운드 Before 2회는 기록 없이 실패해 빠졌다. 중앙값의 신뢰구간은 넓다.
  • 개발 업무만 비교했다. 11월 앱 목표 전체에서는 CTO·PM·QA(모두 Claude)가 약 75만 토큰으로 개발 두 건(29만)보다 컸다.
  • 품질 비교는 얕다. 모든 실행이 합격 기준을 통과했지만, 합격 시험 4개와 QA 판정 외의 코드 품질은 평가하지 않았다. 속도(Claude 약 50초, Codex 약 100초)와 테스트 수(할 일 앱 11개 대 8개)도 달라, 토큰만으로 우열을 말할 수 없다.

방법과 재현

  • 고정 과제: tests/token-bench/ (헬프데스크 큐 규칙, 숨은 합격 시험 check.test.mjs).
  • 실행기: cargo run --bin token-bench -- run <claude|codex> <before|after> --out FILE. 앱이 개발자에게 보내는 요청문과 CLI 호출 경로를 그대로 쓰고, 매번 새 Git 폴더에서 실행한다.
  • 집계: node scripts/token-bench/collect.mjs FILE. 세션 ID로 각 CLI 로그(압축 로그 포함)를 찾아 응답 횟수·캐시·모델·CLI 버전을 센다. Claude 응답은 메시지 ID, Codex 응답은 response ID로 한 번씩만 센다.
  • 원자료: tests/token-bench/results/runs.collected.jsonl(CLI 16회), app-records.collected.jsonl(앱 기록 6건).
