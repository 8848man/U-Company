# WLG-079 — 외부 어댑터 진행 이벤트·취소·재개 선언 (ADR-0070)

2026-11-10, Claude. 남은 과제 "외부 어댑터 프로토콜에 이벤트 스트리밍, 취소, 세션 재개 추가"(초기 체크리스트 [WLG-054](WLG-054.md)의 런타임 이벤트·취소·세션 재개).

## 변경

- [ADR-0070](../../sdd/architecture/decisions/ADR-0070.md): 프로토콜 v1을 유지하면서 선택 기능 세 가지를 더했다. 기능을 선언하지 않은 어댑터는 예전과 똑같이 동작한다.
  - `initialize` 결과의 `capabilities`(`events`, `cancel`, `resume`)
  - `send_task` 중 진행·토큰 이벤트 알림. 표시용 텍스트로만 쓰고 상태를 바꾸지 않는다.
  - 취소 요청(`cancel`, 5초 유예 후 종료)과 `resume`을 선언한 어댑터에만 `resumeSession` 전달
- `runtime.rs`
  - `run_plugin`이 결과가 올 때까지 모든 줄을 읽는다. 이전에는 두 줄만 읽었다.
  - 이벤트를 CLI와 같은 진행·토큰 관찰자로 넘긴다.
  - 취소 신호와 시간 초과 때 선언된 어댑터에 취소 요청을 보낸다.
  - 결과 없이 끝난 어댑터는 실패로 처리한다.
  - CLI 프로세스 전송도 취소 신호를 받으면 프로세스를 끝낸다.
- `provider.rs`: `CallOptions.cancel`을 추가하고 어댑터 경로에도 관찰자를 넘긴다.
- 모의 AI: `events`·`cancel`을 선언하고, 결과 전에 진행 이벤트 하나를 보내며, `cancel`을 받으면 끝낸다.
- 명세: AI-03(프로토콜 절), AI-04(진행·토큰), Validation, ADR 색인.

## 검증·한계

- 새 단위 시험 7개(합성 어댑터와 CLI 프로세스)를 추가했고, 목표 종단 시험에서 모의 AI의 진행 이벤트가 목표 기록에 남는지 확인했다.
- `cargo test`: 두 번 연속 245 통과, 0 실패, 3 무시(Windows). `cargo clippy --all-targets`: 경고 0.
- 실제 제3자 어댑터로는 확인하지 않았다.
- **아직 화면에서 취소를 거는 동작은 없다.** 실행 중인 목표·회의 호출을 CEO가 멈추는 버튼과 그 뒤 목표 상태는 별도 제품 결정이다. 지금은 30분 시간 초과만 취소 신호를 쓴다. 회의의 "이미 시작한 호출은 회수하지 않음" 규칙도 그대로다.
