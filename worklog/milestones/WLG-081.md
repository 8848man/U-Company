# WLG-081 — 개발 빌드 디버그 정보 축소와 용량 게이트

2026-11-10, Codex. 사용자 요청: 개발 프로필의 디버그 정보를 줄이고, 빌드 때 용량을 확인해 이 조치만으로 충분한지 판단한다. 나머지 대안도 SDD에 보존한다.

## 범위

- [Build storage](../../sdd/build-storage.md)와 [ADR-0071](../../sdd/architecture/decisions/ADR-0071.md)에 기본 프로필, 비교 게이트, 대안과 순서를 기록했다.
- `src-tauri/Cargo.toml`: 개발 프로필의 앱 줄 번호 정보와 의존성 디버그 정보 없음. 상세 디버깅은 `debugging` 프로필로 선택한다.
- v4 Tauri npm 실행 전후와 수동 `npm run rust:storage`로 `debug` 전체·영역별·PDB 용량을 기록한다. `.run-data/rust-build-storage.jsonl`은 로컬 측정 기록이며 Git에서 제외된다.

## 관측 및 검증

- 변경 전 누적 상태: `debug` 15.22 GiB(`deps` 8.08, `incremental` 3.86, 최상위 1.81, `build` 1.47). 측정 도구 첫 실행은 15.27 GiB, PDB 3.37 GiB, D: 여유 885.39 GiB였다.
- `cargo metadata --no-deps`: 프로필 설정 해석 통과. 측정·정리 스크립트 Node 집중 시험 3개 통과.
- `cargo clean --profile dev`는 기존 `target/debug/deps/ai_organization_os.exe` 삭제에서 Windows `os error 5`로 중단했다. 재시도와 권한 확장 실행에서도 동일했다. 일부 기존 산출물만 정리되어 원래 출력 경로는 깨끗한 비교군이 아니다.
- 깨끗한 비교를 위해 `src-tauri/target/storage-profile-check`에 별도 Cargo 출력을 지정했다. `cargo build --locked` 4분 40초, 종료 코드 0: `debug` 2.61 GiB, PDB 0.38 GiB.
- 첫 `cargo test --locked` 실행은 샌드박스의 임시 Git 저장소·루프백 소켓 제한으로 191개 통과·54개 실패였다. 같은 빌드 결과를 필요한 실행 환경에서 재실행해 245개 통과·0개 실패·3개 무시를 확인했다. 테스트 산출물까지 `debug` 3.20 GiB, PDB 0.44 GiB.
- 이어진 `cargo build --locked` 종료 코드 0, 22.55초: `debug` 3.87 GiB. 같은 명령을 입력 변경 없이 다시 실행해 1.54초, `debug` 3.87 GiB로 유지됐다. Rust가 증분 캐시 하드 링크를 만들지 못해 복사했다는 경고는 있었으나 두 번째 무변경 빌드의 용량은 증가하지 않았다. 실패 시험의 패닉은 소스 줄 번호(`src/discovery.rs:428:45`)를 표시했다.
- 대표 순서의 3.87 GiB에 약 29% 여유를 둔 5 GiB 예산과 무변경 반복 빌드 증가 0.25 GiB 이하를 [Build storage](../../sdd/build-storage.md)의 지속 검증 게이트로 확정했다. Node 집중 시험 3개 통과, `git diff --check` 통과.
- 기존 기본 `target/debug`는 첫 Cargo 정리 중단 후 12.35 GiB였다. 배타적 파일 열기 진단은 `deps/ai_organization_os.exe`가 **다른 프로세스에 사용 중**이라고 확인했다. 실행 중인 앱·Cargo·rustc는 일반 프로세스 조회에서 보이지 않았고 잠금 주체는 특정하지 못했다.
- 경로가 저장소의 `target/debug` 안인지, 빌드 프로세스와 reparse point가 없는지 확인한 뒤 잠긴 파일 하나를 제외한 생성 파일 5,960개를 정리했다. 기본 경로의 `cargo build --locked`는 대부분 다시 컴파일했으나 마지막 링크에서 그 실행 파일을 열 수 없어 `LNK1104`로 실패했다. 현재 기본 경로는 2.48 GiB로 예산 안이지만 **빌드 실패이므로 충분성 게이트는 미통과**다.
- 별도 검증 경로는 측정 후 `cargo clean --target-dir`로 3.9 GiB를 회수했다. 이 경로를 계속 남겨 디스크를 더 차지하지 않는다.

## 다음 행동

기존 `target/debug/deps/ai_organization_os.exe` 잠금이 풀린 후 기본 경로의 `cargo build --locked`를 완료하고 `npm run tauri:v4`의 용량 보고·실제 앱 시작을 확인한다. 기본 경로의 대표 빌드가 5 GiB와 반복 증가 조건을 통과하면 이번 조치로 충분하다고 기록한다. 깨끗한 빌드도 한도를 넘으면 명세의 두 번째 대안을 검증한다. 현재 다른 대안을 바로 적용할 근거는 없다.

## 후속 확인 (2026-11-10)

[WLG-083](WLG-083.md)에서 기본 경로의 빌드·전체 Rust 시험·반복 빌드와 v4 개발 앱의 실제 Windows 창 시작을 확인했다. 최종 `debug` 4.05 GiB, 무변경 재빌드 증가 측정상 0 GiB로 충분성 게이트를 통과했다. 이전의 실행 파일 잠금과 `LNK1104`는 재현되지 않았다.
