# WLG-075 — Windows에서 Rust 시험이 시작되게 함

2026-11-10, Claude. WLG-063·066·067·070·072에서 Rust 시험 실행 파일이 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`로 시작되지 않아 엔진 시험을 Windows에서 하나도 돌리지 못했다.

## 원인

`tauri_build::build()`는 Common-Controls v6 앱 매니페스트를 앱 실행 파일에만 넣는다. `cargo test`의 시험 실행 파일은 매니페스트가 없어 옛 comctl32를 불러오고, v6에만 있는 진입점을 찾지 못해 시작 직후 멈춘다.

## 변경

- `src-tauri/build.rs`: `WindowsAttributes::new_without_app_manifest()`로 tauri-build의 매니페스트를 끄고, MSVC Windows 대상에서 링커 인자(`/MANIFEST:EMBED`, `/MANIFESTINPUT`)로 같은 매니페스트를 시험 실행 파일을 포함한 모든 링크 대상에 넣는다. 앱 실행 파일의 매니페스트 내용은 그대로다.
- `src-tauri/windows-app-manifest.xml`: tauri-build 2.6.3에 들어 있는 기본 매니페스트를 그대로 복사했다.
- `src-tauri/src/mock_ai.rs`: 모의 AI 어댑터(`scripts/mock-ai/mock-adapter.mjs`)는 이미 지원하지만 Rust 허용 목록에 빠져 시험이 "모르는 모의 AI 방식"으로 실패하던 7개 방식(`needs-auto-read-once`, `needs-auto-remove-once`, `qa-needs-auto-read-once`, `pm-continue-without`, `pm-extra-denial`, `pm-malformed`, `pm-retry-existing`)을 추가했다. 시험이 실행되지 않아 드러나지 않던 결함이다.

## 검증

- `cargo test`: 시험 실행 파일이 시작된다. 241개 중 **219 통과, 19 실패, 3 무시**.
- `permissions`·`permissions_flow`·명령 권한 종단 시험(ADR-0063·0065·0066·0067과 PR #23 병합 해소 포함)은 통과했다.

## 남은 실패 19개 (다음 마일스톤)

| 묶음 | 시험 | 관찰된 실패 |
| --- | --- | --- |
| Windows 파일 잠금 | `delegation::tests` 3개 | `os error 32`(다른 프로세스가 파일 사용 중) |
| 재사용 증거 해시·줄바꿈 | `engine::tests` 3개 | 재사용 증거 SHA-256 불일치, 선언 파일 통합 검사, `"결과\r\n"` 비교 |
| 연결 목표 재사용(ADR-0068) | `engine_e2e::linked_reuse_*` 6개, `approved_linked_reuse_*` 1개 | `saved conflict is present in the snapshot`, 독립 검토 기록 없음 |
| QA 재작업·완료 기준 카드(ADR-0060·0064) | `engine_e2e` 5개 | `no criteria_decision approval`, `awaiting_approval`에서 시간 초과 |
| 오토 모드(ADR-0066) | `auto_mode_grants_an_exact_read_only_to_the_task` | `task_resumed_auto` 이벤트 없음 |

이전 기록(Linux 클라우드 187 통과)과 달리 Windows에서만 실패하는 것인지, 코드 결함인지는 아직 가리지 않았다. ADR-0068은 명세상 엔진 구현이 아직 끝나지 않았다.
