# WLG-073 — v2·v3 수동 QA를 v4 앱에서 실행

2026-11-10, Claude. CEO 질문: 남아 있는 QA-39(v3 파일럿), QA-36/37/38(v2 화면·알림·회의), QA-51(후속 작업·차수 요약)을 v4인 지금도 해야 하는가.

## 판단 근거

- `v4/src/App.tsx`는 `v3/src/App.tsx`를 그대로 쓴다. v3는 v2의 `V2Navigation`·`V2NotificationSettings`·`MeetingPanel`과 `src/GoalChat.tsx`를 가져다 쓴다. 엔진(`src-tauri`)은 하나다.
- 따라서 기능 검증은 여전히 필요하지만, 옛 v2·v3 실행 스크립트로 따로 돌릴 필요는 없다.
- 회의 오프라인 시험 연결은 `UTOPIA_MEETING_FIXTURE=1`과 개발 빌드에서만 켜진다(`meeting.rs::fixture_enabled`). `v4/start-windows.ps1`은 개발 빌드이며 이 환경 변수를 지우지 않는다.

## 변경

- `qa/MANUAL-QA.md`: QA-36 앞에 v4 실행 안내와 항목별 우선순위 표를 추가했다. QA-36·38·39의 실행 명령을 v4로 바꾸고, QA-37의 시스템 알림 확인 대상을 v4 릴리스 빌드로 바꿨다. QA-51에 v4 실행 줄을 추가했다.
- `worklog/00_index.md`: 확인된 열린 작업 표의 세 줄을 v4 기준으로 갱신했다.

## 검증·한계

- 문서만 바꿨다. 실제 Windows에서 v4 앱을 실행하지 않았고, `UTOPIA_MEETING_FIXTURE`를 설정한 채 v4를 실행했을 때 오프라인 시험 연결이 실제로 보이는지는 확인하지 않았다.
