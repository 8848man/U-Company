# WLG-082 — 변경 0건 통합과 반복 복구 (ADR-0072)

2026-11-10, Codex. 브랜치 `feature/no-change-integration`. 빌드 용량 작업은 선행 커밋 `5197aa4`로 분리했다.

## 범위와 결정

- [ADR-0072](../../sdd/architecture/decisions/ADR-0072.md)에 엔진 확인 근거, 변경 없음 증거, 부분 통합, 반복 차단과 복구 상태 전이를 결정했다. DM-03·DM-05·GC-04·UF-06·Security와 QA-58을 연결했다.
- M1: 오류 분류·근거 저장 → M3: 같은 차례 부분 통합 → M2: 복구 상태 전이 순서. M4 계획 근거 검사는 이번 범위 밖이며 다음 라운드 후보다.
- 부재 근거는 선언 파일에서 엔진이 다시 실행하는 리터럴 검색으로 한정한다. 근거는 QA 자료이며 완료 판정이 아니다. 변경 없는 파일의 기록은 통합 증거와 분리한다.

## M1 — 오류 분류와 변경 없음 근거

- Dev가 `no_change_needed` JSON으로 존재 인용 또는 부재 리터럴 검색의 범위를 보고한다. 엔진이 현재 선언 파일을 다시 읽고 검색해 결과·모든 선언 파일 SHA-256·시각을 `task_no_change_proof`로 저장한다. 잘못된 형식·범위 밖 파일·불일치·실제 발견된 패턴은 일반 변경 0건 실패로 보낸다.
- 변경 없음 작업에는 `task_integrated`와 `task_proof`가 없다. 독립 QA는 목표의 원래 산출물별 기준을 판정하며, 합격한 원래 작업의 변경 없음 기록에 실제 `DeliverableReview` ID를 연결한다. 재사용 후보는 그 QA 기록과 현재 파일 해시가 모두 맞아야 한다. ADR-0053 재작업은 빈 근거일 때도 기존처럼 QA로 진행하고 별도 기록을 남기되 자동 재사용하지 않는다.
- 완료 결과의 변경 파일 목록에서도 별도 기록이 있는 작업을 제외한다.

## M3 — 구분된 오류와 같은 차례 부분 통합

- Git 패치·폴더 복사 통합에 `NoChanges`, `PatchConflict`, `ScopeViolation`, `ReuseMismatch`, `Other`를 도입했다. 문자열 포함 검사 없이 차단 종류를 정한다. 같은 차례의 독립 작업은 각각 통합하고 실패를 별도로 저장하며, 첫 실패로 다음 의존 차례에 넘어가지 않는다.
- 대표 차단 우선순위는 ADR-0072대로 적용한다. 반복 판정 서명은 오류 종류와 소문자 정규화·정렬한 선언 파일 집합으로 저장한다. 모의 AI의 혼합 오류 종단 시험에서 두 종류의 기록과 대표 유형을 확인했다.

## M2 — 복구 상태 전이와 화면

- 근거 없는 `no_changes` 차단 카드에서 CEO가 없어야 할 리터럴 문구를 입력하면 엔진이 선언 파일 전체에서 재검색한다. 맞으면 해당 작업을 `completed`로 옮기고 원래 승인 범위·claim 검사로 `pending` 작업을 이어 간 뒤 QA가 전체 산출물을 판정한다. 맞지 않으면 상태를 바꾸지 않는다.
- 재계획 brief에 변경 없음 사실과 새 결함 근거 요구를 넣었다. 같은 목표 계보의 서명이 두 번 기록되면 자동 새 버전을 거절하고 화면에는 충족 처리 확인·직접 지시가 남는다. CEO 문구는 저장된 작업 통합 수를 근거로 이번 차례의 원본 파일 변경 여부를 구분한다.
- 모의 AI 방식 네 개(`task-no-change-with-evidence`, `task-no-change-bad-evidence`, `task-no-change-bare`, `task-mixed-failures`)와 10줄 `workflow.js` 시나리오를 추가했다.

## 검증

- Rust 집중 시험: 유효 근거→QA→의존 업무, 근거 없는 차단→독립 통합→CEO 확인→재개, 잘못된 근거, 혼합 오류, 두 번째 서명 자동 재계획 차단 모두 통과.
- 전체 Rust 시험은 단일 스레드로 254 통과·0 실패·3 무시. 뒤이어 추가한 결과 목록 시험 1개는 별도로 통과했다. 병렬 전체 실행의 16개 종단 시험 시간 초과는 단일 스레드에서 모두 통과했다.
- `cargo clippy --locked --lib -- -D warnings` 통과(코드 경고 0; Windows 증분 캐시 하드링크 실패로 복사한다는 환경 경고 1개). 프런트 `tsc`·Vitest 161개·v4 빌드 통과. 빌드 용량 작업의 `node:test` 3개도 별도 통과했다. 빌드는 기존 500 kB 청크 크기 경고를 출력했다.

## 남은 위험과 다음 행동

- 혼합 차단에서 이미 다른 작업이 통합한 파일은 롤백하지 않으며 저장된 작업별 증거를 확인한다. M1·M3·M2의 엔진 변경은 같은 통합 경로를 교차 수정하므로 문서 결정 커밋과 검증된 구현 커밋으로 묶었다.
- 재작업 종류를 제목 접두어에서 저장 필드로 옮기는 구조 변경과 M4 계획 근거 검사는 다음 라운드 후보로 남긴다.
- 실제 Windows v4 앱 QA-58은 `대기`다.
