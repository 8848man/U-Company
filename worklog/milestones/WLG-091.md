# WLG-091 — uCompany 개발 업무의 CLI 에이전트 입력 토큰 배수 측정

2026-11-17, Claude. 브랜치 `feature/token-multiplier-measurement`, PR #41(2026-11-17 squash merge).

## 범위

- 이 측정은 uCompany가 같은 개발 업무를 Claude Code와 Codex CLI에 맡길 때의 입력 토큰을 비교한다. 업무 배정 판단용이며 모델 효율·비용 비교가 아니다(한계 참고).
- 개발 업무에서 Claude Code 입력이 Codex CLI의 몇 배인지, 2026-10-21 집중 작업 지침(WLG-003) 뒤 얼마나 달라졌는지 측정했다. 레벨 4·5 규모 재실행은 사용량이 커서 하지 않고, 작은 고정 과제와 CEO가 앱에서 실행한 할 일 앱 목표로 대신했다.
- 측정 실행기 `token-bench`(`src-tauri/src/token_bench.rs`, `src-tauri/src/bin/token-bench.rs`): 앱이 개발자에게 보내는 요청문(`engine::worker_prompt`)과 `provider::execute_with_options` 호출 경로를 그대로 쓰고, 고정 과제 `tests/token-bench/project`를 매번 새 Git 폴더에 복사해 실행한다. `focused` 인자는 제품에서 항상 켬이고, 실행기만 끄고 켠다. 숨은 합격 시험 `tests/token-bench/check.test.mjs`는 참고 구현에서 4/4, 구현 전 코드에서 0/4다.
- 집계 스크립트 `scripts/token-bench/collect.mjs`: 세션 ID로 Claude(`~/.claude/projects`, 하위 에이전트 포함)와 Codex(`~/.codex/sessions`, `.jsonl.zst` 압축 로그 포함) 로그를 찾아 응답 횟수(메시지 ID·response ID 중복 제거), 캐시, 출력, 모델, CLI 버전을 세고 조건별 중앙값과 배수를 낸다.
- 비교 자료: [토큰 배수 측정 HTML](../../analysis/token-multiplier-before-after.html). 원자료: `tests/token-bench/results/runs.collected.jsonl`(CLI 16회), `app-records.collected.jsonl`(앱 기록 6건).

모델과 버전은 각 CLI 세션 로그에서 읽었다. 추론 강도는 둘 다 medium이다(Claude Code `effortLevel`, Codex `model_reasoning_effort`; 2026-11-17 설정 기준이며 10월 실행 당시 값은 기록이 없다). 앱은 모델·추론 강도를 지정하지 않고 각 CLI 기본 설정으로 호출한다. 앱의 CTO·PM·QA는 Claude 연결이며 비교에서 뺐다.

- 11월 측정은 모두 첫 QA 또는 숨은 합격 시험을 통과했다(앱 2/2, CLI 16/16, 선언 밖 변경 0). 할 일 앱 폴더의 테스트를 다시 실행해 Dev1 11/11, Dev2 8/8 통과를 확인했다.
- 10월 배수는 응답 횟수(1.7배)와 응답당 입력(2.0~2.5배)이 함께 컸다. 11월에는 Claude 응답 횟수가 Codex 이하(0.6~0.8배)이고, 응답당 입력 비(약 1.8~2.1배, Claude 약 4만·Codex 약 2.2만)만 남았다.
- 같은 고정 과제에서 집중 지침을 끄고 켠 차이는 실행 간 편차(Claude 15.5만~29.8만, Codex 10.1만~22.8만)보다 작아 효과를 확인하지 못했다.
- 할 일 앱 목표 전체에서는 CTO·PM·QA 입력이 약 75만으로 개발 두 업무(29만)보다 컸다.

- HTML은 headless Edge 1100px·600px 캡처로 배치를 확인했다. 실제 브라우저의 호버 동작은 확인하지 않았다.

## 한계와 남은 위험

- 모델 효율 비교가 아니다. 모델에 CLI 지침·도구 정의와 실행 방식까지 더한 에이전트 전체를 비교했다. 응답당 기본 입력(Claude Code 약 4만, Codex CLI 약 2.2만)의 상당 부분은 CLI 차이로 보인다.
- 두 회사의 토크나이저가 달라 같은 글자도 토큰 수가 다르다. 배수 일부는 단위 차이일 수 있으며, 이번 측정으로 분리하지 못했다.
- 토큰은 비용·구독 한도 소모와 같지 않다. 한도 비교는 별도 측정이 필요하다. Codex 로그의 한도 사용률은 1% 단위라 작은 실행 한 번으로는 움직이지 않았고(63%), Claude Code 로그에는 이 값이 없다.
- gpt-6-sol이 Opus 5.5와 같은 급의 모델인지는 확인하지 않았다.
- 10월과 11월은 과제와 CLI 버전이 다르다. 3.3~4.2배→1.2~1.7배 감소를 집중 지침 효과로 보지 않는다.
- 고정 과제는 응답 4~10회로 끝나 탐색을 줄이는 지침이 작동할 여지가 적다. 큰 과제에서의 지침 효과는 측정되지 않았다.
- CLI 실행기 첫 라운드 Before 2회(Claude·Codex)는 결과 줄 없이 실패해 빠졌다. 원인은 확인하지 않았다(출력이 남지 않음).
