## 확인 사실과 추정의 시간순 대조

1. 이전 차수의 작업 생성·승인 요청/결정·통합 이벤트, `task_proof`와 통합 직전 SHA-256: **원장 부재로 확인 불가**. 파일별 승인 범위와 통합 시각도 알 수 없다.
2. 인계에는 직전 차수 ID `2d5cde92-efc0-4743-8ac8-8fedb7e19d4f`, QA 재작업 1회 및 `재사용 파일이 통합 이후 변경되었습니다: sdd/product.md`가 적혀 있다. 이는 원본 이벤트가 아닌 인계 진술이다.
3. 현재 격리 폴더의 `sdd/product.md` SHA-256은 `5c6f14d3ac04c02cb51bf544a3d3ac8b3252100d2b99ac68df88f26183966da8a`다. 이전 해시가 없어 실제 diff와 변경 시각을 계산할 수 없다.
4. 코드상 이전 해시와 현재 해시 불일치가 QA 직전 차단을 일으킬 수 있고, 승인된 후속 통합도 이전 해시를 갱신하지 않은 점은 **가능한 원인**이다. 실제 차단 건의 변경 주체·시점·승인 여부는 **미확인**이다. `전제 없음: 해당 실행의 SQLite 작업·승인·통합 이벤트 원장 및 통합 전후 파일 해시`.

## 이번 마일스톤

- ADR-0027의 해시·의존성·독립 QA 원칙을 유지하면서 [ADR-0068](../../sdd/architecture/decisions/ADR-0068.md)에 계획/재작업 승인 전 중복 검사, 새 승인 범위, 통합 시 파일별 전환 증거, QA 재진입을 결정했다.
- [Security](../../sdd/security.md), [DM-03](../../sdd/domain/DM-03-execution.md), [DM-05](../../sdd/domain/DM-05-recovery.md), [Validation](../../sdd/validation.md)에 차단 분류와 계획·재작업·QA 시험 기준을 연결했다. 기존 승인 확대는 별도 결정 필요로 남겼다.
- **이전 명세 차수에서는** 엔진과 테스트 코드를 변경하지 않았다. 그 당시에는 계획·재작업·QA 동작의 구현/런타임 통과를 주장하지 않았다. 아래 「이번 구현과 검증」은 그 뒤에 기록된 별도 코드 변경 단계이며, 이 문장은 현재 코드 상태를 뜻하지 않는다.

## 집중 검사 결과

**이전 명세 차수의 기록:** PowerShell 문서 검사에서 당시 선언된 8개 파일의 존재, ADR 조항, 해시, 색인 링크를 확인해 `focused-doc-check-ok`가 나왔다고 기록됐다. `git -c core.whitespace=cr-at-eol diff --check` 종료 0, 당시 `git status --short`에 8개 파일 변경·추가, 엔진 시험 미실행으로 기록됐다. 이 결과를 후속 코드 단계의 시험 결과로 취급하지 않는다.

## 이번 구현과 검증 (2026-11-01)

이 절은 위의 **이전 명세 차수 이후** 코드 변경 및 이번 재작업의 읽기 전용 확인이다. 이번 재작업에서 수정한 파일은 WLG-063과 색인뿐이다. 현재 Git 작업 폴더는 수정 전 `git status --short` 기준으로 깨끗했으므로, 과거의 「8개 파일 변경」은 현재 변경 목록이 아니다.

### 현재 코드에서 확인한 범위

- `engine.rs`에는 계획 경로 중복 표시, 승인 파일 범위 검사, 실제 통합 뒤 전환 증거 저장, 현재 해시와 이전 증거를 확인하는 QA 진입 경로가 있다. `model.rs`에는 `ReuseFileTransition`, `ReuseConflict`가 있고, `engine_e2e.rs`에는 실제 연결 목표·승인·`integrate_task` 경로의 회귀 시험이 있다. 코드 존재는 해당 시험의 실행 통과를 뜻하지 않는다.
- `App.tsx`의 `ReuseConflictPanel`은 구조화된 충돌 기록이 **전달되면** 파일, 저장된 승인 ID와 파일 범위, 이전·현재 SHA-256, 이벤트, diff 또는 누락 증거와 복구 경로를 표시한다. 현재 `Snapshot`과 `storage.rs::snapshot`에는 `reuseConflicts` 전달 필드가 없다. 따라서 실제 차단 건이 이 패널에 나타난다는 수용 기준은 **미충족/미검증**이다. 문서 수정 범위 밖의 백엔드 전달 경로가 필요하다.
  - **2026-11-10 정정 (Self grill E15):** 위 문장은 2026-11-01 당시 기록이다. 현재 코드에는 전달 경로가 있다: `storage.rs::snapshot`이 저장된 `reuse_conflict`를 읽어 `Snapshot.reuse_conflicts`로 보내고(보관 목표는 제외), `v3/src/App.tsx`가 `reuseConflicts`를 받아 `ReuseConflictPanel`에 넘긴다. 재시작 뒤 조회 시험(`snapshot_returns_saved_reuse_conflicts_after_restart_and_hides_archived_goals`)도 있다. 다만 Rust 시험 실행과 실제 차단 건의 화면 표시는 여전히 **미검증**이다.

## 재작업 2: 실제 차단 원장 재확인과 후속 코드 검증 (2026-11-01, Developer A)

이 절은 위의 시간순 대조를 이어받는다. 이번 작업의 쓰기 범위는 `worklog/milestones/WLG-063.md`, `worklog/00_index.md`뿐이다. 엔진·시험·화면 파일은 읽고 검증했으며 이번 작업에서 수정하지 않았다. 새 파일은 쓰지 않았다.

## 재작업 3: 실제 차단 건의 증거와 원인 대조 (2026-11-01, Developer A)

이번 배정의 변경 파일은 **`worklog/milestones/WLG-063.md` 하나**다. 위 계획의 다른 파일 및 `worklog/00_index.md`는 이번 쓰기 범위에 포함되지 않는다. 새 파일 쓰기 승인도 없으므로 새 파일을 만들지 않았다. 이번 수용 기준은 (1) 현재 해시와 실제 사건의 이전 해시·작업·승인·통합·QA 기록 확보 여부를 항목별로 밝히기, (2) 확인 사실과 코드상 가설 분리하기, (3) 최초 계획·QA 재작업·외부 변경 시험 명령, 종료 코드, 관찰을 남기기다.

### 확인 사실과 가능한 원인

**확인 사실:** 현재 파일 해시는 위 값이다. 제공된 인계에는 `재사용 파일이 통합 이후 변경되었습니다: sdd/product.md`가 적혀 있다. `engine.rs::verify_task_reuse`는 저장된 `task_proof`의 파일 SHA-256과 현재 프로젝트 파일 SHA-256이 다를 때 정확히 이 문구를 반환한다. 현재 코드에는 후속 작업·승인·`task_integrated`·전환 해시를 대조하는 `verify_reused_file_depth` 경로도 있다. ADR-0027은 기존 해시와 의존성 및 독립 QA를 요구하고, ADR-0068과 Security는 승인된 후속 통합의 새 증거만 전환하며 범위 밖 변경은 차단하도록 정한다.

**코드상 가능한 원인:** 이전 해시 검사만 적용된 경로에서 승인된 후속 수정으로 현재 바이트가 바뀌었거나, 전환 증거의 작업·승인·통합 연결이 누락됐을 수 있다. 별도의 외부 변경 또는 증거 해시 불일치도 차단을 만들 수 있다. 어느 경우인지 원장 없이 선택할 수 없다. **미확인:** `sdd/product.md`의 실제 변경 주체·시점·승인 여부, 이전 통합 SHA-256과 차단 당시 SHA-256, 실행된 엔진 분기. 현재 Git 스냅샷이나 커밋 시각을 앱의 승인·통합 증거로 사용하지 않는다.
