# WLG-072 — 10-27 이후 미커밋 작업 정리와 main 병합

2026-11-10, Claude. CEO 요청: 10-27 이후 미커밋 작업(ADR-0062~0067, v4, `permission_mode`, `technology_presets`, WLG-059~070)을 한 브랜치로 묶어 PR로 올린다.

## 범위

- `feature/backfill-2026-11` 브랜치에 분석 자료, v4 프리셋(ADR-0062), 권한·QA 묶음(ADR-0063~0067)을 세 커밋으로 나눠 커밋했다.
- `origin/main`(PR #22)에 다른 ADR-0063(`명령 전부 허용`)과 WLG-064(미통합 브랜치 통합)가 먼저 들어가 번호가 겹쳤다. 로컬 ADR-0063(재수정 파일 소유권)을 [ADR-0068](../../sdd/architecture/decisions/ADR-0068.md)로, 로컬 WLG-064(Self grill)를 [WLG-071](WLG-071.md)로 바꿨다.
- CEO 결정(2026-11-10): 병합 시 [ADR-0066](../../sdd/architecture/decisions/ADR-0066.md)의 `수동`/`오토`/`풀 오토`를 기준으로 하고, main의 `명령 전부 허용`(Claude `bypassPermissions`, push 차단 환경, 붉은 띠, `get/set_command_mode`, `CommandModeControl`·`commandMode.*`)을 제거했다. ADR-0066은 풀 오토에서도 웹 접속·설치·push·배포를 별도 승인으로 남기므로, 그보다 넓은 우회 모드와 함께 둘 수 없다.
- main의 [ADR-0063](../../sdd/architecture/decisions/ADR-0063.md) 결정 1~3·6은 유지했다: 읽기 전용 명령은 규칙이 되지 않음, 작업 폴더에서 실행 안내, 안전 권한의 프로젝트 공유, `commands_run` 기록. 결정 4·5·7 철회는 ADR-0063 본문과 ADR 색인에 적었다.
- `permissions::rules_for_denials`: 여러 줄·heredoc·인라인 스크립트·`$`/중괄호 명령은 규칙을 만들지 않고(ADR-0067), 한 줄 반복·조건문은 제어어를 떼고 읽기 전용이 아닌 명령만 규칙으로 만든다(ADR-0063 결정 1).
- Security, UF-05, AI-03, GC-03, Validation의 `명령 전부 허용` 문장을 바꿨다.

## 검증·한계

- `tsc --noEmit`(루트·v3·v4) 통과, vitest 32파일 160개 통과.
- `cargo test --no-run` 컴파일 통과(기존 `verify_task_reuse` 미사용 경고 1건). Windows Rust 시험 실행 파일은 기존과 같이 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`로 시작되지 않아 단위·종단 시험은 실행되지 않았다. clippy는 이 도구 모음에 설치되어 있지 않다.
- 실제 Windows 앱·Claude 세션 QA는 하지 않았다.

## 남은 일

- [ ] Rust 시험 실행 환경(`0xc0000139`)을 고친 뒤 `permissions`·`permissions_flow`·`engine_e2e` 시험을 실제로 돌린다. 특히 main의 한 줄 반복문 시험과 ADR-0067의 스크립트 본문 시험이 함께 통과하는지 확인한다.
- [ ] 이미 `command_mode` 저장 레코드가 켜진 데이터는 더 이상 읽히지 않는다. 남은 레코드가 동작에 영향이 없는지 실제 데이터에서 확인한다.
