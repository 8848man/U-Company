# WLG-066 — QA의 잘못된 전제 판정에서 같은 목표 파일 수정

2026-11-07, Codex. 사용자가 실제 보고서 QA에서 `source/`가 없다는 이유로 `팀이 채울 수 없음` 카드가 떴지만, 기준이 요구한 대체 문장만 추가하면 충족할 수 있다고 지적했다. 기존 카드의 `그대로`는 같은 파일을 재검사할 뿐이라 다시 실패한다.

## 범위

- [ADR-0064](../../sdd/architecture/decisions/ADR-0064.md), Security, UF-05, Validation, QA-54에 같은 목표 안에서 기준을 유지하고 파일을 고치는 경로를 기록했다.
- `criteria.rs`는 QA의 `precondition`만으로 CEO 카드를 열지 않는다. 첫 실패는 PM→Dev의 일반 재작업으로 보내고, PM의 기준 수정 제안이나 재작업 후 같은 실패에서만 카드를 연다. 카드 뒤 CEO의 `repair` 결정은 원래 기준을 보존하고 QA 한도를 검사한다. 엔진은 기존 승인 파일 안의 재작업을 계획하고, 새 파일은 기존 범위 승인 절차에 맡긴다. QA 요청문은 기준 자체의 대체 조건이 가능한 경우를 전제 불가로 표시하지 말라고 명시한다.
- v3 완료 기준 카드에 `기준 유지하고 파일 고치기`를 추가했다. 실행 중 기존 파일을 직접 수정하거나 QA를 통과 처리하지 않는다.

## 검증과 남은 위험

- 기존 프로젝트 작업 폴더에 다른 미커밋 변경이 있어 이번 수정은 관련 위치에만 적용했다.
- `cargo check --locked --lib` 통과(기존 `verify_task_reuse` 미사용 경고 1건). `npm run build:v3` 통과. `npx vitest run src/criteriaDecision.test.ts` 3건 통과. `cargo test --locked --lib ceo_can_keep_a_falsely_blocked_criterion_and_request_a_file_repair -- --nocapture`는 시험 실행 파일 컴파일을 마쳤지만 Windows 시작에서 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`로 실패해 시험 본문은 실행되지 않았다. `git -c core.whitespace=cr-at-eol diff --check`는 이번 변경 경로에서 통과했다.
- 사용자 지적에 따라 CEO 카드로 넘기는 시점을 다시 수정했다. QA의 `precondition`만 있는 첫 실패는 자동 재작업, PM의 `criteriaChanges` 제안 또는 재작업 후 같은 기준 실패만 CEO 카드로 가게 했다. 관련 단위·종단 시험의 기대값과 Validation·QA-54를 갱신했다. 이 후속 변경에서 `cargo check --locked --tests` 통과(같은 기존 경고), 변경 파일 `git -c core.whitespace=cr-at-eol diff --check` 통과. Windows 시험 실행 실패가 그대로여서 새 종단 시험 본문은 실행되지 않았다.
- 종단 시험의 실제 PASS는 없으며 기존 Windows 시험 실행 환경 문제와 분리해 해결해야 한다. 이 차수의 경로는 컴파일·프런트 빌드까지 확인됐다.
- 실제 Claude와 Windows 앱에서 원본 사례의 PM 재작업 품질, 명령 승인, QA 재검사는 아직 확인되지 않았다. 기존 실행 중인 백엔드에는 새 경로가 적용되지 않으므로 재시작이 필요하다.

## 실제 ttj.kr 목표 원장 대조 (2026-11-07)

- 로컬 앱 SQLite의 목표 `6f49cedc-4add-4c6c-a4ce-abac3c498088`를 읽기 전용으로 확인했다. 최초 PM 업무 세 개의 선언 출력은 `report/ttj-animation-report.md`, `report/ttj-tech-stack.md`, `skill/landing-motion/` 파일뿐이다. `source/` 파일 생성·웹페이지 저장 업무는 없다.
- 기술 분석 업무의 PM 지시문은 웹페이지를 브라우저에서 “웹페이지, 전체”로 저장해 `source/`에 넣는 일을 **CEO 선행 조치**로 명시한다. `source/`가 없으면 보고서에 차단과 추정을 적으라고 했고, 후속 보고서·Skill 작업도 이 부재를 전제로 진행했다. 실제 프로젝트 폴더에도 `source/`가 없다. 원장은 목표가 `completed`로 끝났음을 보여 준다.
- 따라서 이 차수의 QA 자동 재작업 수정은 빠진 대체 문구와 잘못된 `precondition` 분류만 다룬다. **필수 원본 확보 전에 계획을 승인·실행한 전제 검증 실패와 원본 없는 추정 보고서를 완료로 표시한 문제는 미해결**이다. 다음 개선은 PM 계획 전 필요한 입력·외부 접근·CEO 조치를 판정하고, 필수 원본이 없으면 그 결과를 실제 분석 완료로 간주하지 않는 계약을 소유 SDD에서 정해야 한다. ttj.kr의 당시 제공자 네트워크 요청 실패 여부는 호출 원문과 권한 원장으로 별도 확인이 필요하다.
- 후속 읽기 전용 대조: `engine.rs`의 `planner_facts`는 팀원·QA에 네트워크 접근이 없다고 PM에게 알린다. 실제 목표의 명령 권한 요청 두 건은 로컬 `grep`·`echo`·`ls` 등의 명령만 담고 `WebFetch`, `curl`, `wget` 또는 ttj.kr 접근 요청은 없다. 최초 보고서 작성자 Claude CLI 세션 JSONL의 도구 사용 29건에도 `WebFetch`·`WebSearch` 또는 URL 접근 명령이 없다. 따라서 **그 실행은 사이트 열기를 시도하지 않았다**는 것이 확인되며, uCompany/Claude 실행 환경에서 승인 후 ttj.kr에 실제 접속 가능한지는 별도 시험 전 미확인이다.
