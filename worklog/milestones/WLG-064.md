# WLG-064 — 미통합 작업 브랜치 정리 (2026-11-04, Codex)

## 범위

- `origin/main`에서 통합 브랜치를 만들고 `feature/command-permission-modes`를 병합했다. 이 브랜치는 목표 후속 작업, 명령 승인, 목표 재개, QA 공회전 방지, `지금 할 일`, 명령 권한 모드를 포함한다.
- `codex/select-cli-models`를 병합했다. `WORKLOG.md`의 기록 형식 충돌은 이동 안내 파일을 유지하고 이 파일에 모델 선택 검증 기록을 옮겨 해결했다.
- `feature/completion-usability-rounds`는 Git 계보상 미병합이지만 현재 `main`과 비교한 기능 차이가 없다. 남은 차이는 `src/officeWindowState.test.ts`의 공백 두 줄뿐이다. 이 브랜치를 다시 병합하지 않는다.
- 원래 체크아웃의 미커밋 v4·재작업 파일은 이번 통합 브랜치에 포함하지 않았다. 해당 작업은 별도 검증과 PR이 필요하다.

## 검증

- 병합 중 코드 충돌은 없었고, 기록 파일 `WORKLOG.md` 한 곳만 수동으로 해결했다.
- `npm test`: 31개 파일, 140개 시험 통과.
- `npm run build`, `npm run build:v2`, `npm run build:v3`: 모두 통과. v3 번들 크기 경고는 남는다.
- `cargo check --locked --all-targets`: 통과.
- `cargo test --locked`: 테스트 대상 컴파일은 통과했지만 Windows 시험 실행 파일이 `0xc0000139` (`STATUS_ENTRYPOINT_NOT_FOUND`)로 시작되지 않아 시험 결과를 확인하지 못했다. 동일 환경 문제는 이전 작업 기록에도 있다.
- `git -c core.whitespace=cr-at-eol diff --check origin/main`: 병합으로 들어온 공백 두 줄, 오래된 기록의 공백 한 줄, 인덱스의 끝 빈 줄을 정리한 뒤 통과.
- 모델 선택 원래 작업 기록: 당시 설치된 Codex CLI의 읽기 전용 모델 목록 조회, 프런트 빌드 및 Rust 컴파일은 통과했다. 실제 앱에서 모델 저장·재시작·실제 호출은 아직 확인하지 않았다.

## 남은 위험과 다음 행동

- 실제 Windows 앱에서 통합된 목표·승인·복구 흐름과 AI 모델 선택을 한 시나리오로 다시 확인해야 한다.
- Rust 시험 실행 환경 문제를 별도로 조사하고 PR에 검증 범위를 명시한다.
