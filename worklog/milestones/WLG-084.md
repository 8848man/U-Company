## 빌드 용량 게이트 ([WLG-081](WLG-081.md) 다음 행동)

- `target/debug/deps/ai_organization_os.exe`의 배타적 열기가 성공해 잠금이 풀린 것을 확인했다. 시작 시 기본 경로 `debug`는 4.05 GiB였다(WLG-081 이후 누군가 이미 빌드를 끝낸 상태).
- 기본 경로에서 [Build storage](../../sdd/build-storage.md) 대표 순서를 실행했다.
  - `cargo build --locked` 종료 0(8초, 무변경), 4.05 GiB → 4.05 GiB.
  - `cargo test --locked -- --test-threads=1` 255 통과·0 실패·3 무시(380초) 후 4.29 GiB.
  - `cargo build --locked` 종료 0(16초) 후 4.28 GiB, 같은 명령 재실행(1.2초) 후 4.28 GiB. 무변경 반복 증가 0.
- 게이트 (a) 빌드·시험 통과, (b) 5 GiB 이하, (c) 반복 증가 0.25 GiB 이하를 충족한다. (d) 줄 번호 표시는 같은 프로필로 WLG-081에서 확인한 근거를 따르며 이번에 다시 보지 않았다. **이번 조치(개발 프로필 디버그 정보 축소)로 충분하다고 판정**하고 두 번째 대안은 적용하지 않는다.

- `npm run tauri:v4`: pre 단계 보고 4.05 GiB·예산 안, Vite 준비, `cargo run` 0.93초, `ai-organization-os.exe` 창 "AI Organization OS"가 응답 상태로 열렸다. 창을 닫은 뒤 post 단계 보고 4.05 GiB·예산 안, 종료 0.
- 화면 조작이나 QA 시나리오는 수행하지 않았다(시작 확인만).

## 설치 파일 빌드

- `scripts/build-installer-windows.ps1` 종료 0, 약 6분(release 컴파일 4분 3초). 산출물 `src-tauri/target/release/bundle/nsis/AI Organization OS_0.1.0_x64-setup.exe` 6.7 MB. Vite의 기존 500 kB 청크 경고만 있었다.
- 설치·실행은 하지 않았다.
- 주의: Windows PowerShell 5.1에서 이 스크립트를 `*>` 또는 `2>&1`로 리다이렉트해 실행하면 `$ErrorActionPreference = 'Stop'` 때문에 tauri가 stderr로 내는 `Info` 줄이 `NativeCommandError`로 바뀌어 즉시 실패한다. 리다이렉트 없이 실행하거나 `powershell -File`로 별도 프로세스에서 실행하면 정상이다. 스크립트는 고치지 않았다.
