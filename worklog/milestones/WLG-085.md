# WLG-085 — CEO가 진행 중 목표와 회의를 멈추기

2026-11-14, Codex. 브랜치 `feature/ceo-stop-control`. 볼트의 CEO 중단 결정 후속 과제.

## 범위와 결정

- ADR-0073에 CEO 중단 후 일시정지, 완료분 보존, 재개·취소, 호출 취소와 결과 폐기를 기록했다. DM-04, ME-01, AI-03, Security, UF-03·06·09, Validation에 연결했다.
- 실행 목표의 호출 신호는 목표 ID별로 묶어 병렬 Dev 호출에도 전달한다. 중단 뒤 도착한 답은 통합하지 않는다. 멈춘 목표의 미완료 격리 작업본은 재개 또는 취소 시 앱 작업 경계 안에서 정리한다.
- 회의 중단은 진행 중 패킷의 결과를 취소로 기록하고 발언으로 채택하지 않는다. 전송 사실과 사용량은 남는다. `회의 취소`는 결론 없이 종료한다.

## 검증

- `cargo check --locked --lib`: 통과. 새 작업 트리의 첫 의존성 빌드에 6분 13초 소요. 증분 재검사도 통과.
- Rust 집중 시험: 진행 중 회의 중단이 발언을 폐기하고 취소로 끝나는 시험 1개, 승인 없는 목표의 일시정지·취소가 원본 파일을 보존하는 시험 1개 통과.
- `npm test`: 32개 파일, 161개 시험 통과. `npm run build:v4`: TypeScript 검사와 Vite 빌드 통과. 샌드박스가 Vite의 상위 경로 읽기를 거부해 같은 명령을 승인을 받아 재실행했다.
- 전체 Rust 단일 스레드 시험: 258 통과·0 실패·3 무시(실제 제공자/화면 미포함). 이후 격리 폴더 정리 시험을 강화하고 집중 재검증한다.
- 변경된 프런트 상태 시험 18개 재실행 통과, v4 TypeScript 재검사 통과. 실제 Windows 앱 화면과 제공자 호출은 미검증.
- `cargo clippy --locked --lib -- -D warnings`: 통과(코드 경고 0).

## 남은 위험과 다음 행동

- 진행 중 실제 Windows AI 호출의 취소 효과와 격리 작업본 정리는 앱 QA에서 확인한다. 이미 외부에 보낸 내용은 회수할 수 없다.
- 같은 파일을 바꾸는 M4 과제는 다른 브랜치에서 작업한다. 병합 때 소유 명세와 worklog 인덱스의 두 변경을 함께 확인한다.
