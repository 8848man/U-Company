# WLG-067 — Dev 권한 요청의 PM 검토 경로

2026-11-07, Codex. 사용자는 Dev가 막힌 권한을 PM에게 요청하고 PM이 판단한 뒤 Dev의 작업 권한을 갱신하는 흐름을 요청했다. 기존 구현은 Dev 거절에서 바로 CEO 카드로 갔다. 보안 경계상 PM은 기존 승인 안의 작업 방식만 지시할 수 있고 새 권한은 CEO가 승인하도록 정했다.

## 범위

- [ADR-0065](../../sdd/architecture/decisions/ADR-0065.md)와 Security, DM-03, UF-05, AI-03, Validation, QA-56을 갱신했다.
- `permissions_flow.rs`: Dev 거절 묶음을 목표의 계획 PM에게 읽기 전용으로 한 번 보내 `request_approval`, `retry_with_existing_grants`, `continue_without` 중 하나를 받는다. PM 응답은 저장된 명령 grant를 변경하지 않는다. PM 실패나 12,000자 초과 입력은 이유를 기록하고 기존 CEO 카드로 간다. 기존 권한 재시도는 같은 Dev 세션과 기존 상한을 사용한다. QA 거절은 그대로 독립 승인 경로를 따른다.
- 웹 원본 수집은 이번 변경 범위에 넣지 않았다. 기존 계획 전제와 Dev 지시문은 네트워크 작업을 배제한다. 사이트 접속을 실제로 허용하려면 제공자 권한과 실행 환경까지 묶인 별도 설계·검증이 필요하다.
- 모의 AI에 PM 권한 검토 응답과 두 분기를 추가하고, 기존 승인 카드 시험·PM 생략 분기 시험·JSON 제한 시험을 보강했다.

## 검증과 남은 위험

- `cargo check --locked --tests` 통과. `node --check scripts/mock-ai/mock-adapter.mjs`와 모의 어댑터의 PM 검토 단계·재시도 응답 확인 통과. `git -c core.whitespace=cr-at-eol diff --check` 통과.
- `cargo test --locked --lib pm_permission_review_accepts_only_bounded_decisions`는 시험 파일 컴파일 뒤 Windows 실행 시작에서 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`로 실패하여 시험 본문은 실행되지 않았다. 모의 AI 종단 시험과 실제 Claude/Windows UI 검증은 미실행이다.
- 기존 권한으로 재시도할 때 PM의 대안이 실제로 효과적인지, 계획한 웹 접속이 실제 제공자 환경에서 가능한지 확인되지 않았다. URL/명령의 세부 범위를 강제하는 수집 기능도 별도 작업이다.
