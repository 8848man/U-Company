# WLG-077 — Windows에서 남은 엔진 시험 19개를 고침

2026-11-10, Claude. [WLG-075](WLG-075.md)에서 시험 실행 파일이 시작된 뒤 남은 실패 19개를 처리했다. 결과: `cargo test` **238 통과, 0 실패, 3 무시**.

## 원인과 변경

| 묶음 | 원인 | 변경 | 종류 |
| --- | --- | --- | --- |
| `delegation::tests` 3 | 열린 SQLite 저장소가 있는 임시 폴더를 지우다 Windows 파일 잠금(`os error 32`) | 시험 정리를 다른 시험처럼 실패해도 넘어가게 함 | 시험 환경 |
| `engine::tests` 줄바꿈 1 | Git for Windows 기본값 `core.autocrlf=true`로 시험 저장소의 파일이 CRLF로 바뀜 | 시험용 저장소에 `core.autocrlf=false` | 시험 환경 |
| `engine::tests` 2 | 엔진 오류 문구(`승인 범위 밖 변경`)와 통합 이벤트 ID 요구가 바뀌었는데 시험이 옛 기대를 유지 | 시험을 현재 엔진에 맞춤 | 오래된 시험 |
| 오토 모드 1 | ADR-0063은 읽기 전용 줄을 "덮였다"고 보지 않아, ADR-0066 오토가 정확히 허용한 읽기 명령의 거절이 남아 업무가 재개되지 않음(PR #23 병합 상호작용) | 자동 허용 경로는 자기가 허용한 정확한 규칙으로 해당 거절을 정리 | **제품 결함** |
| QA 재작업·완료 기준 5 | ADR-0068 구현이 모든 QA 재작업에 새 파일 승인 카드를 요구해, 승인된 파일만 고치는 재작업도 CEO 카드에서 멈춤 | 새 파일이 없고 재사용 파일을 건드리지 않는 재작업은 계획 승인에 묶어 바로 진행 | **제품 결함** |
| 연결 목표 재사용 5 | 계획 중 확인한 충돌이 이전 목표에 저장되어 새 목표 화면에 보이지 않음 | 충돌은 CEO가 보는 목표에 저장 | **제품 결함** |
| 연결 목표 재사용 2 | Git이 추적하지 않는 파일은 `git diff`가 비어 충돌에 바뀐 내용이 없음 | 현재 내용을 대신 보여 줌 | **제품 결함** |
| 연결 목표 재사용 1 | 격리 작업 중 바깥 수정은 패치 전에 `출처 불명 변경`으로 막히는데(ADR-0068 §5) 시험은 패치 충돌을 기대 | 시험 기대를 명세에 맞춤 | 시험 기대 정정 |
| 연결 목표 재사용 2 | 시험이 QA 판정을 대문자(`FAIL`/`PASS`)로 비교, 엔진은 소문자 | 시험을 소문자로 | 오래된 시험 |

`engine_e2e` 시험 대기가 시간 초과되면 대기 중인 승인과 최근 이벤트를, 재사용 충돌을 찾지 못하면 저장된 충돌 목록과 목표 보고를 함께 보여 주게 했다.

## 검증·한계

- `cargo test` 전체: 238 통과, 0 실패, 3 무시(Windows).
- 실제 Claude·데스크톱 앱에서 오토 모드 재개, 재작업 진행, 재사용 충돌 화면은 확인하지 않았다(QA-56·57, ADR-0068 런타임 QA).
- 제품 결함 4건은 시험이 그동안 Windows에서 돌지 않아 드러나지 않았다. 실제 사용 중 QA 재작업이 카드에서 멈춘 사례가 있었다면 이 결함 때문일 수 있다.
