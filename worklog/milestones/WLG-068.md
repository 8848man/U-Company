# WLG-068 — 채팅·설정의 AI 실행 권한 모드

2026-11-07, Codex. 사용자 요청: `수동`, `오토`, `풀 오토`를 목표 채팅과 설정에서 선택한다. 풀 오토는 삭제·이동까지 자동 처리하고 웹 접속·설치·push·배포는 별도 승인한다는 사용자의 범위 결정을 반영했다.

## 범위

- [ADR-0066](../../sdd/architecture/decisions/ADR-0066.md)와 Security, DM-03, UF-05, AI-03, Validation, QA-57을 갱신했다.
- `permission_mode.rs`: 프로젝트 기본·목표 대화 재정의를 저장하고 효과 모드를 계산한다. 단순 로컬 조회 명령은 정확한 호출만 자동 허용한다. 풀 오토의 삭제·이동은 Dev 격리 작업과 선언 파일의 단순 상대 경로로 제한한다. 외부 작업, 셸 치환, 리다이렉션, 시험·빌드, 상위 경로, 심볼릭 링크는 자동 대상에서 제외했다.
- `permissions_flow.rs`: 자동 grant는 업무별로 저장하고 모드를 내리면 다음 호출부터 제외한다. 자동 재시도 후 같은 명령이 거절되면 PM/CEO 경로로 보낸다. QA는 폐기 가능한 검토 복사본에서 로컬 조회만 자동 재개한다. 수동 CEO 승인 grant는 기존 대화 범위에 유지된다.
- v3 설정에 `AI 실행 권한` 탭을 추가하고 목표 채팅에는 항상 현재 모드와 선택 버튼을 표시한다. 프로젝트 기본과 대화 재정의를 같은 컴포넌트로 보여 준다.

## 검증·한계

- `cargo check --locked --tests`, `npm run build:v3`, `npx vitest run src/PermissionModeControl.test.ts`, `node --check scripts/mock-ai/mock-adapter.mjs`, `git -c core.whitespace=cr-at-eol diff --check` 통과.
- 기존 Windows Rust 시험 실행 파일은 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`로 시작되지 않으므로 새 단위·모의 종단 시험 본문은 실행되지 않았다. 실제 Claude/Windows UI에서 정확한 `--allowedTools` 일치와 모드 변경은 미검증이다.
- [Claude Code 설정 문서](https://code.claude.com/docs/en/settings)는 `Bash(npm run lint)` 같은 정확한 명령 규칙 예시와 여러 설정 범위의 allow 규칙 병합을 설명한다. 이 문서는 CLI 구문 근거이며 이번 앱의 실제 Windows 실행 통과 근거는 아니다.
- 외부 명령·스크립트의 실제 부작용을 일반 셸 텍스트만으로 완전 판별할 수 없어 자동 범위를 단순 조회와 선언 파일 삭제·이동으로 좁혔다. 이미 실행 중인 제공자 호출이나 제공자 전역 권한은 모드로 소급 통제할 수 없다. 명령 자동 모드는 운영체제 샌드박스가 아니다.
