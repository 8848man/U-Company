# WLG-090 — PM 프리랜서 페르소나와 기본 팀원 페르소나 전문화 (ADR-0076)

2026-11-16, Claude. 브랜치 `feature/freelancer-personas`, PR #40(2026-11-17 squash merge). CEO 요청: "프로젝트 수행 중 더 필요한 인원이 있다고 판단되면 PM이 프리랜서 페르소나를 만들어 업무 흐름으로 가져가게", "기존 캐릭터 페르소나를 더 특색 있고 전문적으로".

## 범위와 결정

- [ADR-0076](../../sdd/architecture/decisions/ADR-0076.md)을 추가했다. ADR-0041의 스쿼드·외부 인력 계약 위에서 PM 계획 JSON의 `freelancers`(목표당 최대 2명)를 엔진이 검사하고 기존 연결에 묶는다. 대기 상태의 목표 전용 외부 인력으로 만들고 승인 카드에 `(프리랜서)`, 직함, 제안 이유를 보인다. 승인하면 계약되고, 교체로 빠지거나 거부·`개선`·취소되면 기록만 남기고 돌려보낸다. 목표가 끝나면 기존 규칙대로 계약이 끝난다.
- 자리 규칙: 작성자 프리랜서는 PM이 지정한 업무만 맡고, 다른 업무가 남으면 정규 작성자 자리를 하나 남긴다. 검토자 프리랜서는 정규 QA로 채우지 못한 자리만 채운다. 잘못된 제안은 계획을 막지 않고 카드에 무시 이유로 표시한다.
- 기본 페르소나: CTO 서진(수석 아키텍트), PM 하윤(딜리버리 매니저), 개발자 도현(시니어 엔지니어), 개발자 이안(프로덕트 엔지니어, 새 프리셋 `developer-craft`), QA 지우(독립 검증 리드), 큐레이터 소라(자료 사서), 전문가(시니어 컨설턴트). 각 지시문은 엔진 계약(파일 수정 금지, JSON 형식, PASS/FAIL 첫 줄)을 유지한다. 기존 팀은 이름·지시문이 이전 기본값과 같을 때만 한 번 갱신한다.
- 명세: DM-01, Security, Validation, ADR 색인, 구현 지도.

## 검증

- Rust 전체 `cargo test --locked`: 266 통과·0 실패·3 무시. 새 시험: 프리랜서 검사·자리·연결·이미지 조건(`planner_freelancers_are_screened_bound_and_seated_within_places`), 교체·거부 해제와 다른 목표 차단(`unused_freelancers_are_released_and_others_goals_cannot_take_them`), 페르소나 계약 문구(`personas_keep_each_role_contract`), 기존 값 보존 갱신(`stock_personas_upgrade_once_and_keep_ceo_edits`), 모의 AI 전체 목표(`engine_e2e::a_planner_freelancer_is_approved_on_the_card_does_its_task_and_leaves`).
- `cargo clippy --locked --all-targets -- -D warnings` 통과. Vitest 32 파일 162 통과, `tsc --noEmit` 통과.
- 진행 중 고친 것: 새 시험 하나가 `store.transact` 안에서 `store.get`을 불러 잠금을 기다리며 멈췄다(시험 코드 문제). 새 모의 방식 `plan-freelancer`를 `mock_ai::MODES`에 등록했다.
- Windows 앱 화면과 실제 제공자 동작은 확인하지 않았다.

## 남은 위험과 다음 행동

- 실제 Claude/Codex 제공자가 `freelancers`를 적절히 쓰는지(남발·과소 제안)는 Windows 앱 QA-40 확장으로 확인해야 한다.
- 프리랜서는 PM과 같은 연결을 쓰므로 모델 능력 자체는 같다. 달라지는 것은 역할 지시와 업무 배정이다.
- 기존 동작: 목표 취소(ADR-0073) 때 이미 `contracted`인 외부 인력은 자동 해제되지 않는다(CEO가 수동 종료). 이번 변경 범위 밖이다.
