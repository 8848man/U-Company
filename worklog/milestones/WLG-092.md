# WLG-092 — 병렬 종단 시험의 승인 대기 안정화 (ISSUE-023)

2026-11-18~20, Codex. 볼트의 `#codex` 과제에서 선택됐다. 11-20에는 ISSUE-055·056의 후속 진단과 수정도 이 시험 안정화 마일스톤에 합쳤다.

## 범위와 근거

- WLG-088에서 전체 Rust 시험 중 `engine_e2e` 승인 대기가 두 번 60초에 걸렸고 재실행에서는 47개가 모두 통과했다.
- `engine_e2e::wait_operation`의 고정 60초는 테스트 전용이다. 이 시험들은 각자 실제 엔진과 모의 AI, Node, Git 프로세스를 사용해 기본 병렬 시험 실행에서 호스트 자원을 경쟁한다.
- 승인 생성·검사나 제품의 시간 제한은 바꾸지 않는다.

## 변경

- 테스트 전용 승인 대기를 180초로 늘렸다. 시간 초과 시 목표 상태, 차단 종류, 보고서와 최근 이벤트를 출력해 다음 실패의 원인을 구분한다.
- 통합된 샘플 앱의 `node --test` 실패 때 표준 출력과 오류 출력을 남긴다. 시험용 Git 프로젝트에 CommonJS 형식을 명시해 상위 저장소의 `package.json` 영향을 막는다.
- 기본 병렬 부하에서 모의 Node 어댑터 초기화가 제품용 10초 제한에 걸릴 수 있어, 시험 빌드에만 30초를 허용한다. 제품 실행 제한은 10초다.
- Validation에 기본 병렬 시험으로 확인할 기준을 기록했다.

## 검증

- 기본 병렬 `cargo test --locked --lib engine_e2e`를 현재 Codex 샌드박스 기본 임시 경로에서 실행하면, 긴 경로의 `git worktree add`가 `fatal: '$GIT_DIR' too big`로 실패했다. 승인 대기 전 단계의 환경 오류다.
- `TEMP`와 `TMP`를 `D:\projects\utopia_company\src-tauri\target`으로 지정해 같은 기본 병렬 명령을 재실행했다. 결과는 47 통과, 1 실패, 1 무시(121.57초). 승인 대기 시간 초과는 없었다. 실패한 `a_sample_app_goal_runs_from_analysis_to_a_qa_passed_report`는 목표 완료·파일 통합 뒤의 `node --test` 확인에서 발생했다. 실패 세부 원인은 이 실행에서 출력되지 않았다.
- 해당 Node 실패의 진단 출력을 추가해 재빌드하려 했으나 Windows 링커가 기존 시험 실행 파일을 열지 못해(`LNK1104`) 검증이 막혔다. 미검증 진단 변경은 되돌렸다.
- 11-20에 링커 잠금이 없는 상태에서 진단 출력을 재빌드했다. 단독 샘플 앱 시험은 상위 `package.json`의 `"type": "module"` 때문에 생성된 CommonJS `require`가 실패함을 드러냈다. 시험용 프로젝트에 `"type": "commonjs"`를 명시한 뒤 단독 재실행은 1 통과였다.
- 첫 기본 병렬 재실행은 46 통과·2 실패·1 무시였다. 두 실패 모두 모의 어댑터 초기화 10초 시간 초과였다. 시험 빌드의 초기화 대기만 30초로 늘린 뒤 같은 명령으로 48 통과·0 실패·1 무시(156.66초)를 확인했다.

## 남은 위험과 다음 행동

- 더 느린 호스트에서의 시간 경합 가능성은 남는다. 다시 시간 초과하면 목표·이벤트와 어댑터 초기화 오류를 구분해 진단한다.
- Windows v4 실앱 QA는 이 Rust 종단 시험으로 대신할 수 없다.
