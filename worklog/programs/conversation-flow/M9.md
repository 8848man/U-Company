# M9 — 요구사항 자료는 PM이 읽고, 자료 정리 담당은 기본 꺼짐 (완료, 오프라인·모의 렌더링 검증)


- [x] 결정(2026-10-14 CEO): Cowork·Codex 방식(자료는 파일로 두고 필요한 에이전트가 직접 열어 읽음, 미리 정리하는 단계 없음)을 따르되 우리만의 안전장치로 요구사항 빠짐 검사를 더한다. [ADR-0049](../../../sdd/architecture/decisions/ADR-0049.md) 개정 절, DM-06, QA-47.
- [x] 자료 역할: 글 자료에 `요구사항`·`참고`(칩에서 전환). 이름이나 첫 제목에 요구사항·요건·명세·기획서·spec·PRD·requirement가 있으면 요구사항으로 제안.
- [x] PM: 요구사항 자료의 요구사항 절을 직접 열어 읽고 계획한다(요청문에서 "열 필요 없다" 삭제). 엔진은 요구사항 절이 모두 어떤 업무의 근거 자료이거나 `requirementExclusions`에 이유와 함께 있는지 검사하고, 빠지면 형식 오류로 PM에게 한 번 되돌린다(ADR-0048). 승인 범위에 반영 수·제외 이유·배경 절을 적고, 계획 카드에 `요구사항 N절 중 M절을 업무에 반영`.
- [x] 자료 정리 담당: 기본 꺼짐(`자료 정리 담당 사용`). 켜면 20,000자 넘는 글 중 제목이 없거나 요구사항인 것만 정리한다. 요구사항에서는 확실한 배경 절만 이유와 함께 표시하고(이유 없는 표시는 무시), 꺼져 있으면 모든 절이 요구사항. 이미지는 정리하지 않고 CEO 설명이나 CTO `자료 요약`으로 한 줄을 채운다.
- [x] 검증: `cargo test --lib` 145(기준선 142 + 요구사항 분류·빠짐 검사 1, 역할 제안 1, 계획 반영 검사 1), 세 프런트 `tsc`, `vitest` 97(+1). 모의 앱에서 PRD 칩이 요구사항으로 제안되고 전환·정리 담당 켜기가 동작, 계획 카드에 "요구사항 2절 중 1절을 업무에 반영" 표시, 콘솔 오류 0.
- 남은 위험: PM이 요구사항 원문을 읽는 만큼 토큰이 는다. 실제 반영률과 토큰은 QA-47에서 확인한다.
