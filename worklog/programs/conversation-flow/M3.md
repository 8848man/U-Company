# M3 — 개선과 거부 (완료, 오프라인 검증)


작업 중 파일 추가: `src-tauri/src/plan_review.rs`(신규), `src-tauri/src/engine.rs`(계획~승인 대기 반복), `src-tauri/src/lib.rs`(명령 2개·프로토콜), `src-tauri/src/meeting.rs`·`archive.rs`·`squad.rs`(취소 상태 허용).

- [x] 변경: `revise_plan`(계획 카드 `개선`)은 승인 대기 중인 계획의 승인을 `revise_requested`로 바꾸고 CEO 방침을 저장하며, 대화에 CEO 방침과 시스템 답을 한 쌍 남긴다(AI 해석 없음). 엔진은 승인 대기에서 이를 보면 시작하지 않은 업무만 지우고(시작한 업무가 있으면 거절) 같은 목표에서 PM 계획부터 다시 하며, 프롬프트에 CEO 방침(신뢰하지 않는 데이터로 표시)과 바뀐 계획의 범위를 넣는다. 새 계획은 새 승인을 받는다. `cancel_goal`(계획 카드 `거부`)은 승인을 거부하고 목표를 `cancelled`로 닫는다. 엔진은 거부를 보고 목표가 취소됐으면 멈춤으로 바꾸지 않고 끝낸다. 취소된 목표의 시작 안 한 업무는 누구도 바쁘게 하지 않고, 보관할 수 있다. 백엔드 프로토콜 35. 화면: `개선`은 다음 메시지를 `revise_plan`으로, `거부`는 `cancel_goal`로 보내고, 취소된 목표에는 "같은 내용으로 다시 시작"(새 목표 + 바로 실행)이 보인다.
- [x] 명세: DM-04와 ADR-0046의 개선 설명을 구현에 맞췄다(업무 `superseded` 상태 대신, 시작하지 않은 업무를 지우고 바뀐 승인에 범위 원문을 남김).
- [x] 검증: `cargo test --locked --lib` 119 통과·2 무시(기준선 114 + `plan_review` 5: 개선은 승인만 바꾸고 업무는 엔진만 지움, 개선·거부한 계획은 시작 불가, 시작된 업무가 있으면 개선 거절, 취소는 파일·업무를 건드리지 않고 아무도 바쁘게 하지 않음, 대기 중 계획에만 답 가능·방향 변경 우선). `cargo check --all-targets` 새 경고 없음. 세 프런트 `tsc`, `vitest` 80, 세 빌드 통과. 모의 렌더링으로 취소된 목표 확인.
- [x] 자체 검토에서 고침: 개선 요청 뒤 엔진이 다음 계획을 시작하기 전까지 목표가 '승인 대기'로 남아 대기 승인 없는 복구 카드가 뜰 수 있었다. 개선 요청과 같은 트랜잭션에서 목표를 `planning`으로 옮긴다.
- 남은 위험: 엔진의 반복 경로(`run`의 재계획)는 Tauri `AppHandle`이 필요해 종단 시험이 없다. 규칙 함수와 상태 전이는 단위 시험으로 확인했다. 실제 PM이 개선 방침을 반영하는지는 QA-45에서 확인.
