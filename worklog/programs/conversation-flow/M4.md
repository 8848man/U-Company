# M4 — Office 창 (완료, 모의 렌더링 검증)


- [x] 변경: v3에 앱 안 Office 창(`OfficeWindow`)을 더했다. 대화 머리글의 `Office ↗`, 진행 줄, 상단 `Office 창` 버튼으로 연다. 제목 막대를 끌어 옮기고, 모서리로 크기를 바꾸고(최소 320×240, 제목 막대는 항상 앱 안), 오른쪽에 붙이면 앱이 그만큼 좁아져 대화를 가리지 않으며, 최소화하면 왼쪽 아래 작은 막대가 된다. 위치·크기·모드는 이 컴퓨터의 `localStorage`에 저장하고 읽기 실패 시 기본값을 쓴다. 안에는 단계 띠(분석 → 계획 → 승인 → 작업 → 합치기 → 검토 → 완료, 승인 대기와 멈춤은 다른 색), 대화와 같은 진행 줄, 기존 픽셀 Office(이 목표의 팀원만 또렷하게, `OfficeCanvas`에 `focusIds` 추가), 팀원 목록(이름, 맡은 일, 작업 중·대기·끝남·멈춤)이 있다. Office 페이지는 팀 설정용으로 그대로 둔다(ADR-0046 문구를 이에 맞춤).
- [x] 검증: 세 프런트 `tsc`, `vitest` 85(기준선 80 + `officeWindowState.test.ts` 5: 단계 띠, 멈춤·취소, 팀원 목록, 다른 목표에서의 활동 구분, 창 위치 제한), 세 빌드 통과. 모의 렌더링으로 떠 있는 창·붙인 창·최소화를 확인하고, 제목 막대 끌기 후 위치가 저장되는 것을 확인했다. 붙였을 때 대화를 가리던 것, 사무실 그림 위아래 빈 띠, 최소화 막대가 전송 버튼을 가리던 것을 고쳤다.
- [x] Windows 실행에서 찾음(2026-10-14 CEO): 하얀 화면, 콘솔 `does not provide an export named 'GoalChat'`. 원인은 `GoalChat.tsx`와 `goalChat.ts`, `OfficeWindow.tsx`와 `officeWindow.ts`가 대소문자만 달라 Windows에서 확장자 없는 import가 계산 파일로 열린 것. 계산 파일을 `goalStream.ts`(M1 브랜치 수정 커밋)와 `officeWindowState.ts`로 바꾸고, 같은 폴더에 대소문자만 다른 파일 이름이 생기면 실패하는 `src/fileNames.test.ts`를 더했다(일부러 충돌 파일을 만들어 실패하는 것 확인). 리눅스 시험·빌드는 대소문자를 구분해 이 문제를 잡지 못했다.
- [x] Windows 실행에서 찾음(2026-10-14 CEO): 캐릭터를 여러 번 옮기고 우클릭하는 중 `Cannot read properties of null (reading 'dx')`로 앱 전체가 멈춤. 원인은 창 끌기에서 위치 계산을 React의 나중 갱신 함수 안에서 `dragRef`로 읽었는데, 그 전에 버튼을 떼면 ref가 비어 있던 것. 위치를 이벤트 순간에 계산하고, 왼쪽 버튼으로만 끌기 시작하며, 포인터 취소·캡처 해제에서도 끌기를 끝낸다. Office 창은 `SafeBoundary`로 감싸 창 안 오류가 앱 전체를 멈추지 않게 했다. headless Chromium에서 끌기·놓기·우클릭 60회 반복으로 수정 전에는 창이 사라지는 것(재현), 수정 후에는 오류 0을 확인했다.
