# M6 — 원클릭 해결 요청과 계획 형식 자동 교정 (완료, 오프라인·모의 렌더링 검증)


- [x] 찾음(2026-10-14 CEO, Windows): QA 뒤 멈춘 목표에서 `팀원에게 해결 요청`이 아무 일도 하지 않음. 버튼은 입력칸에 초점만 줬다. 멈춘 원인은 PM의 QA 재작업 계획이 산출물 하나에 수용 기준을 9개 이상 적어 `validate_contract`가 거절한 것이고, 재작업 요청문에는 1~8개 제한이 없었으며 엔진은 다시 묻지 않고 `other`로 멈췄다.
- [x] 결정: CEO가 계획 문서(권장안 네 가지: 자동 재요청 1회, 한도 도달 시 클릭마다 +1, 같은 목표 재작업, 대화에 한 줄)를 승인해 [ADR-0048](../../../sdd/architecture/decisions/ADR-0048.md)(신규, 색인)로 기록. DM-05, GC-03, 보안 명세, 구현 지도, QA-46 반영.
- [x] 엔진: 첫 계획과 재작업 계획 요청문에 같은 계약 한도를 적고, 형식 검사에 떨어진 계획은 정확한 오류를 붙여 같은 계획 리드에게 한 번 더 요청한다(재작업 횟수 안 씀, 대화에 한 줄). 두 번째도 틀리면 새 멈춤 종류 `plan_form`. 범위 밖 파일이 필요한 재작업은 그대로 `qa_failed`.
- [x] 명령: `request_team_fix`(프로토콜 36). 경로는 저장된 기록으로 엔진이 정한다(`team_fix::route`): 검토 단계에서 멈췄고 모든 업무가 끝났고 승인된 범위가 있으면 같은 목표에서 승인된 파일 안 재작업 후 바로 작업·QA(한도에 닿았으면 그 목표 한도 +1 기록), 그 밖은 계획 리드에게 보낸 자동 방향 변경으로 새 목표 버전(새 계획은 계획 카드 승인), 연결 문제와 CEO 거절은 거부. 요청문은 멈춤 사유와 최근 QA 라운드의 미충족 기준으로 앱이 만들고, CEO 턴(`team_fix`)으로 대화에 남는다. 상태를 바로 `planning`으로 바꿔 두 번 눌러도 한 번만 시작한다.
- [x] 화면: 카드 제목을 `팀원에게 해결 요청`으로(거절은 기존 문구, 연결 문제는 `AI 연결 확인`), 주 버튼 `<계획 리드>에게 해결 요청`과 무엇이 일어나는지 한 줄, 보조 버튼 `직접 지시하기`. v1/v2 대화 화면에도 같은 버튼을 연결했다.
- [x] 검증: `cargo test --lib` 125(기준선 119 + `team_fix` 5 + 형식 재요청 1), `cargo check`, 세 프런트 `tsc`와 빌드, `vitest` 92(기준선 89 + 해결 요청 3). 모의 앱에서 같은 모양의 멈춘 목표를 열어 버튼 → 대화상자 닫힘, CEO 턴·답, 진행 줄 "서연이 작업을 나누는 중…", 콘솔 오류 0을 확인했다.
- 남은 위험: 실제 PM 재작업과 QA 재검토는 Windows에서 QA-46으로 확인한다. 이미 멈춘 목표가 `validating`이 아닌 단계에서 멈췄다면 새 목표 버전 경로로 간다.
