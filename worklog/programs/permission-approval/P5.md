# P5 — 명령 카드 줄이기와 `명령 전부 허용` 모드 (2026-10-31, Claude)

브랜치 `feature/command-permission-modes`(기준 `feature/now-todo` `d6b13a1`). [ADR-0063](../../../sdd/architecture/decisions/ADR-0063.md).

계기: CEO가 "목표 진행 중 `cd`처럼 승인이 필요 없는 명령에도 작업이 멈춘다"고 보고. 원인 조사(`permissions.rs`, Claude Code 권한 문서): Claude Code가 `cd <경로> && npm test` 같은 줄을 통째로 거절 → 엔진이 줄을 나눠 `cd …`까지 카드에 올림 → 경로가 붙은 `cd`는 '작업 폴더 밖 경로'로 분류돼 `모두 승인`에서 빠지고, 폴더가 바뀔 때마다 새 규칙이라 카드가 반복. CEO 결정: 1번(카드 줄이기)으로 개선하고, 계획 카드에서 켜는 3번(`명령 전부 허용`)을 추가, 켜진 동안 목표 대화 외곽에 붉은 띠, 이 모드에서 push·PR은 막기.

## 범위

- [x] ADR-0063, Security·AI-03·UF-05·GC-03·Validation·ADR 인덱스 갱신(원래 CRLF 줄 끝 유지).
- [x] `permissions.rs`: 읽기 전용 명령(`cd`·`ls`·`echo` …)은 규칙·카드·허용에서 제외하고 coverage 판단에서 무시. 읽기 전용만으로 된 거절 줄은 coverage가 되지 않음.
- [x] `permissions_flow.rs`: 안전 등급 허용은 프로젝트 단위(`command_grant_project`)로도 저장해 같은 프로젝트의 이후 목표에 적용. 카드에 물을 규칙이 없을 때는 모든 거절 줄이 이미 허용될 때만 재개(읽기 전용만 막힌 줄은 재시도 안 함). `CommandMode`(`command_mode`, 대화 단위)와 `set_mode`(켜기: 확인 플래그 + 같은 대화의 대기 중 `project_write` 계획 카드 필요, 회의 불가; 끄기: 언제나). 팀원 프롬프트에 "폴더 루트에서 실행, 밖으로 cd 금지"와 모드 안내. `record_commands_run` → `commands_run` 업무 이벤트.
- [x] `provider.rs`: 쓰기 호출 + 모드 켜짐이면 `bypassPermissions` + `--disallowedTools`(git push, gh pr/api/repo/release/workflow, npm·cargo publish). 프로세스 환경: `GIT_CONFIG_COUNT`로 모든 push URL을 쓸 수 없는 전송으로 바꾸고 `credential.helper` 비움, `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`, GitHub 토큰 변수 제거, 빈 `GH_CONFIG_DIR`(임시 폴더 `ucompany-gh-signed-out`). QA(`dontAsk`)·분석·회의(`plan`)는 그대로. Claude `tool_use`의 Bash/PowerShell 명령을 `commands_run`으로 반환.
- [x] `engine.rs` 한 줄(실행 명령 기록), `runtime.rs` 필드 추가, `lib.rs` 명령 `get_command_mode`·`set_command_mode`.
- [x] 화면: `src/commandMode.ts`(상태 훅, `canTurnOn`, 위험 안내 문구), `src/CommandModeControl.tsx`(계획 카드 스위치 + 확인창, 상단 `명령 전부 허용 중 · 끄기` 띠), `src/commandMode.css`(외곽 붉은 띠 `#e5534b`, outline이라 머리말·입력창 위에도 보임), `GoalChat.tsx` 연결.

## 의도적 중복과 제거 경로

모드 스위치는 공용 v3 제어기(`v3/src/App.tsx`)를 거치지 않고 `useCommandMode` 훅이 직접 `get_command_mode`/`set_command_mode`를 부른다. 같은 시점에 다른 작업(v4 프리셋, WLG-059~061)이 `App.tsx`의 같은 줄을 고치고 있어 충돌을 피하려는 선택이다. 제거 경로: 두 작업이 합쳐진 뒤 스냅샷에 `commandModes`를 넣고 `GoalChat`에 `commandMode`·`onSetCommandMode` prop으로 바꿔 훅을 지운다.

## 검증

- `cargo test --locked`: 193 통과, 0 실패(새 시험 6개: 읽기 전용 명령, 프로젝트 단위 허용, 모드 켜기 조건·끄기, bypass 인자·환경, 실제 git으로 push 거절·fetch 유지, tool_use 명령 추출). 기존 종단 시험 `a_refused_test_command…`의 기대 규칙에서 `echo`를 뺌(ADR-0063 의도).
- `cargo clippy --lib`: 새 경고 없음(남은 경고는 기존 파일).
- `tsc --noEmit`(루트·v3), `vitest run` 31개 파일 140 통과(새 `commandMode.test.ts`), `vite build --config v3/vite.config.ts` 성공.
- 화면: `dump_screen_snapshots`의 실제 계획 스냅샷 + 모의 Tauri 브리지 + headless Chromium(1280·420px). 켜짐: 외곽 붉은 띠·상단 띠·계획 카드 `켜짐 · 끄기`; 꺼짐: `명령 전부 허용 켜기…`; 확인창 문구·버튼. 콘솔 오류 없음. 420px에서 페이지 폭이 800px로 넘치는 것은 이 변경 전과 같음(기존).
- 이 작업은 CEO 작업 폴더에 다른 작업의 커밋되지 않은 변경이 있어, 마지막 커밋의 사본으로 클라우드 작업 공간에서 진행했다.
