# Validation specification

Post-approval meeting recovery (MAM-014): verify protocol 23 rejects a protocol-22 frontend/backend mismatch; a block records time and build; synthetic stdin transport handles large input without deadlock while unverified providers remain in argument mode; a full-cap 2- and 3-participant synthetic round keeps **every** stage packet within its preapproval bound; format drift receives at most one bounded repair call within the plan's visible spare budget; a failed/invalid packet retries only by CEO action and an unknown outcome requires explicit duplicate acknowledgement; source changes before proposal require snapshot-or-replan choice while later changes keep using approved bytes; fingerprint v2 ignores transient capabilities but binds executable/model; CRLF quotation offsets refer to original bytes. Offline checks do not establish real Windows Claude/Codex behaviour.

## Windows runtime acceptance fixture

An opt-in local integration test may create a fresh Git repository below the workspace's ignored `.run-data` directory. It uses an already authenticated Codex CLI to run two independent file tasks concurrently in separate worktrees, integrates only their declared files, and asks a read-only QA instance to inspect the result. Keep the fixture and run evidence for diagnosis; the test must not install software, change another repository, or report UI recovery as verified. A passing fixture proves the CLI, parallel worktree, integration, and QA path, while the Tauri approval and restart flow still needs its own app-level check.

## Per-change checks

Run formatting/type/compile checks, focused domain and adapter tests, relevant UI tests, and cross-boundary contract checks. Finish with a spec/code/ADR drift review. A release is recorded only when actually shipped.
