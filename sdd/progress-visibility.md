# 일의 진행 UI 표시 정책

## 목적과 적용 범위

이 정책은 [UI/UX 구현 철학](ux-principles.md)의 UXP-7(사실만 그린다)·UXP-8(같은 것은 어디서나 같게)의 사실 기준을 소유한다.

CEO가 작업의 종류나 AI 공급자가 달라도 **누가, 무엇을, 어느 단계에서, 마지막으로 무엇을 확인했는지, 다음 행동이 무엇인지** 같은 방식으로 파악할 수 있어야 한다. 이 정책은 Office, 업무 현황, CEO 목표 카드와 이후 추가되는 진행 화면에 공통 적용한다. 새 화면이나 런타임을 만들 때 개별 애니메이션부터 정하지 않고 이 문서의 상태 매핑과 출처 규칙을 먼저 적용한다.

## 상태 해석 순서

1. 저장된 Goal/Task/Approval 상태를 사실의 기준으로 삼는다. 실행 중 업무의 `assigneeId`가 가장 구체적인 담당자다. 목표가 `analyzing`, `planning`, `validating`이면 각각 활성 CTO, PM, QA를 현재 담당자로 표시한다. 승인 대기와 통합은 팀 또는 CEO 단계이며 개인이 실제 실행 중인 것처럼 보이지 않는다.
2. 각 담당자에 대해 현재 목표·업무 제목, 상태, 시작/마지막 확인 시각, 관련 파일, 확인 가능한 최근 이벤트를 모은다. 새 이벤트 유형도 goal/task/agent 참조와 시간이 있으면 같은 패널에 나타나야 한다.
3. 런타임 구조화 이벤트는 도구 종류와 시작/완료 같은 운영 사실만 짧게 요약해 저장한다. 프롬프트, 사고 과정, 명령 인자, 임의 stdout, 비밀 값은 진행 UI에 넣지 않는다. 이벤트가 없는 런타임은 단계·경과 시간·마지막 기록만 표시하고 활동을 지어내지 않는다.
4. 오래 지속된 상태를 임의의 완료율로 환산하지 않는다. 그래프는 완료한 명시적 단계와 업무 수를 보여주고 현재 단계는 진행 중으로 표시한다. 승인 대기·실패·중단은 완료와 구분한다.

## 공통 화면 동작

- **한눈에 보기:** 활성 담당자 캐릭터에 말풍선과 움직이는 `…`를 표시한다. 버튼의 접근성 이름에도 상태와 현재 업무를 넣는다. 애니메이션을 줄이도록 설정한 환경에서는 정적인 상태 표시를 유지한다.
- **팀 인계:** 엔진이 저장한 `agent_handoff` 이벤트에 발신·수신 구성원이 모두 있으면 Office에서 발신 캐릭터가 수신자 쪽으로 잠시 이동해 인계 말풍선을 보이고 원래 자리로 돌아온다. 이는 실제 인계 사실의 표현이며 작업 완료나 실시간 대화 내용으로 해석하지 않는다. 저장된 자리 좌표를 바꾸지 않고, 오래된 이벤트는 재생하지 않는다. 감소된 모션 설정에서는 이동을 없앤다.
- **자세히 보기:** 담당자를 클릭하면 활동 패널을 먼저 연다. 실제 작업 중이면 업무 제목, 상태, 그래프, 시간순 실제 이벤트를 보여준다. 업무가 없으면 역할을 소개하는 짧은 예시 대화를 보여주되 `예시 대화`라고 명시한다. 설정은 별도 탭에서 연다.
- **같은 정보의 연결:** 업무 현황의 담당자 이름을 누르면 Office의 해당 담당자 활동 패널로 이동한다. 두 화면은 동일한 저장 상태와 이벤트를 사용한다.
- **목표별 진행:** 업무 현황은 선택된 프로젝트의 모든 목표에 동일한 단계 그래프를 그린다. 완료율을 임의로 계산하지 않고 완료한 단계·통합된 업무 수와 현재 단계만 표시한다. 사용자가 같은 일로 묶은 목표도 각각의 그래프와 승인·담당자 상태를 유지한다.
- **막힘과 다음 행동:** 실패·승인 대기·중단 상태는 **이유 → 마지막 확인된 사실 → 담당자 → 가능한 다음 행동** 순서로 보여준다. 목표 카드, 목표 작업공간, Office 목표 레일이 같은 선택 함수와 같은 저장 상태를 쓴다. 확인할 이벤트가 없으면 `아직 세부 실행 기록이 없습니다`라고 표시한다.
- **오래 응답 없음:** 실행 중인 업무의 마지막 확인 기록이 오래되면 `마지막 기록 후 N분`을 진단 정보로만 보인다. 실패·완료·재시도·승인으로 바꾸지 않고, 같은 상태를 반복 알림하지 않는다.
- **산출물과 근거:** 산출물 업무는 산출물 한 줄, 담당자와 배정 이유, 출력 파일, 수용 기준, 입력 근거 파일을 계획 승인 화면과 목표 작업공간에 같은 내용으로 보인다. 완료 후에는 업무별 QA 판정, 기준별 충족 여부와 근거, 미확인 항목을 함께 보인다.
- **새 유형 대응:** 새 목표 단계, 작업 상태, 어댑터 이벤트는 공통 상태 범주(대기/진행/승인/완료/막힘)에 매핑하고 알 수 없는 값은 원문 상태명과 마지막 기록으로 표시한다. 지원되지 않는 정보를 추정해서 그리지 않는다.

## 검증 기준

활성 CTO/PM/Developer/QA, 다중 개발자 병렬 실행, 승인 대기, 실패, 재시작 후 중단, 이벤트가 없는 외부 어댑터를 각각 시험한다. 담당자 표시는 실제 저장 상태와 일치해야 한다. 브라우저 새로고침 후에도 저장된 진행 기록과 그래프가 같은 내용을 보여야 한다. 예시 대화와 실제 기록은 시각적 라벨로 구분한다.
