# ADR-0019 — Staged project-scoped SDD import

Status: Accepted

Date: 2026-10-08

Affects: [External SDD import](../../specImport/00_index.md), [Security](../../security.md), [Domain](../../domain/00_index.md)

Context: Existing team characters are stored at workspace scope, while goals are bound to projects. Directly copying external roles into global agents would change other projects. External SDD and harness instructions are untrusted and may not fit the engine's fixed workflow.

Decision: Parse text locally into a staged draft with project, agent, workflow, and exception specifications. Apply a versioned profile to one registered project in a transaction. Agent specs remain placeholders until explicitly bound to existing characters. The first slice does not transmit imported content to a provider or change runtime prompts. A later provider handoff must show the exact selected content and destination for approval. The fixed engine stages and approval checks remain authoritative. Preserve unknown sections as exceptions rather than guessing their operational meaning.

Alternatives: Let an AI rewrite the whole organization and execute the result immediately; this has unpredictable mapping, cost, and approval risk. Overwrite global agent instructions; this leaks one project's process into another. Require every existing harness to be converted to a new file format; this harms adoption.

Consequences: Imported workflow steps are locally structured and reviewable but do not yet guide AI planning or replace the hard-coded scheduler. Executable workflow extensions and provider transmission require a later versioned contract and separate approval review. Project profiles can be reviewed and advanced without touching existing harness files.
