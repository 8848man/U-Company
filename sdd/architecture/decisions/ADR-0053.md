# ADR-0053 — A repair that needs new files asks on the same goal; a repair with nothing to change goes back to QA

Status: Accepted (2026-10-20, CEO via the completion rounds plan). Owners: [Security](../../security.md), [DM-05 복구](../../domain/DM-05-recovery.md), [완주율·사용성 개선 라운드](../../completion-usability-rounds.md) R3.

## Context

The R2 end-to-end tests ([ADR-0052](ADR-0052.md)) showed two ways a goal stops although nothing is wrong:

1. A repair plan that needs a new file (a README the QA asked for, a helper module) was sent back once and then blocked as `needs_scope`, so the CEO had to go through a new plan version and approve the whole plan again for one file.
2. A repair whose teammate decided nothing needed changing (QA had misjudged) failed integration with "no file changes" and blocked as `integration_conflict`, which reads as a merge problem.

## Decision

1. **Scope addition on the same goal.** If a repair plan names files outside the approved scope, the engine creates a `project_write_scope` approval listing each new file and the repair tasks, moves the goal to `awaiting_approval` and waits for the button. Approved: the repair runs on the same goal and the added files join its scope (read from its tasks). Denied: the goal blocks as `needs_scope` with no file changed, and `해결 요청` plans a new version as before.
2. **Limits.** At most eight new files at once; `AGENTS.md`, `CLAUDE.md` and anything under `.ucompany/` are never added this way (they need a new plan version). The plan checks (`validate_plan`, contract, references) still apply.
3. **Unchanged repair.** A repair task with no file change completes with a note and the next QA judges the unchanged files. The rework limit still bounds the loop. A non-repair task with no change still fails integration.
4. **Screen.** v3 shows the scope approval as its own card (`고칠 때 새 파일이 필요해요`) with `파일 추가 승인` and `거절`; it has no `개선`, and `거절` stops the goal instead of cancelling it.

## Alternatives

- **Keep the new-version route:** safe but asks the CEO to re-approve the whole plan for one file, and the conversation gains a version.
- **Allow any new file inside the project silently:** removes the CEO's control over what is written; rejected by the security spec.

## Consequences

- `engine.rs` (`scope_addition`, `request_scope_addition`, repair prompt, scope read from the goal's tasks, unchanged repair in `integrate_task`), `src/goalStream.ts`, `src/GoalChat.tsx`, mock AI modes `needs-scope-once`, `repair-no-change`, three end-to-end tests.
- A restart while the scope approval waits leaves the goal interrupted; recovery follows DM-05 (`해결 요청`).
