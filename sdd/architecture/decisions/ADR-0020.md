# ADR-0020 — Portable project specification and local runtime projection

Status: Accepted

Date: 2026-10-08

Affects: [External SDD import](../../specImport/00_index.md), [Security](../../security.md), [Architecture](../../architecture.md)

Context: ADR-0019 made SQLite the applied profile store. JSON download alone does not make edits by Codex, Claude, or another tool visible to Ucompany. Project/team/workflow definitions need a shared owner, while approvals, credentials, and execution history must remain local.

Decision: Use a versioned project-owned `.ucompany/spec.json` manifest as the portable definition source once it exists. SQLite retains an explicitly applied projection and runtime records. The app reports drift, previews current file content before apply, and can initialize the file from an existing profile only if absent. It does not overwrite external edits, edit harness entry points, or automatically transmit imported text to a model. Tool-specific `AGENTS.md` and `CLAUDE.md` can reference the portable file.

Alternatives: Make SQLite authoritative and add import/export buttons; this requires manual transfer and hides external edits. Store all app data in project files; this would mix private operational state and portable definitions. Auto-sync both directions; filesystem and SQLite cannot commit atomically, and concurrent external edits could be overwritten.

Consequences: The canonical manifest is portable, while local application remains an explicit review step. Runtime use of role/workflow instructions still requires the separate provider handoff and engine policy work. A DB profile without a project file remains a local legacy profile until initialized.
