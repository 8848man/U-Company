# ADR-0044 — Consent-gated SDD origin: detect, follow, or bootstrap a project structure

Status: Accepted (2026-10-12, CEO). Owners: [SI-03 SDD 구조 감지와 부트스트랩](../../specImport/SI-03-origin.md), [SI-02 프로젝트 공통 파일](../../specImport/SI-02-portable.md), [Security](../../security.md), [UF-07 외부 명세 이식](../../userFlow/UF-07-spec-import.md).

## Context

A selected project folder may already be managed by a spec-driven workflow (`AGENTS.md`, `CLAUDE.md`, Cursor rules, an external SDD tool such as Spec Kit or OpenSpec), may contain only coding rules, or may have nothing. The CEO wants the app to follow an existing workflow when there is one, and otherwise to set up a U-Company SDD structure as plain project files so that work can continue with any AI tool.

[ADR-0021](ADR-0021.md) left cross-tool Markdown SDD ownership open: "a future reference-based schema must address it explicitly". [SI-02](../../specImport/SI-02-portable.md) and [Security](../../security.md) also said the app never edits `AGENTS.md`/`CLAUDE.md`. That kept existing harnesses safe, but no tool that opens the project without the app's commands could find a shared structure.

A comparison of three public SDD references (Spec Kit, OpenSpec, a three-file personal workflow) on synthetic fixtures showed the same gap. Each one creates its own folders even where a project already has rules. None gives a tool that arrives without its commands a file-based entry point. Records: `tests/sdd-origin/sample_results/`.

## Decision

1. **Detection is read-only and static.** `get_sdd_origin_status` walks the canonical project root without following symbolic links, skips dependency/build folders, stops at depth 4, and classifies the result from file names, locations and a short keyword list. No AI call, no file change, no transmission. Project registration itself still never modifies the folder.
2. **Classification.**
   - `.ucompany/sdd/` exists → `continue` (the project already uses this structure).
   - Agent guidance (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.cursorrules`, `.github/copilot-instructions.md`, `.cursor/rules/`) or an external SDD folder (`specs/`, `.specify/`, `openspec/`, `.kiro/specs/` containing documents) → `existing`. A signal found only in a subfolder makes that subfolder the scope; nothing is offered at the root.
   - An empty guidance file counts as absent. Guidance with content but no spec-workflow keyword → `ask` (keep it; offer to add a workflow section).
   - Nothing → `bootstrap`.
   - When `AGENTS.md` and another tool's guidance both carry rules, the app follows `AGENTS.md` as the more general file and says so.
3. **Following an existing workflow** means the app shows what it found and offers the existing [SI-01](../../specImport/SI-01-import.md) preview of those files. The engine's fixed stages, approvals and file boundaries do not change.
4. **Three project-file writes, each authorized only by its own CEO confirmation** of a preview that lists every file and change. The backend recomputes the plan at apply time and refuses it if any listed file changed since the preview (digest), if a path is a symbolic link, leaves the canonical root, or exceeds 512 KiB.
   - `bootstrap` (mode `bootstrap`): create `.ucompany/sdd/` (index, graph, constitution, handoff, `features/`, `decisions/`), a root `AGENTS.md` whose only content is the managed block, and a one-line `CLAUDE.md` (`@AGENTS.md`). Empty existing entry files are filled; no other file is touched.
   - `add_section` (mode `ask`): append the managed block to the existing `AGENTS.md` byte-for-byte after its current content and create `.ucompany/sdd/`. `CLAUDE.md` is created as the one-line bridge if absent or empty; if it has content that does not load `AGENTS.md`, a managed block holding only `@AGENTS.md` is appended after that content.
   - `convert` (modes `existing` and `ask`, root scope only): copy every root guidance file to `.ucompany/legacy/<UTC timestamp>/` first, then keep the original `AGENTS.md` text outside the managed block, replace `CLAUDE.md` with the one-line bridge, and create `.ucompany/sdd/`. Other tools' guidance files and external SDD folders are backed up but left in place. Nothing is deleted.
5. **The managed block** is delimited by `<!-- U-SDD:START -->` and `<!-- U-SDD:END -->`. The app writes only inside it. A later action replaces only that block, so the CEO's own text outside it survives every rerun.
6. **Structure (v0).** `.ucompany/sdd/00_index.md` owns IDs, the relation vocabulary and reading order, in the same style as this repository's [authoring principle](../../authoring.md). `.ucompany/sdd/graph.json` is a derived machine index of node IDs, owning file paths and typed edges. It is not a second original; where they disagree the Markdown index wins. The app does not synchronize prose between them. `.ucompany/spec.json` ([SI-02](../../specImport/SI-02-portable.md)) is unchanged and stays the role/workflow manifest.
7. **Tools.** The bridge is created only for tools tested in practice (Claude Code reads `CLAUDE.md`; GPT/Codex reads `AGENTS.md`). Gemini, Cursor and Copilot are listed as placeholders and receive no files until verified.

## Alternatives

- **Keep "never edit `AGENTS.md`/`CLAUDE.md`":** rejected. Tools that open the project without app commands cannot find the structure. The confirmation, preview, digest check, managed block and backup keep the original safety goal.
- **Write the entry point automatically on registration:** rejected. Registration must stay read-only. A silent write would also break a project that already has a workflow.
- **Adopt Spec Kit or OpenSpec as the structure:** rejected. Both create their own folders inside projects that already have rules, and neither has a tool-neutral file entry point. Their per-feature folders and checkbox task lists are kept as ideas.
- **A top-level `.sdd/` folder:** rejected. The app already owns `.ucompany/` in project folders; one app-owned folder is easier to recognize and back up.
- **Let an AI read every document to classify the project:** deferred. Static detection handles the clear cases at no token cost. AI review of the ambiguous candidates the scanner lists, and when to ask, belong to the onboarding design that follows testing.

## Consequences

- Backend protocol 33; the frontend minimum is unchanged. With an older backend the card shows only a restart note, and the rest of the screen works as before.
- The question appears in 설정 › 프로젝트 명세 for the selected project. Asking at the moment a folder is opened waits for the onboarding/tutorial flow design.
- Graph integrity (node files and anchors exist, typed edges, required relations, task list matches graph) is checked by the offline harness `tests/sdd-origin/`, not by the app in this slice.
- Real Windows verification is QA-43.
