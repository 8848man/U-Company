# ADR-0021 — One-way portable spec synchronization

Status: Accepted

Date: 2026-10-08

Affects: [External SDD import](../../specImport/00_index.md), [Security](../../security.md)

Context: ADR-0020 introduced a project manifest, but the existing generic import command could still apply an unrelated draft to SQLite after that manifest existed. This allowed two mutable originals. A previewed file could also change before application.

Decision: Only a draft produced by reading the fixed `.ucompany/spec.json` path may update the applied SQLite profile. At apply time compare its mapped content with a fresh read of the file and reject drift. A generic imported draft can create that file only if absent, then the app previews the file before applying. SQLite retains built-in presets, a reviewed operational projection and runtime records, never a competing SDD editor. An existing DB profile may create the file as a legacy migration path.

Alternatives: Bidirectional automatic merge cannot safely resolve concurrent file edits or reconcile prose. Automatically overwrite the project file from SQLite would erase work by another tool. A fully file-only runtime would require moving operational state into the project, which is outside this specification.

Consequences: Generic uploads still preview, but users save them into an absent project file or merge them into an existing one before applying. Cross-tool Markdown SDD ownership is not solved by this manifest alone; a future reference-based schema must address it explicitly.
