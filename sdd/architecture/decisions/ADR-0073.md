# ADR-0073 — CEO가 실행 중인 목표와 회의를 멈추고 다시 결정한다

Status: Accepted (2026-11-14, CEO). 구현·검증 상태는 Worklog를 따른다.
Date: 2026-11-14

Owners: [DM-04](../../domain/DM-04-lifecycle.md), [DM-05](../../domain/DM-05-recovery.md), [ME-01](../../meeting/ME-01-process.md), [AI-03](../../aiIntegration/AI-03-adapter.md), [Security](../../security.md).

## 맥락

현재 실행 목표에는 CEO 중단 버튼이 없고, 회의 중단은 새 호출만 막는다. 실행 중 회의 호출은 응답이 오면 기록한다. ADR-0070의 취소 신호는 제공자 경계에 있지만 화면 행동과 연결되지 않았다. 따라서 CEO가 멈춘 뒤에도 AI 호출이 계속되고 그 결과가 작업이나 회의에 반영될 수 있다.

## 결정

1. CEO가 진행 중 목표 또는 회의에서 `멈추기`를 누르면 저장 상태를 `paused`/`stopped`로 바꾸고 이미 완료된 작업, 통합 증거, QA 판정, 회의 발언과 호출 한도를 보존한다. 새 호출·통합·단계 전이는 시작하지 않는다. 이미 시작한 파일 통합 한 건은 원자 단계의 완료·실패를 기록한 뒤 멈추며, 그 변경 사실을 숨기지 않는다.
2. 진행 중 제공자 호출에 즉시 취소 신호를 보낸다. 제공자가 취소를 지원하면 ADR-0070의 제한된 종료 절차를 쓰고, 내장 CLI는 프로세스를 종료한다. 이미 결과가 도착했더라도 멈춤 이후에 확정된 응답은 결과나 발언으로 반영하지 않는다. 사용량과 취소 사실은 기록한다.
3. 멈춘 뒤 CEO는 `재개` 또는 `취소`를 고른다. 재개는 저장된 단계, 남은 작업, 현재 승인·파일·연결 조건을 다시 검사한다. 실행 중이던 업무의 결과는 불명확하므로 그 격리 작업본을 자동 통합하거나 자동 재실행하지 않는다. 불명확한 부분은 확인·재계획 경로로 보낸다. 회의는 기존 발언을 보존하고 계획 재승인 후 남은 패킷만 보낸다.
4. 취소는 목표 또는 회의를 종료하고 앱이 만든 격리 작업본을 경계 검증 후 정리한다. 원본 프로젝트의 이미 통합된 파일은 되돌리지 않는다. 취소 전에 어떤 변경이 원본에 반영됐는지 CEO에게 보여 준다. 취소는 새 프로젝트 쓰기나 외부 전송 승인이 아니다.
5. 회의의 종전 규칙인 “이미 시작된 호출은 회수하지 않음”을 대체한다. 취소 신호와 결과 폐기를 적용한다. 전송 자체를 회수할 수 없으므로 호출 수와 전송 사실은 남는다.

## 한계

- 제공자가 취소 신호를 무시하면 제한 시간이 지난 뒤 프로세스를 종료한다. 이미 전송된 내용을 취소할 수는 없다.
- 앱 재시작으로 결과를 알 수 없는 기존 호출에는 동일한 보수적 복구 규칙을 적용한다. 승인·전송을 자동으로 반복하지 않는다.
