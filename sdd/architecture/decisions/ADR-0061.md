# ADR-0061 — `지금 할 일` is the one place for the CEO's next action: original objective, CEO actions and starting Git

Status: Accepted (2026-10-27, CEO). Owners: [GC-03 작업 공간](../../goalConversation/GC-03-workspace.md), [GC-04 복구](../../goalConversation/GC-04-recovery.md), [Security](../../security.md).

## Context

Two recent additions sat outside the conversation's existing decision path:

1. **Git bootstrap (ADR-0045-era recovery).** The `앱에서 Git 저장소 시작` panel appeared in the feed whenever a blocked goal's text mentioned Git, but the backend accepted it only for a goal whose single unfinished task was a failed `git init`. In conversations like PostGen (no `.git`, criteria about commits) the panel showed and always refused.
2. **Original objective (ADR-0059/0060).** `이어서 하기`, `다시 열기` and the CEO actions were a separate card under the header, apart from `지금 할 일`, the place the CEO already uses for start and recovery (ADR-0047, ADR-0048).

## Decision

1. **One entry.** The `지금 할 일` bar names the highest-priority item, and its dialog holds the details and buttons. Priority:
   - start (a new goal)
   - recovery (`해결 요청` and the other recovery kinds)
   - checking the original objective
   - continuing it (`원래 목표 확인하고 이어서 하기` / `남은 일 n개 이어서 하기`)
   - CEO actions only (`CEO가 할 일 n개`, with `마쳤어요 · 다시 확인`)
   - starting Git
   - a closed conversation (`다시 열기`)

   The separate objective card is removed. In a multi-version conversation whose newest version stopped, the recovery dialog also offers `원래 목표 확인하고 이어서 하기`.
2. **Git start works where it is offered.** It is offered for a folder project when the conversation is about Git:
   - a blocked goal whose records mention `.git`, `git init` or commits
   - a conversation turn routed to `git_bootstrap`
   - a CEO action, or a stuck criterion (ADR-0060), about Git, commits or pushing

   The backend allows `preview_git_bootstrap`/`bootstrap_project_git` for any execution goal of the selected folder project while no goal of that project is running or waiting for approval (the execution mode changes). Scope approval is unchanged: exact files, author and message, `main`, no remote, no push. Automatic QA after the commit still runs only in the original recovery case (one blocked Git-init task whose files match the commit).

## Alternatives

- **Keep the objective card and fix only Git:** two places to look for "what do I do now".
- **Let the team run `git init` as a task:** the integration path cannot carry `.git` metadata (Security); the app's fixed operation stays the only way.

## Consequences

- `src/nowTodo.ts` (+tests), `src/GoalChat.tsx`, `v3/src/v3.css`; `git_bootstrap::allowed`, `lib.rs` command guards.
- A Git start no longer requires a blocked goal; the CEO can start Git from a completed conversation before pushing.
