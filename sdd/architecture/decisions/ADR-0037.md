# ADR-0037 — Bounded meeting packets and explicit recovery after plan approval

Status: Accepted (2026-10-09). Refines the delivery, validation and recovery portions of [ADR-0036](ADR-0036.md), while keeping its Office Agent, read-only provider and plan-approval decisions.

## Context

The first Office-character meeting can approve a plan whose proposal packet fits but later debate packets exceed the CLI command-line limit. Model format drift, failed calls and unrelated source or capability changes then block a meeting after approval. [MAM-014](../../multiAgentMeeting/MAM-014-decision.md) adopts stdin after provider-specific verification, planned spare calls for one format repair, and continuing with approved source snapshots.

## Decision

- Validate conservative worst-case packet lengths for every stage before plan approval. Preserve original content; reject an oversized plan instead of truncating a packet or response.
- Keep literal CLI arguments as the default. Use stdin for a built-in provider only after its synthetic Windows harness establishes a complete response, EOF handling and no deadlock. The common provider path makes the selection apply to meetings and execution goals.
- Record raw invalid output. A bounded repair request to the same member/stage spends one of two default spare calls within the 12-call hard cap. Repeated invalid output blocks. Manual stage retry requires an approved plan and available cap; an uncertain outcome additionally requires a CEO duplicate-send acknowledgement.
- Use approved source snapshots in packets. A file change before proposals requires CEO choice between the snapshot and a new plan; later changes do not invalidate critique/revision/evaluation. Fingerprint v2 binds stable destination properties, excluding transient capability/health results. Quote verification may normalize line endings/space while retaining original-byte offsets.
- Protocol changes prevent an older frontend from invoking new meeting commands; blocked records carry the build and time of the decision.

## Alternatives and consequences

Increasing the packet cap alone cannot bound later contributions, and silently shortening them loses evidence. Retrying an unknown outcome automatically can transmit a duplicate. Requiring reapproval after every unrelated source edit interrupts a debate even when the packet still uses frozen bytes. The selected design adds validation and visible recovery while preserving the plan scope and exact packet record. Real Claude/Codex stdin support remains disabled until separately verified on Windows; offline tests alone are not proof.
