# ADR-0022 — Explorer-style Windows project folder picker

Status: Accepted

Date: 2026-10-08

Affects: [Product](../../product.md), [Security](../../security.md), [Architecture](../../architecture.md)

Context: The existing Windows `FolderBrowserDialog` uses an older tree UI. It is difficult to navigate or confidently select a project root that already contains multiple folders. Registration itself already accepts nonempty ordinary folders, but the UI suggests a narrower flow.

Decision: Use the Windows Common Item Dialog (`IFileOpenDialog` with folder-picking and filesystem options) on a dedicated STA thread. It gives Explorer-style breadcrumb navigation and search and can select the currently displayed folder. Keep the existing native macOS/Linux picker and manual path fallback. Treat cancel as no selection; preserve canonicalization and registration checks after selection. When an ordinary selected folder contains nested repositories, copy their working files for isolated execution while excluding `.git` metadata at every depth.

Alternatives: Build a custom file browser inside the app, which duplicates OS navigation and permission behavior. Continue the legacy dialog, which fails the requested interaction. Use a file-selection workaround, which can return ambiguous filenames instead of a folder.

Consequences: Windows gains the native modern folder dialog. A parent folder with nested repositories can be registered and executed within the existing bounded copy and declared-file trust boundary, but nested Git metadata never enters the copy. UI click-through still requires manual verification in the desktop app.
