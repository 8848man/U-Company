# ADR-0067 — 필요한 거절 호출만 명령 승인 카드에 올린다

Status: Accepted (2026-11-08, CEO). Owners: [Security](../../security.md), [UF-05](../../userFlow/UF-05-approval.md), [AI-03](../../aiIntegration/AI-03-adapter.md).

## Context

ADR-0065의 PM 응답은 승인 요청 여부만 정했다. 엔진은 그 뒤 거절 호출 전체를 규칙으로 바꾸었고, 여러 줄 셸 스크립트는 JavaScript·PowerShell 본문까지 줄별 명령으로 잘못 나누었다. CEO에게 불필요하고 해석할 수 없는 승인 카드가 표시됐다.

## Decision

1. 앱은 거절 호출에서 후보 명령 규칙을 추출한다. PM은 새 승인이 필요한 후보 규칙의 키만 고른다. 엔진은 실제 거절 기록에서 나온 키만 받으며 PM이 새 명령을 만들 수는 없다. 한 거절 호출에 여러 명령이 있어도 필요한 것만 고른다.
2. 여러 줄 셸 입력·heredoc·제어문·인라인 스크립트는 줄별 승인 규칙으로 변환하지 않는다. PM은 필요한 단순 명령을 따로 요청하도록 Dev에게 기존 권한 내 재시도를 지시할 수 있다.
3. PM 응답이 잘못되거나 선택 없이 승인 요청을 하면 기존 권한으로 제한된 재시도를 한다. 횟수를 다 쓰거나 여전히 유효한 선택이 없으면 거절을 기록하고 현재 산출물을 QA에 보낸다. 선택되지 않은 거절 호출 전체로 CEO 카드를 만들지 않는다.
4. QA의 독립 거절 경로와 CEO의 실제 승인 버튼은 유지한다. PM 선택은 권한 부여가 아니다.

## Consequences

PM 응답 형식에 `rule_keys`가 추가된다. 기존 응답의 `request_approval`은 이 필드가 없으면 유효하지 않다. 승인 요청이 줄어드는 대신, PM이 필요한 단순 명령을 고르지 못하면 QA가 현재 산출물을 실패로 판정할 수 있다. 실제 Claude Windows 실행에서 원본 거절 호출과 표시된 카드의 일치를 검증해야 한다.
