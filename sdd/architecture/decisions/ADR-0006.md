# ADR-0006 — Adopt or initialize one selected folder

Status: Accepted

Date: 2026-10-01

Affects: [Product](../../product.md), [Security](../../security.md), [Integrations](../../aiIntegration/00_index.md)

Context: ADR-0005 exposed separate cards for an existing Git project and a new child directory. Manual QA found this choice unnatural: the user wants to select one folder and have the app decide whether to adopt or initialize it. Windows CLI discovery also treated extensionless npm shell wrappers as native executables.

Decision: Present one folder-selection flow. Adopt an existing Git root without changing it. Initialize only a selected empty folder outside any existing Git worktree, with a README and initial commit. Reject nonempty non-Git folders with an explanation; do not infer permission to alter their contents. Keep canonical paths for operations but convert Windows verbatim prefixes for display. Resolve Windows CLI executables using `.exe`, `.cmd`, and `.bat` before an extensionless name. Model overrides come from a provider catalog where available, with a provider-default option otherwise.

Alternatives: Creating a child folder after selection would require another name and repeat the split flow. Auto-initializing a nonempty folder risks changing unrelated user content. Persisting prettified paths would weaken canonical path comparisons.

Consequences: Folder choice has one main action and predictable safety behavior. Existing non-Git folders with content need a separate explicit migration flow later. Provider CLIs without a reliable catalog use their configured default model.
