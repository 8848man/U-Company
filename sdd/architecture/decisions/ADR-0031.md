# ADR-0031 — Linked user-flow graph as an SDD navigation layer

Status: Accepted

Date: 2026-10-08

Affects: [Product](../../product.md), [User flow index](../../userFlow/00_index.md)

## Context

The product specification gives an MVP sequence, while goal conversation, approval, recovery, provider setup, and portable SDD behavior are defined in separate owning specifications. A contributor can find each rule, but cannot follow a complete CEO journey or its branches from one entry point. Repeating detailed rules in a new journey document would create another conflicting SDD origin.

## Decision

Create `sdd/userFlow/` with one index and stable `UF-##` files. The index describes what each flow accomplishes and links to it. Each flow owns its user-facing sequence, entry and exit states, and typed links to other flows. Typed links are `requires`, `next`, `branch`, `resume`, and `observe`; target IDs must exist in the index. Flow files reference the owning product, domain, security, and feature specifications for normative rules. They do not redefine approval policy, state transitions, adapter contracts, or acceptance evidence. `WORKLOG.md` and manual QA continue to distinguish intended behavior from verified implementation.

## Alternatives

- One long end-to-end document: simple to open, but hard to maintain when branches change independently.
- A machine-enforced RDF or graph database: adds schema and tooling before the documentation needs queries or inference.
- Links only in the existing index: makes discovery easy but does not describe branch conditions or the user's next action.

## Consequences

Stable IDs and typed links make the flow set navigable by people and AI tools without creating a second business-rule authority. Every new user-visible journey must update the index and its adjacent flow relationships. Link checks can be automated later; the initial graph is Markdown and has no runtime effect.
