# ADR-0052 — Prove goal completion with a mock AI and close usability gaps in rounds

Status: Accepted (2026-10-20, CEO). Owner: [완주율·사용성 개선 라운드](../../completion-usability-rounds.md).

## Context

The app's safety gates fail closed, so its common failure is a goal that stops, not a wrong result. Nothing exercises the whole engine `run()` path: it needs a Tauri `AppHandle`, and real providers cost tokens and vary. The CEO wants to try building a sample app through U Company end to end on a dedicated branch.

## Decision

1. **Mock AI through the existing plugin protocol.** A dependency-free Node adapter (`scripts/mock-ai/mock-adapter.mjs`) speaks plugin protocol v1 (`initialize`, `send_task`), recognizes the stage from the request text, and replays a scenario: CTO analysis lines, a PM plan in the task schema, real file writes for implementation tasks, and QA verdicts. It is registered as a `plugin` connection with the `files` capability, so no engine branch knows it is a mock.
2. **End-to-end engine tests.** Engine functions become generic over `tauri::Runtime` so tests run `run()` on `tauri::test::mock_app()` with the mock adapter against a temporary Git project. Behavior is unchanged.
3. **Rounds.** The remaining improvements (scope addition on the same goal, plan-card estimates, result summary and block statistics, first-run guidance) are delivered in rounds R3–R6, each with owning-spec updates, tests and a WORKLOG entry; R7 verifies and hands over.

## Alternatives

- **A host trait instead of generics:** cleaner long term, but touches every call site with new types; generics over `Runtime` are a mechanical change Tauri already supports.
- **Testing only with real providers:** costs tokens, is not repeatable, and cannot run offline.

## Consequences

- New `scripts/mock-ai/`, engine generics, a `tauri` `test` dev feature, new end-to-end tests, [샘플 앱 흐름 점검](../../../qa/SAMPLE-APP-FLOW.md).
- The mock adapter is a test tool: it never claims to be a real model, and its connection name says `모의 AI`.
