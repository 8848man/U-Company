# ADR-0012 — Goal-owned QA caps and invocation-time model identity

Status: Accepted (2026-10-02)

ADR-0010 put the QA repair cap on the project and read it at each QA decision. That made a project setting change alter every existing goal. The project value is now only the default copied into a new goal. Each goal persists its own cap and the engine reads that value at each QA decision. A legacy goal with no saved cap receives the then-current project preset once when the database opens. This preserves the ability to edit a running goal without coupling separate goals. The alternative of falling back to the live project preset on every read would repeat the original coupling.

Token analytics needs to explain which model consumed tokens even after team assignments change. The per-invocation ledger snapshots connection ID and effective model ID. Old records retain unknown model identity; current assignments are not substituted because that would misattribute historical use. The existing five-second persistence cadence remains; analytics aggregates saved records without additional model calls.
