# ADR-0036 — Office-character meetings with chair-planned, plan-approved read-only debate

Status: Accepted (2026-10-09). Supersedes the transmission-grant parts of [ADR-0035](ADR-0035.md); ADR-0035's Goal kind, deliberation statuses, backend command guards and schema-refusal decisions remain.

## Context

ADR-0035 introduced Goal-bound deliberation with fixed viewpoint slots, per-packet approval as the default, an optional meeting-scoped grant and a closed-text gate that kept real Claude/Codex connections out of meetings. The user clarified the product intent (existing Office characters debate; a PM/CTO chair designs the debate; one Home composer selects the mode) and decided in [MAM-010](../../multiAgentMeeting/MAM-010-decision.md): D3, meetings share the read-only trust boundary of execution goals; D4, one CEO plan approval by default with optional per-stage packet review, superseding MAM-005 D1. [MAM-012](../../multiAgentMeeting/MAM-012-response.md) fixed the first implementation contract.

## Decision

- Participants, evaluator and chair are existing Agents snapshotted at plan approval; meetings never create Agents. The chair is `pm`, else `cto`, by fixed ID.
- The chair proposes a JSON plan; one backend function validates it; CEO edits create immutable revisions with digests; the CEO approves an exact revision and digest in `plan` or `per_stage` mode.
- Meeting provider calls use the same entry point, arguments and working directory as execution read-only calls. Only connections with a read-only execution profile (Claude and Codex CLI today) may take part; other kinds are excluded with a reason.
- Every call still goes through a recorded immutable packet and a transactional reservation that rechecks plan approval, packet digest, destination fingerprint, profile and cap, serialized with stop, revoke and restart. Uncertain calls are never re-sent automatically.
- One backend busy rule covers meetings and execution goals; plan approval and execution start check it in their transactions.
- The first protocol is one round of `propose_critique_revise`; decision packages carry an engine-built trace graph and engine-derived dissent.
- The database moves to schema version 4. Meetings of the earlier fixed-slot model are closed read-only (`legacy_closed`); their packets and approvals expire.

## Alternatives

- Keep the closed-text gate: safest, but blocks the characters' working connections, which execution goals already use under the same read-only boundary.
- Keep per-packet approval as default: exact, but stops a character debate at every stage; it remains available as `per_stage`.
- Let agents exchange Markdown files: readable, but needs project writes and cannot be validated or recovered; rejected in favour of engine-rendered records.

## Consequences

Participants can read files of the selected project beyond the chosen sources; the plan card states this and only quotes from frozen sources count as verified evidence. Read-only flags are trusted as for execution goals; their real Windows behaviour must be checked in QA-38 before practical use. Old binaries refuse version 4 data. The meeting-scoped `미리 승인` from ADR-0035 is retired.
