# ADR-0065 — Dev 권한 요청을 PM이 먼저 판단한다

Status: Accepted (2026-11-07, CEO). Owners: [Security](../../security.md), [DM-03](../../domain/DM-03-execution.md), [UF-05](../../userFlow/UF-05-approval.md), [AI-03](../../aiIntegration/AI-03-adapter.md).

Date: 2026-11-07

## Context

ADR-0058은 Dev의 거절된 명령을 곧바로 CEO 카드로 보냈다. 단순한 명령 조합이나 이미 승인된 방식으로 대체 가능한 요청도 CEO에게 넘어가 작업이 멈췄다. 반면 PM의 모델 출력만으로 네트워크·외부 작업 권한을 만들면 기존 승인 경계를 깨뜨린다.

## Decision

1. Dev의 거절된 명령은 통합 전에 해당 목표에서 계획을 맡은 PM이 한 번 검토한다. PM은 승인 범위와 명령을 보고 `request_approval`, `retry_with_existing_grants`, `continue_without` 중 하나와 이유를 JSON으로 제안한다.
2. `retry_with_existing_grants`는 새 권한을 저장하지 않는다. 앱이 같은 Dev 세션에 PM의 제한된 지시를 전달한다. 재시도에서 새 거절이 나오면 기존 횟수 상한 안에서 CEO 카드로 보낸다.
3. `request_approval`만 기존 CEO 명령 승인 카드를 만든다. `continue_without`은 거절을 기록하고 현재 산출물로 통합·QA를 진행한다. PM 출력의 명령·경로·승인 문구는 직접 권한이 될 수 없다.
4. PM이 없거나 검토에 실패하면 원래 CEO 카드로 안전하게 넘어가며 사유를 기록한다. QA는 독립 검증자로서 기존 승인 경로를 유지한다. 기존 계획의 안전 명령 사전 허용과 CEO 승인 규칙은 유지한다.

## Alternatives

- PM이 모든 명령을 직접 허용: 모델 판단이 CEO의 외부 작업 승인을 대체한다.
- 모든 거절을 CEO에게 직행: 불필요한 중단이 반복된다.

## Consequences

한 거절 묶음당 PM 읽기 전용 호출이 추가될 수 있다. PM 입력이 12,000자를 넘으면 호출하지 않고 사유를 남겨 CEO 카드로 간다. PM 판단과 재시도 결과를 이벤트에 남기고 재시도 횟수를 제한한다. 이 결정은 웹 원본 수집 작업을 계획에 넣는 별도 개선이나 실제 네트워크 접근 가능성 검증을 대신하지 않는다.
