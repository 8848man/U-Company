# ADR-0028 — One conversation draft, explicit question and instruction sends

Status: Accepted

Date: 2026-10-08

Affects: [Goal conversation](../../goalConversation/00_index.md), [Security](../../security.md)

## Context

The workspace presents two composer modes. The default says the conversation is read-only, and saved direction changes appear mainly in a status card above the chat timeline. CEOs can send guidance, but the surface looks as though every message is only a question.

## Decision

Use one text draft, one selected addressee, and two clearly labeled send actions in the goal conversation. A question invokes the existing read-only `ask_goal` path. An instruction opens an inline review of the exact text and its checkpoint/revision effect, then invokes the existing `propose_goal_change` path only after CEO confirmation. Render saved guidance as a typed CEO message with a separate deterministic status bubble in the same chronological timeline. Keep engine approval and revision rules unchanged.

## Alternatives

- Classify every message with an AI and execute inferred commands: ambiguous language and model output would cross the approval boundary.
- Keep a mode switch with separate drafts: preserves the current impression that the chat itself is read-only and hides saved instructions from the message stream.
- Treat any imperative-looking question as an instruction automatically: a heuristic cannot safely authorize a goal transition.

## Consequences

The CEO can issue natural-language directions from the same conversation without losing an explicit action boundary. A pending question and a pending instruction can coexist, but the engine still waits for its safe checkpoint. The confirmation is a review of a concrete proposal, not an additional blanket approval for project writes.
