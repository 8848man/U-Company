# ADR-0023 — Recheck project mode on explicit selection

Status: Accepted

Date: 2026-10-08

Affects: [Product](../../product.md), [Security](../../security.md), [Architecture](../../architecture.md)

Context: Ordinary-folder tasks integrate declared file deltas and omit `.git` metadata. A model task that only runs `git init` or commits cannot convert the registered project and ends with no file changes. Even after external setup, selecting the same registered path kept the old `folder` mode because the registry reused its saved record.

Decision: Keep Git initialization and first commit outside the current AI file-task loop. On explicit selection or switch, re-detect the same canonical folder. Update its stored execution mode if it is now a committed Git root, while preserving project ID and user-set QA preset. Do not initialize Git, stage files, normalize line endings, or commit as a side effect of registration.

Alternatives: Integrate `.git` metadata from task copies; this would violate the file allowlist and conflict with live repository state. Automatically run Git setup when a goal mentions Git; this needs a separate reviewed operation and cannot safely infer what to stage or commit.

Consequences: Users can finish repository setup using Git and reselect the folder without losing project identity. Existing blocked goals do not become completed automatically; a new goal can use Git worktrees after re-detection.
