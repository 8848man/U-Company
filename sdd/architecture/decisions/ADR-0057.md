# ADR-0057 — Keep file-name case, pass earlier results forward, and give the goal conversation the QA record

Status: Accepted (2026-10-26, CEO). Owners: [DM-03 업무·증거](../../domain/DM-03-execution.md), [GC-01](../../goalConversation/GC-01-turns.md), [Security](../../security.md).

Date: 2026-10-26

## Context

A PostGen follow-up pass (2026-10-25) went to the PM twice after QA and then blocked. Its records show three app-side causes besides the command permissions of ADR-0058:

1. The repair prompt listed the approved files in lower case (`readme.md`), the PM copied that name, the teammate saved `readme.md`, and folder integration compared names case-sensitively. It saw a new `readme.md` beside the unchanged `README.md` and stopped with "프로젝트 파일이 작업 중 변경되어", although nothing had changed it.
2. A repair task measured the before/after timings QA asked for, but only in its own result text; the README task of the same round never received them and honestly wrote "미확인", so the same criterion failed again.
3. When the CEO asked in the goal conversation why QA kept sending the work back, the teammate answered that the QA verdict was not in its record: the conversation context carried task titles and status only.

## Decision

1. **Case.** File names keep the case of the approved plan or of the file already in the project. Prompts list the original names; a planned path that matches an existing file or an approved file case-insensitively is rewritten to that name before the plan is saved. Folder integration treats a workspace file whose name differs from a baseline file only by case as the same file (a case-only rename is applied to the original name), so case alone never reads as a conflict.
2. **Earlier results go forward.** A teammate's brief includes, bounded, the result summaries of the goal's completed tasks it depends on and of the earlier tasks in the current repair round, and for a repair the failed criteria with QA's evidence. The QA prompt lists what each repair task of the round reported. All of it is labelled as untrusted teammate output; it is context, never evidence by itself.
3. **Conversation QA record.** Goal conversation prompts (question and message) include the latest per-deliverable QA verdicts with failed criteria and evidence, the rework count, and the block kind and reason, all built from saved records with no extra model call.

## Consequences

- `engine.rs` (`project_case`, plan normalisation, repair prompt names, `worker_brief` context, QA prompt), `platform.rs` (`integrate_folder_copy`), `goal_context.rs` (`review_digest`).
- Prompts grow by at most a few thousand characters per call; the limits are fixed in code.
