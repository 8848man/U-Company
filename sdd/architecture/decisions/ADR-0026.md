# ADR-0026 — Conversation-first goal workspace

Status: Accepted

Date: 2026-10-08

Affects: [Goal conversation](../../goalConversation/00_index.md), [Information density](../../content-density.md)

## Context

The goal workspace presents status facts, graphs, task lists, recovery instructions, guidance, and a composer as successive large sections. A user who wants to talk to a teammate or handle a blocked goal must scan many competing controls before finding where to write.

## Decision

Keep one goal workspace and the existing saved conversation/engine commands. Make the chat timeline and bottom composer its primary structure. Present one state-derived decision card near the conversation, and move supporting operational facts behind one disclosure with a compact summary. Keep read-only questions and CEO direction changes as explicit composer modes; never classify natural-language messages into privileged commands automatically. Retain exact approval and failure evidence with expansion.

## Alternatives

- Make every natural-language message a possible command: intent classification could silently widen file scope or confuse discussion with authorization.
- Split progress and decisions into separate dialogs or tabs: recreates the navigation problem and hides the current next action.
- Remove operational evidence entirely: would weaken the inspectable-work promise and make recovery untrustworthy.

## Consequences

The screen asks for one clear user action at a time while preserving auditability. The presentation changes only; goal turns, guidance, approvals, task history, and token records remain in their existing storage. Manual QA must verify that a long conversation, blocked report, and approval scope remain reachable by keyboard in a small window.
