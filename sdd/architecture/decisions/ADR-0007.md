# ADR-0007 — Execute Windows npm agent entry points directly

Status: Accepted (2026-10-01)

## Context

Windows npm installs create `.cmd` launchers. Rust `Command` invokes batch files through `cmd.exe`; a CEO goal can contain characters that cannot be safely escaped for batch arguments. A `--version` probe passed, but a long natural-language goal failed with `batch file arguments are invalid`. Claude's wrapper calls a package-native `claude.exe`; Codex's wrapper calls a package JavaScript entry point through Node.

## Decision

The built-in runtime resolves known npm wrappers to those package entry points before passing any goal text. It does not pass untrusted goals through batch files or construct a shell command. Missing entry points produce a clear connection error. Discovery checks Claude login with `auth status`, and refresh updates the matching saved connection. Generic custom wrappers remain outside this built-in resolution and must use a native executable or an adapter that accepts literal arguments safely.

## Alternatives

Quoting and escaping for `cmd.exe` was rejected because some characters cannot be represented safely for batch execution. Writing the goal into a temporary batch file was rejected because it increases injection risk and creates sensitive temporary content. Requiring every user to replace npm installations was rejected because the package-native entry points already work.
