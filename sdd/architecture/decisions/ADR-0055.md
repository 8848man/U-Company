# ADR-0055 — Repeated work in one visible goal conversation

Status: Accepted (2026-10-25, CEO). Owners: [GC-01](../../goalConversation/GC-01-turns.md), [GC-02](../../goalConversation/GC-02-guidance.md), [DM-02](../../domain/DM-02-goal.md).

Date: 2026-10-25

## Context

The CEO wants to keep instructing the team from an existing goal conversation, including after the first plan passes QA. The current backend refuses a direction after `completed` and asks for a separate new goal. ADR-0051 already joins linked versions into one visible conversation, while separate Goal IDs keep approvals, tasks and QA evidence attributable to their own plan.

## Decision

1. A clear post-completion work instruction is classified separately from a question or a request to resume unfinished work. It records the CEO's exact text and creates one linked next version in the same visible conversation.
2. The completed version remains completed. The next version goes through analysis, plan, explicit file-scope approval, isolated execution and QA. The previous approval never authorizes its file changes. Engine-verified unchanged work may be reused under the existing continuation rule.
3. A completed version's follow-up route is distinct from the in-flight direction route, which must still race atomically with completion. Duplicate unresolved guidance or an already linked version is refused.
4. The UI says that further work can be requested in the current input and presents each plan pass with its own result and approval evidence. It never calls a completed provider session resumed.

## Alternatives

- Reopen the completed Goal row and reuse its task and approval IDs: rejected because completion, evidence and approval scope would become ambiguous.
- Require a new visible goal conversation: rejected because it forces the CEO to restate context and conflicts with the one-conversation decision in ADR-0051.

## Consequences

The storage and engine add a post-completion follow-up path. The v3 conversation uses the existing version chain, so older shells may still show linked versions separately. A conversation-context summary policy is a separate decision; no threshold or model-generated summary is introduced by this ADR.
