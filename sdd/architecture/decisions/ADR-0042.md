# ADR-0042 — UI/UX philosophy: three depths, summary first, control always visible

Status: Accepted (2026-10-11, CEO). Canonical rules: [UI/UX 구현 철학](../../ux-principles.md). Refines the long-text rule of the [정보 밀도 UI 정책](../../content-density.md).

## Context

The 업무 tab and the Office Meeting dialog show provider-facing text as-is: the CEO's prompt as card titles, full approval reasons, task instructions and results, and in the decision package every unresolved critique with IDs and responses, next to recommendations, claims, alternatives and provenance on one screen. The CEO's goal for the product is that a non-specialist, even a primary-school child, understands the first screen, while the user can still see and control what was approved, sent and argued.

Until now the information-density policy said that expanding long text must reveal the original "without rewriting or AI summarization". Showing a short summary first therefore needs an explicit decision. It must not weaken the security rules that approval scope stays fully inspectable and that model output is untrusted.

## Decision

1. **Three depths.** Every screen shows one depth at a time: 한눈에 (summary, decision, at most five choices with one recommended, control line), 흐름 요약 (one line per process stage and grouped issues), 자세히 (all evidence and originals). The user moves between depths explicitly.
2. **Summary first, original one step away.** Long human-facing text is shown as a summary with `원문 보기` in the same place. A model-written summary is labelled `AI 요약`; a truncated first sentence is labelled `원문 일부`. Originals are never rewritten.
3. **No extra cost for simplicity.** Summaries come from summary fields added to provider calls that already happen (for example the CTO analysis, the meeting chair plan, each meeting stage reply and the evaluation), from deterministic text built from saved facts, or from truncation. No call, transmission or approval exists only to summarise.
4. **Summaries are untrusted display text.** Bounded length, plain text, never used for state, approval, completion or assignment. Approval and security confirmation dialogs keep showing the full scope.
5. **Control stays visible.** What the user decided (approved plan or scope, data sent, calls used, team) is one line on the first depth. Pending decisions are never collapsed.
6. **Plain words** on depths 1–2. Internal terms, IDs and hashes move to depth 3. Stored values and code names do not change.

## Alternatives

- **Keep the original-only rule and rely on collapsing:** rejected. Collapsed originals are still unreadable for the target user, and the first screen does not say what to do.
- **Separate summarisation calls:** rejected for now. They would add provider calls and data transmission outside the approved meeting plan, and cost.
- **Hide raw records entirely:** rejected. Control and auditability require every original to be recoverable.

## Consequences

- Provider schemas gain optional summary fields. These are introduced per feature with their owning spec (for meetings, ME-01/ME-02 and the planned 3rd improvement). Older records fall back to `원문 일부`.
- The information-density policy's tall-content rule is amended: AI summaries may precede the original if labelled, and the original stays one action away.
- Every new or changed screen is checked against the checklist in the philosophy document.
