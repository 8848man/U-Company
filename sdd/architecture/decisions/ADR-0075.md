# ADR-0075 — U-Company를 볼트 MCP 클라이언트로 연결한다

Status: Accepted (2026-11-16). 2026-11-14 Claude가 Proposed로 작성했다. 접근 범위(읽기 + `raw/inbox` 제출)와 제출 전 CEO 승인은 CEO 결정이다(볼트 utopia-company 결정 로그 2026-11-14, U1 결정). 결정 5번(사서 처리 요청은 제출 뒤 별도 버튼)은 2026-11-14 리뷰를 거쳐 CEO가 2026-11-16에 승인했다. 구현은 볼트 과제 U2이며 v4 데스크톱 QA 통과 뒤 시작한다.
Date: 2026-11-14 (Accepted 2026-11-16)

Owners: [AI-05](../../aiIntegration/AI-05-vault.md), [Security](../../security.md), [UF-03](../../userFlow/UF-03-goal.md), [Validation](../../validation.md).

## 맥락

사용자는 여러 프로젝트의 결정·과제를 Obsidian 볼트에 모은다. 볼트의 ADR-007은 볼트를 공용 장부로 두고, 실행 도구(Claude Code, Codex, U-Company)가 자기 몫(`#claude`·`#codex`·`#ucompany`)의 과제를 가져가고 끝나면 요약을 제출하게 했다. U-Company는 엔진으로 합치지 않고 볼트 MCP를 쓰는 실행 도구 하나로 연결한다. 엔진 병합은 v4 QA·제품 방향, U-Company 효용 기록, 세션 열기 병목이 모두 확인되면 다시 검토한다.

볼트 MCP 서버(`obsidian-vault`, 계약 v1.1.0)는 같은 PC의 stdio 서버다. `projects/`·`wiki/`만 읽고, 쓰기는 `raw/inbox/`에 새 파일을 만드는 것뿐이며, 사서 처리 요청은 inbox 파일 하나에 대한 작업만 만든다. 볼트 페이지는 사서만 고친다. 앱 쪽 보안 명세는 MCP 결과를 신뢰하지 않는 자료로 보고, 프로젝트 밖 접근·새 실행 파일 등록·외부 전송에 CEO 승인을 요구한다.

## 결정

1. **연결.** 볼트 연결은 앱 전역에 하나다. CEO가 설정에서 실행 파일과 인자 목록(예: `python`, `-X`, `utf8`, `<볼트>/mcp/server/server.py`)을 입력한다. 처음 실행하기 전에 실행 파일, 인자, 작업 폴더를 "앱 사용자 권한으로 실행되는 코드"로 보여 주고 CEO의 확인을 받는다. 셸 없이 고정 인자로 실행한다. 작업 폴더는 앱 데이터 폴더다(볼트 폴더나 선택 프로젝트가 아니다). 사용자 환경에서 `VAULT_MCP_`로 시작하는 변수는 넘기지 않는다. 앱 동작 한 번(조회, 제출, 처리 요청, 상태 조회)마다 서버 프로세스를 하나 띄우고, 제한 시간이 지나면 프로세스 트리를 종료한다. `initialize`에서 서버 이름 `obsidian-vault`와 계약 MAJOR 1을 확인하고, `tools/list`에 필요한 도구(`vault_list_projects`, `vault_list_tasks`, `vault_submit_summary`, `vault_request_ingest`, `vault_get_job`)가 있을 때만 기능을 켠다. 맞지 않으면 기능을 끄고 그 이유를 보여 준다.
2. **프로젝트 대응.** 프로젝트마다 CEO가 볼트 슬러그를 고른다. 앱은 `vault_list_projects`로 후보를 보여 주고, 폴더 이름과 맞는 슬러그를 먼저 제안한다. 대응은 앱 SQLite에만 저장하고 프로젝트 파일에 쓰지 않는다. `PROJECT_NOT_FOUND`가 오면 볼트 프로젝트를 만들거나 합치지 않고 다시 고르게 한다.
3. **과제 가져오기(읽기).** 목표 입력 화면의 `볼트 과제에서 가져오기`를 누를 때만 `vault_list_tasks(project=<슬러그>, agent="ucompany")`를 부른다. 앱 시작 때 조회하거나 주기적으로 조회하지 않는다. 목록에는 `#ucompany` 과제와 태그 없는 공용 과제만 오며, 공용 과제는 `공용`으로 표시한다. 함께 오는 `procedure`는 접힌 참고문으로만 보여 준다. CEO가 과제 하나를 고르면 그 문장이 목표 입력란에 들어가고, CEO는 고친 뒤 보낸다. 보내기는 일반 목표 전송이며, 그 뒤 CTO 분석·PM 계획·계획 승인·QA는 그대로다. 과제 원문, 줄 번호, 출처 날짜는 목표 기록의 `vaultTask`로 저장한다. 제공자에 가는 것은 CEO가 보낸 목표 문장뿐이다. `procedure`와 다른 볼트 내용은 제공자에 보내지 않는다.
4. **요약 제출(쓰기).** 목표가 `completed` 또는 `cancelled`가 되면 목표 대화 끝에 `볼트에 기록` 카드를 보여 준다. 막힌 목표에서는 CEO가 목표 메뉴에서 같은 카드를 연다. 자동으로 제출하지 않는다. 앱은 AI를 부르지 않고 저장된 기록으로 볼트 세션 요약 양식(볼트 AGENTS.md 3장)을 만든다. frontmatter는 `date`, `source: u-company`, `model`(참여 연결 목록), `project`(대응 슬러그), `type: dev`, `status`(목표 상태에서 `done | in-progress | blocked`)다. 본문은 목표, 결정 사항(CEO 승인·방향 변경), 산출물(통합된 프로젝트 상대 경로와 QA 판정), 남은 과제, 이슈, 작업 방식 회고로 이뤄진다. `vaultTask`가 있으면 `## 볼트 과제 갱신`에 과제 원문과 CEO가 고른 결과(`완료 | 변경 | 불필요 | 사람 몫`)를 넣는다. 원시 프롬프트, 명령 문자열, 제공자 stdout, 자격 증명, 프로젝트 밖 절대 경로는 넣지 않는다. CEO는 제출될 전문 그대로를 보고 고칠 수 있으며, `볼트에 제출`을 눌러야 `vault_submit_summary`가 불린다. `SENSITIVE_CONTENT`가 오면 알려 준 줄 번호를 표시하고 CEO가 고친 뒤 다시 누르게 한다.
5. **사서 처리 요청.** (CEO 승인 2026-11-16.) 제출에 성공하면 같은 카드에 `사서 처리 요청` 버튼을 보여 준다. 누를 때만 `vault_request_ingest`를 부른다. 처리 요청은 볼트를 앱이 직접 쓰는 일이 아니라 사서 작업을 만드는 일이고, 사서 실행 한 번이 사용량을 쓰기 때문이다. 그 뒤 카드가 보이는 동안 5초 간격으로 `vault_get_job`을 부르고, 10분이 지나면 조회를 멈추고 `다시 확인` 버튼을 둔다. `completed`면 갱신된 페이지와 커밋을, `needs_review`면 사유를 그대로 보여 주고 끝낸다. 앱은 `retry: true`를 보내지 않는다. `failed`면 코드와 메시지를 보여 주고, `retryable`일 때만 CEO가 다시 요청할 수 있다.
6. **기록과 재시작.** 제출 결과(`file`, `sha256`), 작업 ID, 마지막 상태를 목표별로 SQLite에 저장한다. 재시작 뒤 제출이나 처리 요청을 자동으로 반복하지 않는다. 끝나지 않은 작업은 카드를 열 때만 상태를 다시 조회한다.
7. **실패 격리.** 볼트 연결이 없거나 실패해도 목표 생성·실행·완료는 막히지 않는다. 볼트 오류 문구와 결과 문장은 표시용 자료일 뿐이며 앱 동작을 일으키지 않는다.
8. **하지 않는 것.** 볼트 파일을 직접 읽거나 쓰지 않는다. 과제 체크 표시를 바꾸지 않는다(사서 몫). 볼트 검색·페이지 내용을 계획 맥락에 자동으로 넣지 않는다. `#claude`·`#codex`·`#사람` 과제를 가져오지 않는다. 앱이 사서 역할을 대신하거나 헤드리스 사서를 직접 실행하지 않는다.

## 검토한 대안

- 볼트 폴더를 파일 시스템으로 직접 읽고 쓰기 — 서버가 필요 없다 / 사서 단일 쓰기 원칙(볼트 ADR-001), 서버의 민감 정보 검사와 경로 검사를 건너뛰고 페이지 형식이 바뀌면 깨진다 — 버림.
- 목표가 끝나면 자동 제출 — 손이 덜 간다 / 앱이 만든 기록을 사람이 보지 않고 넘긴다 — CEO 결정으로 버림.
- AI가 요약을 쓰기 — 문장이 낫다 / 제공자 전송 승인이 하나 더 필요하고 기록에 없는 내용이 들어갈 수 있다 — 나중에 별도 결정.
- 제출 뒤 처리 요청을 자동으로 하기 — 볼트 USAGE_PROMPT의 기본값이다 / CEO 결정의 범위가 "읽기 + inbox 제출"이고 사서 실행이 사용량을 쓴다 — 버튼으로 둠.
- 볼트 내용을 계획 맥락으로 자동 전달 — 계획이 맥락을 더 안다 / 볼트의 다른 프로젝트 기록까지 제공자에 갈 수 있다 — 버림. 필요하면 CEO가 참고 자료([ADR-0049](ADR-0049.md))로 붙인다.

## 결과

- 좋아지는 것: 다른 실행 도구와 같은 흐름(배정 → 가져가기 → 제출)으로 U-Company 목표를 볼트에 남긴다. 볼트 과제 U3(실사용 비교)의 근거 기록이 생긴다. 볼트가 없어도 앱은 그대로 동작한다.
- 감수하는 것: 볼트 MCP 서버를 실행할 Python이 필요하다. 볼트는 하나만 연결한다. 결정적 요약은 문장이 딱딱하다. 지금 볼트에 `#ucompany` 과제가 없으므로 가져오기는 U3 전까지 공용 과제로만 시험된다.
- 이후: U2 구현(`#codex`) → U3 검증. 볼트 MCP 계약의 MAJOR가 바뀌면 이 ADR을 대체한다.

## 관계

- `implements`: 볼트 ADR-007(실행 도구는 볼트에 느슨하게 연결), 볼트 ADR-006(다른 프로젝트는 로컬 MCP로 볼트를 조회하고 요약을 제출).
- `constrained_by`: [Security](../../security.md), [ADR-0049](ADR-0049.md).
