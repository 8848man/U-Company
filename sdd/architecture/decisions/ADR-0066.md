# ADR-0066 — 목표 대화와 설정의 명령 자동 승인 모드

Status: Accepted (2026-11-07, CEO). Owners: [Security](../../security.md), [DM-03](../../domain/DM-03-execution.md), [UF-05](../../userFlow/UF-05-approval.md), [AI-03](../../aiIntegration/AI-03-adapter.md).

Date: 2026-11-07

## Context

작업마다 `grep`, `echo`, 검사 명령을 승인하는 중단이 잦다. 사용자는 채팅과 설정에서 오토 모드, 풀 오토 모드를 고르길 원했다. 풀 오토의 범위는 삭제·이동까지이며 웹 접속, 패키지 설치, Git push, 배포는 계속 별도 승인하기로 결정했다. Windows의 Claude 명령은 사용자 권한으로 실행되고 기존 접두어 규칙은 뒤에 인자를 더 받을 수 있으므로, 그 규칙을 자동 승인에 재사용하면 설정 범위보다 넓어진다.

## Decision

1. `수동`, `오토`, `풀 오토` 세 모드를 둔다. 설정은 선택 프로젝트의 기본값이고, 목표 채팅은 한 목표 대화의 재정의다. 대화가 재정의하지 않으면 프로젝트 기본값을 따른다. 변경은 이미 실행 중인 호출을 바꾸지 않고 다음 권한 판단부터 적용된다.
2. 오토는 앱이 정해 둔 단순 로컬 조회 명령만 자동 허용한다. 프로젝트 코드·스크립트를 실행하는 시험과 빌드는 내부에서 삭제·외부 접속할 수 있으므로 기존 PM/CEO 경로로 간다. 알 수 없는 명령, 셸 확장·명령 치환·리다이렉션·외부 경로가 섞인 명령도 기존 경로로 간다.
3. 풀 오토는 오토 범위에 더해, Dev 격리 작업 폴더 안에서 계획에 선언된 파일의 단순 삭제·이동만 허용한다. 경로는 상대 경로·기존 승인 파일로 검증하고 심볼릭 링크, 옵션·글롭·셸 연산자를 거부한다. QA와 계획·분석 호출에는 삭제·이동 자동 허용을 적용하지 않는다.
4. 자동 허용은 거절된 정확한 호출에만 적용하고 해당 업무 호출에서만 유효하다. 대화 전체의 접두어 권한으로 저장하지 않는다. 모드를 낮추면 남은 자동 권한은 다음 호출부터 무효다. CEO가 개별 승인한 기존 명령 권한은 별도 기록으로 유지된다.
5. 웹 접속·패키지 설치·push·배포·프로젝트 밖 파일 작업·권한 변경·새 파일 범위는 두 자동 모드 모두 별도 CEO 승인이다. 프로젝트 쓰기 계획 승인, 외부 전송 승인, 파일 통합 검사는 계속 필요하다. 자동 분류가 불확실하면 기존 PM/CEO 경로로 간다.

## Consequences

모드 선택은 제품 권한 정책이며 운영체제 샌드박스가 아니다. 제공자나 프로젝트의 전역 권한 설정이 앱보다 넓으면 앱이 실행 전 모든 호출을 통제한다고 주장할 수 없다. 실제 Windows 제공자 검증이 필요하다.
