# ADR-0017 — Probe saved CLI paths and separate team settings

Status: Accepted

Date: 2026-10-05

Affects: [Integrations](../../aiIntegration/00_index.md), [Product](../../product.md)

Context: Automatic discovery refreshed a registered CLI only when its path exactly matched the newly discovered path. A saved Claude connection could retain an old login state even though another path was probed. Office mixed team-wide roster actions into an individual character panel, making bulk changes tedious and hiding controls hard to locate.

Decision: Probe each registered built-in CLI at its saved path and expose an explicit recheck with the checked path and safe result. Keep a false Claude `loggedIn` report distinct from a probe failure. Put team-wide add, bulk connection assignment, and hide/restore controls in an Office team settings view. Bulk assignment is one SQLite transaction for the selected active members and clears their model overrides. Individual character panels retain individual fields only.

Alternatives: Copy the PATH-discovered state onto every saved connection, which can misreport another executable's credentials; treat a failed auth probe as logged in, which can launch work with invalid credentials; loop over per-member UI saves, which can leave a partially changed team.

Consequences: A user logged in through a different Claude installation must check or register the executable they intend to use. A false CLI report requires login in that executable's user context. Team-wide changes become reviewable and atomic; past usage records remain unchanged.
