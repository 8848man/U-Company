# ADR-0029 — AI-routed goal conversation with automatic safe continuation

Status: Accepted

Date: 2026-10-08

Affects: [Goal conversation](../../goalConversation/00_index.md), [Security](../../security.md)

## Context

ADR-0028's two send actions still require the CEO to classify every message. The intended interaction is one conversational send: a connected teammate understands a question or instruction and takes the next state-safe step.

## Decision

Use a read-only model call to classify each CEO message as discussion, actionable goal direction, guarded start/retry, or ambiguity. Persist the original message and routing result. Discussion returns an answer; ambiguity asks a clarifying question. A start/retry request uses only the existing state-validating engine command. An actionable direction records the exact CEO text through the existing guidance transaction, pauses at the safe checkpoint, creates a linked goal with the old intent, exact CEO instruction, and bounded prior conversation marked as non-authoritative context, and starts CTO/PM re-planning. Resume this continuation after app restart. The model cannot approve project writes, change projects, or skip the engine's validation. Project-write approval remains an explicit CEO decision.

This supersedes ADR-0028's explicit question/instruction send choice. It preserves ADR-0028's chronological conversation and typed workflow status.

## Alternatives

- Keep two send actions: requires the CEO to operate the workflow rather than converse.
- Route by keywords alone: natural Korean and mixed requests make this unreliable.
- Let the model execute arbitrary tool calls: crosses the project's scoped approval and trust boundaries.

## Consequences

One message may begin a new planning loop without another CEO click. Incorrect or ambiguous interpretation must be visible and recoverable through a later instruction. A pending model call and safe checkpoint remain observable. New file changes still stop at scoped approval.
