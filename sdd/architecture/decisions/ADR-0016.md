# ADR-0016 — Accept ordinary folders with isolated copies

Status: Accepted

Date: 2026-10-05

Affects: [Product](../../product.md), [Domain](../../domain/00_index.md), [Architecture](../../architecture.md), [Security](../../security.md)

Context: ADR-0003 and ADR-0006 required Git for registration and writing. Users need to select an existing folder without creating or linking a repository. Automatic Git initialization also modifies a folder before the user approves an AI write.

Decision: Register any existing canonical folder unchanged. Persist whether it was a Git repository root at registration; legacy projects remain Git projects. Git roots keep the worktree path. Ordinary folders use bounded isolated copies with saved baselines, declared-file checks, and conflict checks before serialized integration. A folder inside a parent Git repository is an ordinary folder with its own path boundary. No repository is initialized as a side effect of selecting a folder.

Alternatives: Initialize Git in every selected folder, which changes user content and still requires Git; write directly to a shared folder, which prevents parallel isolation and reliable conflict checks; reject nonempty ordinary folders, which fails the requested use case.

Consequences: Large or symlink-containing ordinary folders can fail snapshot preparation with an actionable error. Git worktrees retain richer diff handling. Ordinary-folder integration preserves the selected folder's current bytes only if they still match the task baseline. This supersedes ADR-0003's Git requirement and ADR-0006's empty-folder initialization decision; their other decisions remain.
