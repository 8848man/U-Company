# ADR-0054 — Show what approval sets in motion, what a finished goal changed, where goals stop, and how to start

Status: Accepted (2026-10-20, CEO via the completion rounds plan). Owners: [GC-03 작업공간](../../goalConversation/GC-03-workspace.md), [완주율·사용성 개선 라운드](../../completion-usability-rounds.md) R4–R6.

## Context

The 2026-10-20 usability review rated the plan-approval, result and first-run steps lowest for a non-developer CEO: the plan card said nothing about how much work approval starts, a finished goal showed the raw report but not which files changed or how to try them, the app recorded block kinds but never showed which stop is common, and an empty home gave no path to a first successful goal.

## Decision

1. **Plan card estimate (R4).** The card shows how many AI calls approval starts (open tasks + reviewers + two SDD steps when the approval carries the SDD note), a token figure from this project's own average per call when it has at least three records, and how many QA rework rounds may follow. It is computed from saved records in the screen; it is never called a cost or a quota.
2. **Plain rework wording (R4).** The QA rework limit reads as "QA에 떨어지면 다시 고치는 최대 횟수"; the used-up block reads "다시 고치기 횟수를 다 씀".
3. **Finished-goal summary (R5).** `get_goal_result` returns the files the goal's completed tasks were approved to change (and whether each exists now) and plain ways to try them, detected from files that exist: `index.html`, `package.json` scripts, `*.test.js`, `Cargo.toml`. `open_project_folder` opens the saved project path in the system file manager. Read-only; no AI call.
4. **Block records (R5).** Every engine block and every restart interruption also saves a `goal_block` record (goal, project, kind, time). `get_block_stats` counts them by kind for a project; v3 settings › 프로젝트 shows the five most common with plain labels.
5. **First run (R6).** The v3 home without a goal shows a readiness check (project folder, Git, an AI connection for every teammate) with one action per missing item, and `샘플 앱 만들어 보기`, which fills the composer with a prepared to-do app goal; the CEO still sends it.

## Alternatives

- **Ask an AI to summarize results or estimate effort:** costs tokens, can be wrong, and the counts are already in saved records.
- **Derive block statistics from the event log:** the snapshot carries a recent window only, so history would be incomplete.

## Consequences

- `src/planEstimate.ts`, `src/GoalChat.tsx` (estimate, result summary), `src-tauri/src/goal_result.rs`, `engine.rs` and `storage.rs` (block records), three commands (protocol 39), `v3/src/BlockStats.tsx`, v3 home first-run section, [샘플 앱 흐름 점검](../../../qa/SAMPLE-APP-FLOW.md).
- v1/v2 keep their screens; only shared wording changes there.
