# ADR-0034 — Saved-state attention signals with a native notification adapter

Status: Accepted (2026-10-09)

## Context

V2 needs optional sound and Windows notifications for pending CEO approvals and blocked goals. The existing app has in-app toasts but no OS delivery. The toolchain is Rust 1.89; current Tauri notification releases require Rust 1.90, and Windows native notifications require an installed app identity. The original launcher is a development executable with bundling disabled.

## Decision

Use a frontend transition detector over successful persisted snapshots, shared by any v2 screen. A narrow delivery adapter plays a Web Audio cue and calls the Tauri notification plugin. Pin a plugin release compatible with Rust 1.89, and provide a v2 installer build configuration rather than changing the original development launcher. Preferences are local UI settings, default off, and enabling OS delivery is the only permission-request path. First snapshot is a baseline, not a replay. Approval decisions remain backend commands through the existing scoped dialog.

## Alternatives

- Notify directly from every Rust event: catches events when no window is open, but would need process/background lifecycle, preference persistence, and repeated-event handling at many write sites.
- Launch PowerShell/WinRT commands: avoids a plugin dependency but creates a broad process boundary for a UI feature and complicates platform portability.
- Use browser `Notification`: does not provide reliable installed Windows app identity in the current Tauri development flow.
- Upgrade all Rust/Tauri packages now: larger migration than this feature requires.

## Consequences

Notifications are emitted only while the v2 app window is running and observing state changes. On startup, pending work remains visible in the app and open-work launcher without a burst of OS messages. OS delivery must be tested from an installed Windows build; the dev launcher is suitable for sound and in-app state checks only. The adapter must degrade without disrupting goal execution if permission or native delivery fails. The Cargo package sets `default-run = "ai-organization-os"` because Tauri bundling otherwise selected the unrelated `provider-harness` binary.
