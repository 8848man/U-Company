# ADR-0058 — Ask the CEO for command permissions a teammate needs, inside the goal conversation

Status: Accepted (2026-10-26, CEO). Owners: [Security](../../security.md), [AI-03 어댑터](../../aiIntegration/AI-03-adapter.md), [DM-03 업무·증거](../../domain/DM-03-execution.md).

Date: 2026-10-26

## Context

Claude Code runs writing tasks with `--permission-mode acceptEdits`, which edits files but denies other shell commands when nobody can answer a prompt. In the PostGen pass every Claude call (Developer B, QA) reported that tests and benchmarks were blocked, so acceptance criteria that need a run could not be met and the goal went back to the PM twice. Some installations use only Claude, so routing such work to Codex is not an answer.

A verification on 2026-10-26 (Claude Code 2.1.310) showed: in `acceptEdits` and `dontAsk`, a denied call is reported as a `permission_denied` stream event and in the final result's `permission_denials` (`tool_name`, `tool_input.command`); `--resume <session> --allowedTools "Bash(cmd *)"` continues the same session and the approved command then runs; Claude often chains commands (`node --test; echo …`), so exact-text rules miss the next try; in `plan` mode Claude does not even attempt a command and nothing is recorded. On native Windows Claude Code runs shell commands without a sandbox. Codex in `workspace-write` already runs local commands and reports no structured denial.

## Decision

1. **Grants belong to one goal conversation.** Approved command rules are saved on the conversation (the first goal of the version chain) and apply to every pass, task, repair and QA call in it, never to other goals or projects.
2. **Ask early.** A planned task may list the commands it will run (`commands`). The plan card shows them as rules; approving the plan grants the grantable ones. Rules that are not grantable at once are listed and asked about when they are needed.
3. **Ask when blocked.** After a call ends, the engine reads the provider's structured denials. Denied commands become proposed rules (split at `;`, `&&`, `||`, `|`, then the command name and first argument with ` *`). The task does not go to integration: the goal waits on a `command_permission` approval card that lists each rule. `모두 승인` grants every grantable rule; a not-grantable rule has its own button. `승인하지 않음` lets the task continue as it is and QA judge it. After approval the engine resumes the same provider session in the same isolated folder with the grants, asking it to run what was blocked, at most twice per task.
4. **Not grantable at once.** A bare tool (`Bash`), a wildcard-only rule, and commands that delete, move outside, publish, push, fetch from the network, change permissions or run another shell (`rm`, `del`, `rmdir`, `curl`, `wget`, `git push`, `npm publish`, `ssh`, `powershell`, `cmd`, `sudo`, …) are never included in `모두 승인`; each needs its own button, and the card says commands run with the user's own rights on Windows.
5. **Read-only roles run approved commands in a copy.** QA calls on Claude use `dontAsk` with the file-writing tools disallowed and the conversation's grants allowed, in an isolated copy of the integrated project, so approved commands can run tests without touching the project. Meetings keep the enforced read-only `plan` profile. Analysis and planning calls stay read-only as before.
6. **Other providers.** Claude is supported. Codex keeps `workspace-write` (no structured denials; unchanged). Other CLIs are unchanged. The external adapter protocol may report `permissionDenials` and receives `allowedCommands`; unknown fields stay ignored.

## Alternatives

- **Pause inside the call (`--permission-prompt-tool`)**: keeps a process open for up to a day and is lost on restart.
- **Route command work to Codex**: impossible in Claude-only setups.
- **Grant for the project or the whole app**: wider than the CEO asked.

## Consequences

- `provider.rs` (Claude arguments, denial parsing), `runtime.rs` (plugin fields), `engine.rs` (grants, plan commands, permission approval, resume), `permissions.rs` (rule derivation and classification), `model.rs`, `lib.rs` (decision command), v3 cards.
- QA calls on Claude need a copy of the project per review.
- Requires a Claude Code version that knows `dontAsk`; an older CLI fails the QA call with its own error, shown as a provider failure.
