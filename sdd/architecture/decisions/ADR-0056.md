# ADR-0056 — Structured context at a goal work-pass boundary

Status: Accepted (2026-10-25, CEO). Owners: [GC-01](../../goalConversation/GC-01-turns.md), [GC-02](../../goalConversation/GC-02-guidance.md), [DM-02](../../domain/DM-02-goal.md).

Date: 2026-10-25

## Context

ADR-0055 lets the CEO request another work pass in one visible conversation. The initial implementation copied the previous goal intent and two chat turns into each linked goal intent. This grows on every pass and eventually reaches the 12,000-character goal limit. Repeated model replies also cost context without necessarily preserving decisions or evidence.

## Decision

1. At each linked work-pass boundary, build a structured handoff from persisted goal, CEO guidance, task, QA/report, and conversation records. Keep the original CEO goal and latest CEO instruction identifiable. Include prior pass status, completed file scope, and bounded recent decisions/evidence. The summary is context, never a new approval, a QA verdict, or proof of task reuse.
2. The handoff is deterministic and does not make a separate model call. The exact original turns, guidance, approvals, tasks, QA and reports remain in storage and in the visible version chain. Omitted or shortened context is labelled, not silently invented.
3. Estimate accumulated conversation text at four characters per token. At 8,000 estimated tokens or more, carry only the structured handoff into the next work pass; below that threshold, at most two short recent exchanges may accompany it. Always build the handoff at the boundary, so long prior goal intents are not recursively copied.
4. The next pass receives its own goal ID, plan and approval under ADR-0055. The app keeps the 12,000-character intent limit and reports when even the exact latest instruction plus bounded handoff cannot fit. An estimated token count is a budget heuristic, not a provider-reported token count.

## Consequences

The planner sees a smaller, labelled history. It must inspect the saved records or project files when a short excerpt is insufficient. The user can inspect the original records in the same visible conversation. No model-generated summary can erase CEO text or authorize a write.
