# ADR-0068 — 승인된 재수정 파일의 재사용 소유권 전환

Status: Accepted (engine implemented; engine tests pass on Windows 2026-11-10; runtime QA pending)

Date: 2026-11-01

Affects: [Security](../../security.md), [DM-03](../../domain/DM-03-execution.md), [DM-05](../../domain/DM-05-recovery.md), [Validation](../../validation.md)

**2026-11-10 amendment ([WLG-077](../../../worklog/milestones/WLG-077.md)):**

- A QA repair asks the CEO with a `project_write_scope` card only when it adds files or touches a file reused or replaced from an earlier goal. A repair that stays inside the files of the approved plan is bound to that plan approval (`RepairTaskScope.approval_id` = the `project_write` approval) and starts without a card, as in [ADR-0053](ADR-0053.md).
- A conflict found while checking the earlier goal's evidence is saved on the goal the CEO is working on, so the new goal's screen shows it.
- For a file Git does not track yet, the conflict shows its current text instead of an empty diff.
- An outside edit made during isolated work is blocked as `출처 불명 변경` before the patch is applied (decision 5), not later as a patch conflict.

## Context

[ADR-0027](ADR-0027.md)은 완료·통합된 이전 작업의 파일 해시와 의존성이 현재 프로젝트와 일치하고 새 작업의 소유 파일과 겹치지 않을 때만 재사용한다. 현재 엔진의 `validate_continuation`은 재사용 작업과 새 계획 작업의 파일 중복을 거부하고, QA 직전에 이전 통합 해시를 다시 검사한다. 따라서 승인된 새 작업이 같은 파일을 수정한 경우에도 이전 해시를 재사용 판정에 남겨 두면 QA가 `재사용 파일이 통합 이후 변경되었습니다`로 차단될 수 있다. 그 오류 문구만으로 변경의 승인 여부나 실제 경로를 알 수는 없다.

## Decision

1. 계획 승인 카드 생성 전과 재작업 승인 카드 생성 전, 정규화한 프로젝트 상대 경로를 기준으로 재사용 후보의 파일, 의존 작업의 파일, 이번 계획·재작업의 선언 파일과 승인 범위를 대조한다. 대소문자만 다른 이름과 동일한 실제 대상도 중복으로 취급한다. 중복과 각 파일의 이전 작업 ID, 통합 해시, 새 작업 ID, 제안 변경, 필요한 승인 범위를 카드에 표시한다. 이 검사와 카드 승인은 별개다.
2. 겹친 파일을 수정하는 새 작업은 기존 재사용 작업 ID를 그대로 유지할 수 없다. 계획을 고쳐 해당 작업의 재사용 지정을 해제하고, 해당 파일을 이번 차수의 명시적 작업·승인 범위에 넣어 CEO의 새 프로젝트 쓰기 승인을 받아야 한다. 한 이전 작업의 일부 파일만 수정한다면 그 작업 전체를 자동 재사용 완료로 표시하지 않는다. 수정하지 않는 파일과 선행 의존성의 기존 통합 증거는 계속 검사한다. 이미 승인된 범위 안의 재작업에는 해당 범위의 유효한 승인이 필요하고, 범위 밖 파일은 기존 [ADR-0053](ADR-0053.md)의 별도 범위 승인 또는 새 목표 버전 계획을 따른다. 기존 승인을 암묵적으로 넓히지 않는다.
3. 승인된 작업이 실제 수정 내용을 통합할 때 파일별로 이전 재사용 판정을 종료한다. 이 파일은 이번 차수의 산출물로 전환하여 새 목표·작업 ID, 승인 ID와 승인된 파일 범위, 통합 이벤트·시각, 이전/새 SHA-256, 실제 변경 차이, 의존 작업·원래 출처를 연결해 저장한다. 새 해시는 통합된 현재 프로젝트 바이트에서 계산한다. 통합 실패, 빈 변경 또는 증거 누락은 전환 완료가 아니다. 이전 통합 증거는 이력으로 남긴다.
4. QA 재진입은 전환 파일의 새 작업·승인·통합 증거와 새 현재 해시 및 이번 목표의 수용 기준을 검사한다. 전환되지 않은 재사용 파일과 선행 의존성은 ADR-0027의 기존 증거 및 현재 바이트를 계속 검사한다. 한 파일에 옛 해시와 새 해시를 동시에 완료 조건으로 요구하지 않는다. 이 검증은 독립 QA를 대체하지 않는다.
5. 선언·승인 범위 밖 변경은 `승인 범위 밖 변경`, 이벤트·작업·승인·통합 연결이 확인되지 않는 변경은 `출처 불명 변경`, 해시 불일치는 `재사용 증거 불일치`로 각각 차단한다. 이전/현재 해시, 파일별 diff, 작업·승인·이벤트의 확인된 값과 누락 값을 보여준다. 필요한 조치는 원본 바이트 복구 후 재검사, 정확한 범위의 새 계획·승인 후 재작업, 또는 누락된 로컬 증거 확보 및 재대조 중 해당 경로로 안내한다. 문서나 모델의 설명은 누락된 승인·통합 증거를 대신하지 못한다.

## Alternatives and boundary

이전 해시를 새 내용의 QA 근거로 재사용하거나, 중복을 무조건 허용하는 방식은 출처를 흐리므로 채택하지 않는다. 모든 파일을 다시 실행하는 방식도 ADR-0027의 선택적 재사용을 잃는다. 이 결정은 기존 승인 범위를 확대하지 않는다. 재사용 파일의 자동 수정 권한, 과거 승인 소급 적용, 출처 불명 변경의 자동 수용이 필요하다면 별도 CEO 결정과 Security 변경이 필요하다.

## Consequences

파일별 출처·승인·해시 연결 저장과 계획/재작업/QA 세 경로의 검사 구현이 필요하다. 현재 엔진의 작업 단위 중복 거부와 QA의 옛 해시 재검사는 이 결정을 아직 구현하지 않는다. [WLG-063](../../../worklog/milestones/WLG-063.md)에 현재 차단 건의 확인 가능한 증거와 빈칸을 기록한다.
