# ADR-0011 — Snapshot dirty project contents for approved work

Status: Accepted (2026-10-02)

The earlier engine rejected any tracked or untracked local change before CTO analysis. This made a new project unusable after the user added ordinary files. The existing worktree preparation already copies the selected project's current diff into each isolated worktree and commits that copy as a temporary baseline. Developer changes are later integrated as a patch relative to that baseline, with declared-file checks and `git apply --check` before application.

Allowing the dirty tree through analysis and execution preserves user files and uses that baseline mechanism. The CEO still approves the specific project and task file list before any agent write. A patch conflict blocks instead of overwriting the user's content. Alternatives were forcing a user commit or auto-committing their changes; both impose unexpected Git state changes on the user. This decision does not expand approval or permit edits outside declared files.
