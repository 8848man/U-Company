# ADR-0071 — 개발 빌드 디버그 정보 축소와 용량 판정

Status: Accepted
Date: 2026-11-10

## 맥락

Windows `src-tauri/target/debug`가 증분 캐시 정리 후에도 15.22 GiB였다. `deps` 8.08 GiB, `.pdb` 3.33 GiB, `.rlib` 3.91 GiB가 주요 부분이다. 증분 캐시만 정리해도 전체 용량이 안정된다는 근거는 없다. 사용자는 개발 빌드의 디버그 정보 축소를 먼저 적용하고 지속적인 충분성 게이트를 요청했다.

## 결정

기본 개발 프로필의 앱 디버그 정보를 줄 번호 수준으로, 의존성 디버그 정보를 없음으로 바꾼다. 자세한 디버깅을 위한 명시적 `debugging` 프로필을 둔다. [Build storage](../../build-storage.md)가 용량 측정·판정·대안 순서를 소유한다. 실제 수치와 빌드·시험 결과는 Worklog에 남긴다.

## 대안과 결과

- 기본 전체 디버그 정보를 유지하면 디버거 경험은 좋지만 측정된 `.pdb`·라이브러리 용량을 줄일 수 없다.
- 라이브러리의 `staticlib`·`cdylib` 출력을 먼저 줄일 수도 있다. Tauri의 플랫폼 요구와 기존 Windows·Ubuntu 빌드를 확인해야 하므로 두 번째 단계로 둔다.
- `cargo clean`을 매번 실행하면 즉시 공간은 회수하지만 증분 빌드 이점을 없앤다. 빌드 결과가 계속 쌓일 때 별도 운영 정책으로 검토한다.

프로필 변경은 첫 빌드에 전체 재컴파일 비용을 만든다. 기본 디버거의 변수·의존성 추적은 약해질 수 있으며, 필요한 경우 `debugging` 프로필로 다시 빌드한다. 용량 절감 수치나 충분성은 검증 전까지 주장하지 않는다.
