# ADR-0035 — Goal-bound deliberation with separate transmission grants

Status: Accepted (2026-10-09, implementation staged)

## Context

The current Goal engine assumes CTO → PM → file implementation → QA. A multi-perspective meeting needs the same project and usage identity without allowing its Goal to enter that execution path. MAM-005 fixes two product decisions: per-packet preview and approval by default with an optional meeting-scoped `미리 승인`, and v2 meeting validation before v3 self-improvement. Existing approvals do not bind preview bytes to transmission, and a CLI working directory does not confine reads.

## Decision

Use `Goal.kind=deliberation` and one Meeting per Goal. Keep coarse Goal statuses `deliberating`, `awaiting_decision`, and `completed`; Meeting owns detailed stages. Version the SQLite database to 3 before writing any meeting record so older binaries refuse it. Execution-only commands reject deliberation Goals on the backend. Keep legacy project-write `Approval` separate from a byte-bound `TransmissionApproval` and never infer either from AI text.

The default transfer mode presents each immutable packet and destination for a CEO decision. A stage may show multiple packet decisions in one card. The optional meeting-scoped range grant is available only after the Security contract and closed-text provider checks are implemented and verified. A grant expires on restart, revocation, destination fingerprint change, input change, time limit, or meeting end. Dispatch and revocation have an ordered start gate; an ambiguous in-flight call is not retried automatically. A meeting's recommendation only drafts a new execution Goal; the CEO submits it explicitly and later approves any file work separately.

## Alternatives

- Reuse execution statuses and approvals: smaller schema change but omissions in old commands can run CTO/PM or approve a different payload.
- Make Meeting independent of Goal: requires parallel project, usage, navigation, and recovery identity.
- Approve all future generated text at meeting start: smoother loop but the unknown bytes cannot be represented as an exact-content grant. The optional scoped mode needs its own bounded, tested contract.
- Trust CLI `read-only`/`plan` and a temporary `cwd`: insufficient evidence of denied reads, tools, MCP, and network access.

## Consequences

Old binaries cannot open a version 3 data file. QA must use a separate data directory; production upgrade needs backup and recovery. The old and v2 frontends share backend guards and must both distinguish meeting Goals. The first live meeting is blocked until immutable packet approval and a verified closed-text connection exist. The `미리 승인` mode is a later gated slice, not a privilege granted by this ADR. The v3 self-implementation project path and Git preparation remain a later CEO choice.
