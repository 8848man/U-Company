# ADR-0032 — Topic folders for independently evolving SDD entities

Status: Accepted

Date: 2026-10-08

Affects: [SDD authoring principle](../../authoring.md), [SDD index](../../00_index.md)

## Context

ADR-0031 created a linked user-flow graph, but the SDD had no general rule for when other topics should use the same form. Applying folders to every document would increase navigation and duplicate rules; leaving independently changing entities in one file obscures ownership and impact.

## Decision

Use a topic folder with an index and linked entity files only when a topic has at least two independently evolving responsibilities or lifecycles **and** their relationships matter to change analysis. The index is a map; each rule has one owning file. Keep cross-cutting invariants in the existing canonical Spec and reference them. Preserve old paths only as content-free relocation notices when external links may exist. Add the decision test and migration procedure to `sdd/authoring.md` and the development workflow.

## Alternatives

- Folder for every topic: adds many files with no useful relationship graph.
- One large SDD file: makes distinct entity owners and dependent changes difficult to find.
- Copy shared rules into every entity: creates conflicting originals.

## Consequences

The SDD index points to a topic index when the criterion is met. Topic indexes and entity files need link and ownership checks whenever they change. Existing single-file policies stay single unless they independently meet the criterion. This is documentation architecture, not a runtime feature or approval change.
