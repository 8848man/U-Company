# ADR-0010 — Bounded QA repair loop and per-run token ledger

Status: Accepted (2026-10-01)

The initial implementation blocked immediately when QA returned a non-PASS review. This discarded the team's ability to repair approved work. A project-scoped cap now bounds additional repair rounds. Each round records QA feedback, lets PM plan file-changing repair tasks only within the original approved file set, uses isolated worktrees over the current integrated snapshot, and runs QA again. Exhaustion or scope expansion blocks with a reviewable reason. The loop counter is persisted on the goal.

Token usage is recorded once per runtime invocation and aggregated by project and character. Provider-reported final counts replace temporary estimates. Lightweight estimates use existing prompt and structured stdout, and updates are throttled; no polling call to a model is added. This gives useful live visibility without implying billing precision or adding model cost.
