# ADR-0059 — A conversation keeps its original objective: resume it with the project's changes, and close it when later work achieved it

Status: Accepted (2026-10-26, CEO). Owners: [DM-02 목표](../../domain/DM-02-goal.md), [GC-01](../../goalConversation/GC-01-turns.md), [GC-05 열린 작업](../../goalConversation/GC-05-open-work.md), [UF-06 복구](../../userFlow/UF-06-recovery.md).

Date: 2026-10-26

## Context

Since goal versions read as one conversation (ADR-0051) and a completed goal can take another work pass (ADR-0055), a conversation's state is the state of its newest version. When the newest pass is small ("find why it stopped", "decide the fix") and completes, the conversation shows as completed and leaves open work, although the CEO's original objective is unfinished (e.g. 677e378d → c1e27704 → 7a7dd2e8; 35d86ef5 → e845695e → a35eeb25). The CEO loses the place to resume or give feedback. Work done later in another goal of the same project may also already have achieved an older objective that still looks open.

## Decision

1. **Objective record.** Each conversation (keyed by its first goal, as for command grants in ADR-0058) has a `conversation_objective`: `open`, `checking`, `achieved`, `closed_by_other`, `reopened`, with the judgement's summary, evidence, remaining work, the goals that achieved it, the project changes seen, and when and on which version it was checked.
2. **When it is checked.** Automatically when a version completes, and when the CEO presses `이어서 하기`. A conversation of one version that passed QA is `achieved` without a model call. Otherwise the CTO makes one read-only call with the original CEO goal and the conversation's CEO instructions, every version's status, files and latest QA, the project's changes since the app integrated them, and up to eight later completed goals of the same project. It returns `achieved`, `achievedBy` (only listed completed goals), `evidence` (required when achieved), `remaining` and a summary. A malformed answer is asked again once; a second failure leaves the conversation open with the reason.
3. **Project changes** are computed without a model: files whose content differs from the app's integration proofs, and, in a Git project, `git status` and the last five commits.
4. **Resume.** `이어서 하기` is offered while the conversation is open and its newest version is completed or blocked. After the check, an unachieved objective continues through the existing paths with an instruction built from the remaining work, the project changes and the stop reason: a follow-up pass after a completed version (ADR-0055), or the `해결 요청` route after a blocked one (ADR-0048, ADR-0051). New file work still needs a plan approval.
5. **Automatic close.** If the judgement says a later goal of the same project achieved the objective, the conversation is closed as `closed_by_other` (achieved by its own versions: `achieved`). Closing only records the state: no file, approval, task or goal record changes, so `다시 열기` restores it as `reopened`. The conversation shows who closed it and why.
6. **Open work and the goal list** use the conversation state: a conversation is in progress while its newest version is unfinished or its objective is `open`/`reopened` (or not yet checked after more than one version).

## Alternatives

- **Keep the newest version's status:** the problem the CEO reported.
- **Ask before closing:** chosen against by the CEO; the close is reversible and changes no files.
- **Scan all open conversations periodically:** spends tokens without a CEO action; out of scope.

## Consequences

- `src-tauri/src/objective.rs`, `engine.rs` (check after completion), `lib.rs` (`resume_conversation`, `reopen_conversation`, protocol 41), snapshot `conversationObjectives`; `src/goalChain.ts`, `src/openWork.ts`, `src/GoalChat.tsx`, `v3/src/V3ChatHome.tsx`, `v3/src/App.tsx`; mock AI stage `objective`; QA-53.
- Each completed multi-version pass costs one read-only CTO call.
