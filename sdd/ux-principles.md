# UI/UX 구현 철학

Status: Accepted (2026-10-11, CEO). 모든 화면의 상위 원칙이다. 결정 이유는 [ADR-0042](architecture/decisions/ADR-0042.md)에 있다. 화면별 세부 규칙은 아래 **하위 정책**이 소유하며, 이 문서와 충돌하면 이 문서를 기준으로 하위 정책을 고친다.

## 목표 문장

> 비전공자, 더 나아가 초등학생도 첫 화면만 보고 **지금 무슨 일이 일어나고 있고, 내가 무엇을 하면 되는지** 안다. 그러면서도 사용자는 필요할 때 **자신이 무엇을 승인했고, AI가 무엇을 근거로 말했는지**를 끝까지 따라가 확인하고 통제할 수 있다.

쉬움과 통제는 서로 맞바꾸는 대상이 아니다. 쉬움은 **보여 주는 순서**로 얻고, 통제는 **언제든 도달할 수 있는 경로**로 지킨다. 정보를 지워서 쉽게 만들지 않는다.

## 원칙

| ID | 원칙 | 뜻 |
| --- | --- | --- |
| UXP-1 | 한 화면에 한 깊이 | 한 화면(또는 한 대화상자 단계)은 아래 세 깊이 중 하나만 보여 준다. 다음 깊이의 내용을 미리 펼쳐 두지 않는다. |
| UXP-2 | 요약 먼저, 원문은 언제나 한 번에 | 사람이 읽을 긴 텍스트는 요약을 먼저 보이고, 같은 자리에서 한 번의 동작으로 원문을 연다. 원문은 지우거나 고쳐 쓰지 않는다. |
| UXP-3 | 통제는 항상 보인다 | 사용자가 정한 범위(승인한 계획·범위, 보낸 자료, 사용한 호출 수, 팀 구성)는 첫 깊이에 한 줄로 늘 보인다. 결정이 필요한 일은 접힌 곳에 묻히지 않는다. |
| UXP-4 | 결정은 적게, 권장은 분명하게 | 사용자에게 고르게 할 때는 선택지를 최대 다섯 개로 줄이고 권장안 하나를 강조한다. 권장은 미리 고른 상태일 수 있지만, 실행·승인은 항상 사용자가 직접 누른다. |
| UXP-5 | 쉽게 만드는 데 추가 비용을 쓰지 않는다 | 요약과 쉬운 설명은 이미 일어나는 AI 호출의 응답에 함께 받거나, 저장된 사실에서 결정적으로 만든다. 요약만을 위한 새 호출·새 전송·새 승인은 만들지 않는다. |
| UXP-6 | 쉬운 말 | 첫 두 깊이는 일상어와 짧은 문장을 쓴다. 전문 용어, ID, 해시, 경로, 모델 이름은 세 번째 깊이에 둔다. |
| UXP-7 | 사실만 그린다 | 저장된 상태와 기록만 표시한다. 없는 정보는 추정하지 않고 "아직 없음"으로 보인다. AI 요약은 사실이 아니라 **AI의 정리**로 표시한다([일의 진행 UI 표시 정책](progress-visibility.md)). |
| UXP-8 | 같은 것은 어디서나 같게 | 같은 목표·회의·팀원은 홈, 업무, Office, 작업공간에서 같은 요약·같은 상태 이름·같은 다음 행동으로 보인다. 화면마다 따로 계산하지 않고 공유 선택 함수를 쓴다. |

## 세 깊이

| 깊이 | 이름 | 보여 주는 것 | 보여 주지 않는 것 |
| --- | --- | --- | --- |
| 1 | **한눈에** | 한 줄 요약, 지금 필요한 결정과 버튼, 선택지 최대 5개(권장 1개 강조), 남은 문제 개수, 통제 한 줄(UXP-3) | 단계별 기록, 근거 목록, 원문 |
| 2 | **흐름 요약** | 진행 단계(예: 계획 → 제안 → 비판 → 수정 → 평가, 또는 분석 → 계획 → 작업 → 검증)마다 한 줄 요약·참여자·항목 수·상태, 묶어서 요약한 쟁점(해결 / 남음 / 확인 필요) | 개별 발언 전문, 해시·ID |
| 3 | **자세히** | 단계별 발언과 근거, 쟁점별 개별 의견과 응답, 주장 추적, 보낸 원문과 받은 응답 원문, 모델·연결·사용량, 해시 | — (모든 원문을 복원할 수 있어야 한다) |

- 깊이 이동은 사용자가 고른다: 1 → `요약 보기` → 2 → `이 단계 자세히` / `쟁점 자세히` → 3. 3에서는 현재 위치(예: `회의 › 요약 › ③ 비판`)와 뒤로 가기를 보인다.
- 짧은 대상(한 줄로 충분한 업무, 자료가 없는 회의)은 깊이를 건너뛸 수 있다. 빈 깊이를 만들려고 버튼을 늘리지 않는다.

## 요약 규칙

1. **출처:** 요약은 다음 중 하나다.
   - 이미 일어나는 AI 호출의 구조화된 응답에 들어 있는 요약 필드
   - 저장된 사실로 만든 결정적 문장(예: `세 명이 의견을 냈고 주장 6개`)
   - 원문 첫 문장을 길이 제한으로 자른 **원문 일부**
2. **표시:** AI가 만든 요약에는 `AI 요약`, 잘라 낸 원문에는 `원문 일부`라고 표시한다. 결정적 문장은 표시 없이 쓸 수 있다.
3. **원문 경로:** 요약이 보이는 자리마다 `원문 보기`가 있다. 원문은 고쳐 쓰지 않는다.
4. **신뢰 경계:** AI 요약은 모델 출력이며 [Security](security.md)의 신뢰하지 않는 텍스트다.
   - 일반 텍스트로만 그리고, 길이 제한을 둔다(한 줄 요약 80자, 쟁점·단계 요약 120자, 회의 전체 요약 300자).
   - 상태 전이, 승인, 완료 판정, 배정에 쓰지 않는다. 요약이 원문과 다르면 원문이 기준이다.
5. **승인 범위 예외:** 승인·보안 확인 대화상자에서는 승인 대상의 범위(파일, 대상 AI, 보낼 내용)를 요약으로 대신하지 않는다. 첫 깊이 카드는 요약과 `확인 열기`를 보이고, 확인 대화상자는 범위를 빠짐없이 보인다.
6. **없을 때:** 요약 필드가 없거나 형식이 틀리면 원문 일부로 표시한다. 요약을 얻으려고 다시 호출하지 않는다.

## 쉬운 말 용어

화면 표시만 바꾸고 저장 값과 코드 이름은 유지한다. 깊이 3에서는 원래 용어를 함께 보일 수 있다.

| 내부 용어 | 깊이 1·2 표시 |
| --- | --- |
| 패킷 / payload | 보낼 내용 |
| 비판(critique) / 반론(dissent) | 약한 곳 짚기 / 반대 의견 |
| 미해결 반론 | 아직 의견이 갈리는 점 |
| 평가자(evaluator) | 심사 담당 |
| 권고(recommendation) | 제안 |
| 결정 자료(package) | 회의 결과 |
| 호출 상한 | AI에게 물어볼 수 있는 횟수 |
| SHA-256·지문·ID | 깊이 3에서만 |

## 화면 점검표

새 화면이나 바뀐 화면은 [Validation](validation.md)에서 다음을 확인한다.

1. 첫 깊이만 보고 "지금 무슨 일이고 내가 무엇을 하면 되는지" 한 문장으로 말할 수 있는가.
2. 한 화면에 두 깊이 이상이 펼쳐져 있지 않은가.
3. 요약이 보이는 모든 자리에서 한 번에 원문에 갈 수 있는가. AI 요약과 원문 일부가 구분되어 표시되는가.
4. 통제 한 줄(승인 범위·보낸 것·호출 수)과 결정이 필요한 일이 첫 깊이에 있는가.
5. 선택지는 다섯 개 이하이고 권장안이 하나로 분명한가. 실행·승인은 사용자가 직접 누르는가.
6. 요약을 위해 새 AI 호출이나 전송이 생기지 않았는가.
7. 깊이 1·2에 해시·ID·영문 전문 용어가 나오지 않는가.
8. 같은 대상이 다른 화면에서 같은 요약·상태·다음 행동으로 보이는가.
