# 전체 앱 UX 복잡도 축소 계획

Status: **v2 코드 구현, 실사용 검증 대기**. [v2 소스와 실행 방법](../../v2/README.md)에 다섯 메뉴 구현이 있다. 원래 UI는 비교용으로 유지한다. 현재 제품 규칙은 [제품](../product.md), [목표 작업공간](../goalConversation/GC-03-workspace.md), [정보 밀도 정책](../content-density.md), [보안](../security.md)이 소유한다. 실제 화면·사용성 검증은 [WORKLOG](../../WORKLOG.md)에 기록한다.

## 문제와 목표

현재 상단 탐색은 **CEO 데스크·프로젝트·업무 현황·토큰 사용량·AI 연결·Office 6개 메뉴**이고, 전역 프로젝트 전환과 열린 작업 버튼이 별도로 있다. [App.tsx](../../src/App.tsx)의 CEO 데스크는 목표 작성·현재 프로젝트·토큰·QA 설정·목표별 상태와 행동을 한 화면에 놓는다. 업무 현황은 목표 그래프·승인·업무 카드·활동 기록을 동시에 보여준다. 프로젝트 화면에는 폴더 선택과 [외부 명세 이식](../../src/SpecImportPanel.tsx)이 함께 있고, AI 연결에는 발견·미설치 도구·직접 추가·등록 목록이 이어진다. Office는 목표 레일·캐릭터·개인 패널·팀 설정을 포함한다. 같은 목표의 상태·담당·QA·세부 기록이 여러 화면에서 반복된다. 기존 다섯 항목 제한은 목록 길이를 줄이지만 **첫 화면에 경쟁하는 정보 블록 수**는 줄이지 못한다.

목표는 처음 보는 사람이 현재 프로젝트에서 **지금 할 일 → 담당자 → 근거 → 세부 설정**을 자연스럽게 찾게 하는 것이다. 첫 화면은 한 가지 주 행동과 필요한 결정만 강조하고, 세부 정보는 같은 목표·프로젝트·팀원에 묶인 상세 화면에서 펼친다. 데이터·기록·승인 근거는 삭제하거나 숨기지 않는다.

## 계획 파일과 관계

| ID | 파일 | 소유하는 결정 |
| --- | --- | --- |
| UX-01 | [탐색과 여정](UX-01-navigation.md) | 최상위 메뉴, 전역 진입점, 첫 사용/재방문 경로 |
| UX-02 | [화면별 정보 우선순위](UX-02-surfaces.md) | 각 메뉴의 기본 정보·보조 정보·상세 이동 위치 |

관계는 `defines`(구조가 화면의 위치를 결정), `validates`(계획의 결과를 시험), `maps_to`(기존 UF 여정과 대응)로 한정한다. UX-01의 메뉴 구조가 UX-02의 정보 배치를 제한하고, UX-03이 두 제안을 검증한다. v2 분리와 엔진 재사용은 [ADR-0033](../architecture/decisions/ADR-0033.md)에 기록했다. 관련 [UF-01–UF-08](../userFlow/00_index.md)은 v2 진입 위치를 함께 설명한다.

## 유지할 경계

- 승인 대기와 중단된 목표의 **지금 필요한 결정**은 접힌 일반 기록 속에 묻히지 않는다.
- 연결·모델·토큰 추정 여부·실제 진행 근거는 상세에서 복원 가능하다. 정보 축약은 추가 AI 호출로 만들지 않는다([UI/UX 구현 철학](../ux-principles.md) UXP-5).
- 화면의 정보 배치는 [UI/UX 구현 철학](../ux-principles.md)의 세 깊이(한눈에 · 흐름 요약 · 자세히)를 따른다.
- 사용자가 과거에 요청한 **토큰 전용 메뉴**와 Office 캐릭터의 일감 가시성은 유지한다.
- UI 재배치는 목표 상태, 프로젝트 귀속, 승인 정책, 저장 데이터와 런타임 실행 방식을 바꾸지 않는다.
