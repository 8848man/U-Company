# UX-03 — 구현 순서와 수용 기준

Status: **v2 구현 진행 중**. 아래 체크박스는 검증 근거가 있을 때만 완료로 바꾼다. 실제 증거는 [WORKLOG](../../WORKLOG.md)와 [수동 QA](../../qa/MANUAL-QA.md)에 기록한다.

`v2/`에 다섯 메뉴·전역 프로젝트 선택·설정 하위 화면·간결한 홈/목표 중심 업무를 구현했다. TypeScript/Vite와 개발 서버 모듈 로딩은 확인했다. 이 단계의 체크박스는 Windows/Ubuntu 실제 화면과 사용자 과제 검증까지 포함하므로 아직 열어 둔다. [QA-36](../../qa/MANUAL-QA.md#qa-36-v2-간결한-탐색과-정보-소유권)과 [v2 실행 안내](../../v2/README.md)가 남은 검증 경로다.

## 작업 순서

- [ ] **0. 기준선 기록:** Windows 앱에서 빈 워크스페이스, AI 미연결, 2개 프로젝트/여러 목표, 승인 대기, 중단 목표의 화면을 캡처한다. 각 메뉴의 첫 화면 블록 수, 동일 사실의 중복 위치, 핵심 과제의 클릭·소요 시간을 기록한다. 현재 `App.tsx`의 조건과 실제 화면이 다른 경우 실제 화면을 우선 기록한다.
- [ ] **1. 정보 소유자 고정:** 기존 `goalBrief`, `goalRecovery`, 진행·토큰 집계 등 저장 상태 기반 selector를 재사용해 목표 요약·결정 우선순위를 한곳에서 계산한다. 화면마다 별도 상태 해석을 추가하지 않는다. 승인·중단·새 목표·진행·완료의 우선순위와 동률 규칙을 명세한다.
- [ ] **2. 탐색 전환:** [UX-01](UX-01-navigation.md)의 5개 상위 메뉴, 전역 프로젝트 선택기, 설정 하위 항목을 만든다. 기존 프로젝트/AI 연결 진입 링크·토스트·열린 작업은 새 목적지로 연결한다. 메뉴 선택과 프로젝트 전환은 서로 다른 동작으로 유지한다. 결정된 구조를 ADR로 기록한다.
- [ ] **3. 홈·업무:** 홈의 첫 사용/재방문 상태를 나누고 목표 카드의 중복 정보와 버튼을 줄인다. 업무 현황은 목표 중심으로 만들고 선택 목표의 업무·이벤트만 펼친다. 유효한 승인 요청은 접힌 기록 속으로 옮기지 않는다.
- [ ] **4. 설정 화면:** 프로젝트 목록과 외부 SDD 이식을 분리하고, AI 연결의 등록/발견/지원 목록을 단계적으로 연다. Office의 일괄 팀 설정을 설정으로 이동한다. 개별 팀원의 개인 설정은 Office 캐릭터 선택에서 계속 제공한다.
- [ ] **5. Office·토큰·대화:** Office 목표 레일을 짧은 선택 줄로 다듬고 활동 패널은 선택 팀원에 집중한다. 토큰 메뉴는 전체 비교를 유지하고 상세 모델 기록을 확장한다. 목표 대화에는 상태에 맞는 중요 카드만 기본 표시한다.
- [ ] **6. 회귀와 문서 동기화:** [UF-01–UF-08](../userFlow/00_index.md)의 실제 진입·복귀 경로, 제품/진행/정보 밀도/목표 대화 Spec, 구현 지도, QA를 갱신한다. Windows 실기 QA 후 Ubuntu에서 핵심 흐름을 별도로 확인한다.

각 단계는 이전 단계의 화면만 남기지 않고 실제 새 경로로 끝나야 한다. 중간 상태에서도 프로젝트 전환, AI 상태 확인, 승인, 목표 복구, 토큰 상세에 접근할 수 있어야 한다.

## 핵심 사용자 과제와 합격 기준

| 과제 | 성공 조건 |
| --- | --- |
| 첫 사용자가 폴더를 고르고 AI를 연결해 목표를 전달 | 필요한 다음 행동이 처음 보는 화면에서 발견되고, 잘못된 AI 상태나 프로젝트를 실행 가능으로 표시하지 않는다. 목표가 선택 프로젝트에 묶인다. |
| 재방문자가 승인 대기 목표를 찾고 범위를 검토 | 홈 또는 열린 작업에서 즉시 발견한다. 정확한 승인 범위와 거부/나중에/승인 선택이 보이고 AI 답변만으로 승인되지 않는다. |
| CEO가 진행 중 목표의 담당자와 실제 근거를 찾음 | 홈의 요약에서 목표를 열고, 한 목표 작업공간에서 팀원·마지막 확인 이벤트·업무·QA를 찾는다. Office와 업무의 표시는 같은 저장 사실을 가리킨다. |
| 중단 목표를 고치고 돌아옴 | 이유·멈춘 단계·유효한 복구 행동이 보인다. AI 연결 수정이나 Git 첫 커밋 후 같은 목표로 돌아오는 경로가 명확하다. 지원하지 않는 재개를 제안하지 않는다. |
| 프로젝트를 바꾸거나 SDD를 이식 | 전역 선택기로 빠르게 전환하고, 상세 설정에서 파일 원본/미리보기/적용을 구분한다. 다른 프로젝트의 목표·명세가 섞이지 않는다. |
| 토큰을 목표·팀원·모델별 비교 | 독립 토큰 메뉴에서 프로젝트 총량을 기준으로 비교하고 원문 기록·추정 여부를 복원한다. 숨긴 AI 호출이나 새 모델 호출이 없다. |

수치 목표는 기준선 측정 후 확정한다. 제안 기준은 **초보 사용자의 핵심 과제 성공률 80% 이상**, 찾기/전환 과제의 중앙 소요 시간 **기준선 대비 25% 이상 감소**, 주요 과제의 불필요한 메뉴 왕복 감소다. 3–5명의 제품 비숙련 사용자에게 화면 설명 없이 과제를 맡기고, 실패한 위치와 잘못 이해한 라벨을 기록한다. 수치 달성만으로 승인·보안·상태 정확성 결함을 통과시키지 않는다.

## 회귀 게이트

- 긴급 승인과 중단 복구는 모든 메뉴에서 접근 가능하고 접힌 일반 기록에만 존재하지 않는다. `열린 작업`은 크로스 프로젝트 복귀를 유지한다.
- 프로젝트 선택·팀 배정·목표 실행·승인·QA·토큰은 기존 저장 ID와 기록을 유지한다. UI 축약은 기록 삭제나 AI 요약 호출이 아니다.
- 빈 상태, 오류, 로딩, 여러 프로젝트, 여섯 개 이상 목표/AI/업무, 좁은 창, 키보드, 포커스 복귀, 고정 앱바·사이드바를 검사한다.
- 한 화면에서 설명을 줄여도 막힌 버튼은 클릭 시 구체적인 이유와 다음 행동을 보여준다. 실제 승인 범위는 다이얼로그에서 완전히 확인 가능하다.
- 완료 판정은 실제 앱 스크린샷·과제 기록·자동 회귀 결과가 WORKLOG에 남은 뒤에만 한다. 이번 계획 문서 작성은 이 게이트를 통과한 것이 아니다.
