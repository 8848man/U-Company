# UX-01 — 탐색과 사용자 여정 재배치

## v2 최상위 구조

현재 6개 메뉴를 **홈·업무·Office·토큰·설정 5개**로 정리한다. 이름은 개발 용어보다 사용자가 찾는 일을 우선한다. 프로젝트와 AI 연결은 `설정`의 하위 항목으로 옮기되, **현재 프로젝트 전환은 전역 프로젝트 선택기**에서 계속 바로 할 수 있게 한다.

| 위치 | 사용자가 여기서 하는 일 | 기존 화면과의 관계 |
| --- | --- | --- |
| 홈 | 목표를 말하고 지금 필요한 결정·진행 목표를 연다 | CEO 데스크를 간결하게 구성 |
| 업무 | 목표별 진행을 비교하고 한 목표의 업무·기록을 파고든다 | 업무 현황의 목표 중심 재배치 |
| Office | 팀이 일하는 모습을 보고 팀원·목표를 선택한다 | 시각화와 개인 활동에 집중 |
| 토큰 | 프로젝트·목표·팀원·모델 사용량을 비교한다 | 독립 메뉴 유지 |
| 설정 | 프로젝트 등록/명세, AI 연결, 팀 일괄 설정을 관리한다 | 기존 프로젝트·AI 연결·Office 팀 설정을 묶음 |

전역 프로젝트 선택기는 등록된 폴더 전환과 `폴더 추가`만 빠르게 제공한다. 상세 경로, Git 방식, 프로젝트 QA 기본값, 공통 SDD는 설정의 프로젝트 상세에서 다룬다. 우측 하단 `열린 작업`은 **다른 탭·프로젝트의 미완료 목표로 빠르게 돌아가는 진입점**만 맡고, 업무 현황의 축소 복사본이 되지 않는다. 긴 목록은 전용 업무 화면으로 이동한다.

## 첫 사용과 재방문 경로

| 상황 | 첫 화면의 제안 | 다음 행동 |
| --- | --- | --- |
| 프로젝트가 없음 | `작업할 폴더 선택` 한 가지 행동 | 폴더 등록 후 목표 작성 화면으로 복귀 |
| AI 역할이 부족함 | 현재 목표 실행에 필요한 역할만 이유와 함께 표시 | 설정의 해당 AI 연결/팀 배정으로 이동하고 복귀 |
| 첫 목표 작성 | 목표 입력과 `팀에 전달`을 중심에 둠 | 생성된 목표를 열어 실행·승인 상태 확인 |
| 회의로 먼저 검토 | 같은 입력칸의 모드를 `회의`로 바꾸고 안건 입력 | 의장 계획 카드를 확인·승인하고 같은 목표 작업공간에서 결정 자료 확인 |
| 재방문, 결정 필요 | 가장 긴급한 승인/중단 결정을 상단에 표시 | 같은 목표 작업공간에서 범위와 근거 확인 |
| 재방문, 진행 중 | 현재 목표와 담당자·다음 확인 시점 표시 | 필요하면 업무·Office·토큰으로 깊이 이동 |
| 다른 프로젝트의 열린 일 | 전역 선택기 또는 열린 작업으로 대상 선택 | 프로젝트를 바꾼 뒤 그 목표 작업공간으로 이동 |

초기 설정 완료 후에는 영구적인 3단계 온보딩 막대를 기본 화면에서 제거한다. 필요할 때만 해당 미충족 조건을 보여준다. 진행 중 목표의 대화·승인·복구는 [공통 목표 작업공간](../goalConversation/GC-03-workspace.md) 하나로 모은다.

## 대안과 결정 게이트

토큰을 업무의 하위 탭으로 접으면 메뉴 수는 더 줄지만, 사용자가 요청한 전용 토큰 메뉴와 프로젝트 전체 비교가 약해진다. 프로젝트를 완전히 설정 안에만 넣으면 전환이 느려지므로 전역 선택기를 남긴다. Office 팀 일괄 설정을 시각화 옆에 유지하면 개인/조직 설정의 구분이 흐려진다. 이 구조는 [ADR-0033](../architecture/decisions/ADR-0033.md)으로 v2에 적용했다. 메뉴 라벨과 전역 선택기의 실제 발견성은 수동 QA에서 검증한다.
