# 완주율·사용성 개선 라운드

Status: R0~R7 구현 완료, Windows 수동 점검(QA-50) 대기 (2026-10-20, 브랜치 `feature/completion-usability-rounds`). 결정: [ADR-0052](architecture/decisions/ADR-0052.md). 진행 증거: [WORKLOG](../WORKLOG.md).

## 왜 하는가

2026-10-20 평가에서 U컴퍼니는 잘못된 결과를 막는 장치는 강하지만, 목표를 **끝까지 완주하는지**는 증명되지 않았다.

- 엔진 `run()` 전체 경로에 종단 시험이 없다(Tauri `AppHandle` 의존).
- 수동 QA 항목은 대부분 실행 기록이 없다.
- 실제 사용에서 찾은 문제 대부분이 "틀린 결과"가 아니라 "멈춘 목표"였다(ADR-0048, ADR-0050, ADR-0051).
- 비개발자에게는 첫 실행, 계획 승인 판단, 결과 확인이 어렵다.

목표는 사용자가 **U컴퍼니로 샘플 앱을 만드는 흐름**을 토큰 없이 한 번, 실제 AI로 한 번 끝까지 돌려 볼 수 있게 하는 것이다.

## 라운드

각 라운드는 같은 순서로 닫는다: 소유 명세·ADR → 구현(기존 함수 재사용) → 시험 추가·전체 통과 → 자체 검토 → 커밋 → WORKLOG. 시험이 깨지면 그 라운드에서 고치고, CEO 결정이 필요하면 멈춘다.

| 라운드 | 결과 | 완료 기준 |
| --- | --- | --- |
| R0 기준선 | 브랜치, 기준선 시험, 이 문서와 ADR-0052 | Rust lib 148, vitest 104, 빌드 3종 통과 기록 |
| R1 모의 AI 연결 | 플러그인 프로토콜 v1을 따르는 시나리오 재생 어댑터(`scripts/mock-ai/`)와 연결 등록 경로 | 앱이 모의 AI를 `files` 능력이 있는 연결로 쓰고, 개발 업무가 실제 파일을 만든다 |
| R2 엔진 종단 시험 | `run()` 전체를 모의 앱 + 모의 AI로 돌리는 시험 | 정상 완주, QA 실패 후 재작업, 계획 형식 재요청, 재시작 시 승인 보존 |
| R3 범위 추가 승인([ADR-0053](architecture/decisions/ADR-0053.md)) | 재작업에 새 파일이 필요하면 같은 목표에서 파일 추가 승인으로 이어감 | 새 목표 버전 없이 승인 → 재작업 → QA |
| R4 계획 카드 사용성([ADR-0054](architecture/decisions/ADR-0054.md)) | 예상 호출 수·토큰 범위, 쉬운 용어 | 승인 전에 얼마나 걸릴지 감을 잡을 수 있다 |
| R5 결과 확인·멈춤 통계 | 바뀐 파일 요약, 실행해 보는 법, 멈춤 종류별 횟수 | 비개발자가 결과를 열어 볼 수 있다 |
| R6 첫 실행·샘플 앱 | 홈 준비 점검, `샘플 앱 만들어 보기`, [샘플 앱 흐름 점검](../qa/SAMPLE-APP-FLOW.md) | 안내만 따라 첫 목표를 끝낼 수 있다 |
| R7 통합 검증·인계 | 전체 시험, 모의 화면 확인, PR 본문 | 검증한 것과 못 한 것이 기록됨 |

## 범위 밖

설치 파일(.msi), 위험 낮은 계획 자동 승인(보안 정책 변경이라 별도 결정), 역할 전문 분야 배정, `engine.rs` 분할, v1·v2 셸 정리. 화면 변경은 v3 셸에만 한다.
