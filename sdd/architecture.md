# Architecture and persistence specification

Tauri 2 hosts a Rust orchestration core and a shared React/TypeScript frontend. SQLite is the local source of truth for organization configuration, goals, tasks, sessions, normalized events, approvals, artifacts, and connection definitions. Database writes and state transitions are transactional; schema changes use numbered migrations. Credentials stay in the operating system's credential store or the provider's existing CLI login, never in SQLite or event payloads.

External SDD import uses the existing SQLite object store: at most one staged draft per project, one applied read model per project, and immutable revision records. Applying a draft checks its base revision and current project file, then writes the read model, revision record, draft removal, and count-only event in one transaction. Profiles are returned to the UI only for the selected project. Import preview does not modify a project folder or provider process. The separate create-only portable action writes the tool-neutral project manifest after user confirmation; status and preview detect later external edits. The contract is owned by [External SDD import](specImport/00_index.md).

The core is split into domain transitions, scheduler, adapter registry, platform services, persistence, and UI commands/events. Platform services own executable lookup, app data paths, credential access, process lifecycle, canonical path validation, and Git worktree creation/cleanup. Windows and Linux implementations must satisfy the same contract; domain code has no OS-specific paths or command syntax.

The scheduler persists a planned task and selected agent before spawning. For a Git repository root it creates one Git worktree per parallel writing task; for an ordinary folder it creates one bounded isolated copy and baseline per task. Integration is serialized and checks the resulting changes and conflicts before updating the primary project. An app crash leaves isolated workspaces and native sessions discoverable for recovery. Project discovery is read-only; changes to an existing project's instructions or harness require a separate, explicit task.

The frontend receives ordered snapshot plus event updates from the core. Office position and animation are projections of organization configuration and normalized execution events. Pixel Agents code is limited to the Canvas visualization layer; its server/runtime is not adopted. Copied code keeps the MIT notice and assets are included only after individual rights are checked.
