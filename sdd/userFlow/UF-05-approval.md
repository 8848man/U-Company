# UF-05 — 범위 승인

## 목적과 시작 조건

CEO가 실제로 변경될 대상과 이유를 보고 앱 안에서 명시적으로 결정한다. PM의 파일 작업 계획, 또는 중단된 Git 첫 커밋의 고정 복구 작업처럼 승인 대상이 생성됐을 때 시작한다.

## 사용자 흐름

앱 기술·구조 선택을 바꾸려면 `설정 > 앱 기술·구조` 탭으로 이동한다. 계획 카드에서 이동해도 대기 승인·고정 선택은 그대로 남는다. 프로젝트가 없으면 해당 탭은 프로젝트 선택으로 안내할 뿐 승인 또는 프리셋 저장을 제공하지 않는다. 설정에서 목표로 복귀하면 저장된 해당 계획 개정과 승인 범위를 다시 확인한다.

앱 산출물 계획 카드에는 선택 프리셋 ID·버전, 개정 지문, 해결된 기술 결정, 예상 산출물 영향, 수치 목표의 검증 상태가 함께 표시된다. 아래 네 결정은 서로 다른 버튼·기록이며 하나가 다른 것을 대신하지 않는다. 규칙 원문은 각 소유 명세에 있다.

| 결정 | 누르는 곳과 대상 | 바꾸는 것 | 바꾸지 않는 것 | 소유 명세 |
| --- | --- | --- | --- | --- |
| 선택 저장 | `앱 기술·구조` 탭, 완전한 차이·영향 미리보기 뒤 저장 | 그 프로젝트의 활성 선택(이후 계획의 기본값) | 대기·승인된 계획 카드, 스냅샷, 프로젝트 파일, 외부 자원 | [ADR-0062](../architecture/decisions/ADR-0062.md) D-2·D-3 |
| 계획 승인 | 목표 대화 계획 카드의 `승인`/`개선`/`거부` | 현재 계획 개정과 그 선택 지문에 묶인 실행 시작 | 다른 개정, 설정의 활성 선택 | [ADR-0046](../architecture/decisions/ADR-0046.md), [보안](../security.md) |
| 프로젝트 쓰기 승인 | 같은 계획 카드의 선언 파일 범위, 또는 `파일 추가 승인`·Git 첫 커밋 카드 | 승인된 파일만 통합 | 선언 밖 파일, 명령 권한 | [보안](../security.md), [ADR-0053](../architecture/decisions/ADR-0053.md) |
| 외부 전송 승인 | `AI와 만들기`의 최종 전송 전문·제공자 확인 버튼 | 그 내용·목적지로 한 번의 모델 호출 | 활성 선택, 계획, 파일 | [보안](../security.md) |

설정 선택 변경만으로 대기 카드는 바뀌지 않는다. 현재 목표에 적용하려면 CEO가 `개선`으로 같은 Goal의 새 계획을 요청하고 이전 대기 승인을 무효화한 다음 새 카드의 범위를 다시 승인한다. 승인 뒤 선택 변경은 안전 체크포인트와 연결 Goal의 새 계획·승인을 거친다([ADR-0046](../architecture/decisions/ADR-0046.md), [ADR-0027](../architecture/decisions/ADR-0027.md)). 화면에 남은 오래된 카드(이전 개정, 다른 프로젝트, 지문 불일치)로 누른 `승인`은 엔진이 거부하고 파일·업무 시작이 없으며, CEO는 현재 카드를 다시 확인한다.

1. 목표 카드나 대화의 `확인하기`에서 요청된 프로젝트·작업·파일 범위와 이유를 확인한다. v2에서 새 요청의 시스템 알림·소리를 켰다면 짧은 신호를 받을 수 있지만, 실제 범위와 결정은 앱의 목표 작업공간에서 확인한다. 승인 대상이 없으면 버튼은 이유와 다음 행동을 설명한다. CTO가 개발 목표로 판단했고 프로젝트에 U 컴퍼니 구조가 없으면 같은 창에 `작업 구조`가 함께 나온다(권장 동작, 바꾸기, `이번엔 건너뛰기`, `이 폴더는 묻지 않기`). 계획에 필요한 역할에 쓸 AI가 부족하면 `AI 연결`도 함께 나온다. 이 답들은 계획 승인과 따로 기록되고, 답하지 않아도 승인 결정은 할 수 있다([SI-03](../specImport/SI-03-origin.md), [ADR-0045](../architecture/decisions/ADR-0045.md)).
2. CEO가 승인하거나 거절한다. v3에서는 이 범위가 목표 대화 안의 계획 카드로 나오고 선택지가 셋이다([ADR-0046](../architecture/decisions/ADR-0046.md)): `승인`, `개선`(다음 메시지를 방침으로 같은 목표에서 다시 계획, 새 계획은 다시 승인), `거부`(목표를 취소, 파일 변경 없음). 단순 대화 문장, AI의 권고, 창 닫기, 시간 경과는 승인으로 해석하지 않는다.
3. 승인된 범위에서만 엔진이 작업을 이어간다. 범위가 바뀐 새 목표 버전에는 이전 승인을 재사용하지 않는다. 거절은 기록되고 자동 재시도하지 않는다.
4. QA 재작업에 승인되지 않은 새 파일이 필요하면 v3 대화에 `고칠 때 새 파일이 필요해요` 카드가 나온다([ADR-0053](../architecture/decisions/ADR-0053.md)). 새 파일 목록과 재작업 계획을 보고 `파일 추가 승인`하면 같은 목표에서 재작업이 이어지고, `거절`하면 파일을 바꾸지 않고 목표가 멈춰 `해결 요청`으로 새 계획 버전을 만들 수 있다. 이 카드에는 `개선`이 없다.
5. Dev가 승인되지 않은 명령에 막히면 PM이 먼저 판단하고, 새 권한이 필요한 거절 호출만 고른 뒤 v3 대화에 `명령 실행 승인이 필요해요` 카드가 나온다([ADR-0065](../architecture/decisions/ADR-0065.md)). 스크립트 본문은 줄별 명령으로 나열하지 않는다. QA의 거절은 별도 경로로 간다([ADR-0058](../architecture/decisions/ADR-0058.md)). `모두 승인`은 안전한 명령과 직접 고른 위험 명령만 이 목표 대화에 허용하고 막힌 작업을 같은 세션에서 이어 간다. `승인하지 않음`이면 지금 결과로 통합·QA가 진행된다. 계획 카드에 적힌 안전한 명령은 계획 승인과 함께 허용된다.
6. Git 첫 커밋은 별도 미리보기에서 실제 폴더·선택 파일·작성자·메시지를 확인한 뒤 승인한다. 앱은 승인한 고정 Git 작업만 수행하고 결과를 목표에 기록한다.

## 종료와 분기

Dev의 명령이 거절되면 먼저 PM이 해당 작업과 기존 승인 범위를 확인한다. 기존 권한으로 가능한 다른 방법이 있으면 CEO 카드 없이 같은 Dev 세션에서 한 번 다시 시도한다. 새 권한이 필요한 경우에만 `명령 실행 승인이 필요해요` 카드가 나오며, 카드에는 PM이 요청한 이유를 보여 준다. PM이 불필요하다고 판단하면 거절 사실을 기록하고 현재 결과를 QA에 보낸다. PM이 응답하지 못하거나 형식이 틀리면 그 사실을 기록하고 기존 CEO 카드로 이동한다([ADR-0065](../architecture/decisions/ADR-0065.md)).

설정의 `AI 실행 권한`에서 선택 프로젝트의 기본 모드를, 목표 채팅의 `실행 권한`에서 이 대화의 모드를 고른다. 기본은 `수동`; 목표는 `프로젝트 설정 따름`으로 되돌릴 수 있다. `오토`는 단순 로컬 조회, `풀 오토`는 선언한 파일의 삭제·이동도 자동 처리한다. 시험·빌드와 외부 작업, 범위 밖 작업은 계속 승인 카드로 간다는 설명을 같은 화면에 둔다. 선택한 모드는 채팅에서 항상 보이고 변경은 다음 권한 판단부터 적용된다([ADR-0066](../architecture/decisions/ADR-0066.md)).

승인하면 저장된 현재 계획의 다음 유효 단계로 돌아간다. 거절 또는 오래된 요청이면 목표는 새로운 판단을 기다린다. Git 미리보기 뒤 파일이 바뀌면 승인이 거부되고 다시 범위를 확인한다. Git 커밋이 성공해도 원래 업무 범위가 맞지 않으면 목표가 자동 완료되지 않는다.

## 완료 기준 결정 (ADR-0060)

첫 QA 실패 때 QA의 `전제 없음` 판단만으로 CEO 카드를 열지 않는다. PM이 원래 기준과 QA 근거를 받아 승인된 파일의 재작업을 계획한다. PM이 기준 수정을 제안하거나, 재작업 뒤에도 같은 기준이 그대로 실패하면 `완료 기준 결정` 카드가 뜬다. 그때 CEO가 기준을 유지한 채 승인된 파일 안에서 더 고칠 수 있다고 판단하면 `기준 유지하고 파일 고치기`로 같은 목표의 재작업을 요청할 수 있다. 기존 QA 한도를 넘기지 않으며, 새 파일이 필요하면 별도 범위 승인을 받는다. 기준마다 `빼기`·`바꾸기`·`그대로`를 고르고 `결정대로 다시 확인`을 누르면 파일은 그대로 두고 QA만 다시 한다(재작업 횟수를 쓰지 않음). `멈추기`는 목표를 `criteria_blocked`로 멈춘다.
