# UF-03 — 목표 실행

## 목적과 시작 조건

CEO의 자연어 목표를 선택 프로젝트에 묶어 실제 팀 작업·검증·보고까지 진행한다. 프로젝트가 선택되고 필요한 AI 역할이 사용 가능해야 한다.

## 사용자 흐름

1. CEO가 목표를 입력한다. 목표에는 현재 프로젝트 ID와 그 시점의 프로젝트 QA 재작업 기본값이 복사된다. 목표 카드에서 QA 최대치를 별도로 조정할 수 있다.
2. v3에서는 목표를 보내면 바로 팀 실행이 시작되고, 분석·계획 중에는 대화의 진행 줄만 바뀐다([ADR-0046](../architecture/decisions/ADR-0046.md)). v1·v2는 `팀 실행 시작`을 누른다. 팀 실행을 시작하면 CTO가 분석하고 PM이 파일 소유권·의존성이 있는 작업 계획을 세운다. 산출물 업무는 산출물 한 줄, 수용 기준, 입력 근거 파일, 필요한 능력을 함께 갖고, 엔진이 능력과 사용 중 상태를 확인해 담당자를 정한다. 계획이 파일 변경을 요구하면 CEO에게 산출물·담당자·배정 이유·출력 파일·수용 기준·근거를 한 승인 범위로 보여준다. 기준이 없거나 맡을 팀원이 없으면 승인 전에 이유와 함께 멈춘다.
3. 승인 후 독립 작업은 격리된 작업공간에서 병렬 실행되고, 선언된 파일만 원래 프로젝트에 통합된다. Office와 업무 현황은 저장된 담당자·단계·확인된 활동을 보여준다.
4. QA가 실제 통합 결과를 산출물·수용 기준별로 검증한다. 실패하면 목표가 가진 재작업 한도 안에서 계획·개발·QA를 반복한다. 통과하면 같은 목표 작업공간에서 산출물별 판정·근거·미확인 항목과 CEO의 다음 결정을 확인한다.

## 종료와 분기

완료는 통합과 QA 근거가 저장된 뒤에만 표시된다. 새 파일 작업은 기존 목표의 승인과 구분해 판단한다. CEO가 진행 중 지침을 바꾸면 목표 대화로, 승인이 필요하면 범위 승인으로, 실행·통합·QA가 실패하면 중단 복구로 이동한다. 앱 재시작 후에도 저장된 목표와 미완료 단계에서 다시 판단한다.
