# User flow index

이 폴더는 CEO가 앱에서 **무엇을 하고, 어떤 상태를 보고, 다음에 어디로 가는지**를 연결한 사용자 여정 그래프다. 폴더의 소유권과 분리 기준은 [SDD 작성 원칙](../authoring.md)을 따른다. [제품 명세](../product.md)는 목적과 기능 범위를, [도메인](../domain/00_index.md)은 상태 모델을, [보안](../security.md)은 권한 경계를 소유한다. 이 문서들은 그 규칙을 다시 정의하지 않는다. 구현·검증 여부는 [WORKLOG](../../WORKLOG.md)와 [수동 QA](../../qa/MANUAL-QA.md)에서 확인한다.

## 읽는 방법

각 `UF-##` 파일은 같은 순서로 **시작 조건 → 사용자의 행동과 보이는 결과 → 성공 종료 → 중단·대안 경로 → 관련 플로우**를 기록한다. 관계는 아래 다섯 종류로 한정한다.

| 관계 | 의미 |
| --- | --- |
| `requires` | 대상 플로우가 만들어 둔 상태 또는 설정이 필요하다. 매번 다시 수행하라는 뜻은 아니다. |
| `next` | 현재 흐름을 성공적으로 마친 뒤 자연스럽게 이어지는 흐름이다. 자동 실행을 뜻하지 않는다. |
| `branch` | 적힌 조건에서 대상 흐름으로 들어간다. |
| `resume` | 대상 흐름에서 잠시 벗어났다가 저장 상태를 바탕으로 돌아온다. |
| `observe` | 대상 흐름이 만든 사실을 읽는다. 읽기만으로 상태를 바꾸지 않는다. |

관계의 원본은 각 플로우 파일의 `연결` 표다. 여기에는 파일 목록과 목적만 둔다. ID는 이름이 바뀌어도 유지하고, 대상 ID는 이 목록에 있어야 한다. 승인이나 복구 가능성은 그래프의 화살표가 아니라 저장 상태와 기존 Spec이 결정한다.

## 대표 경로

`UF-01 → UF-02 → UF-03 → UF-05 → UF-03 → UF-08`이 최초 실행의 기본 길이다. 실행 중 지침을 바꾸면 `UF-03 → UF-04 → UF-03`으로, 실패하면 `UF-03 → UF-06`으로 분기한다. 기존 프로젝트 명세를 가져올 때는 `UF-01 → UF-07`을 거친다. 실제 실행 여부와 필요한 승인은 각 단계의 저장 상태로 다시 판단한다.

회의 경로는 `UF-01 → UF-02 → UF-09 → UF-08`이다. 회의 전송 승인은 UF-09 안의 별도 범위 결정이며 UF-05의 프로젝트 파일 쓰기 승인과 섞지 않는다. 회의 결과의 후속 초안을 CEO가 제출하면 새 UF-03 실행 목표가 시작된다.

## 새 플로우를 추가할 때

1. 중복되지 않는 ID와 한 문장 목적을 이 목록에 추가한다.
2. 동일한 섹션 구조의 파일을 만들고 각 분기의 조건과 상태 근거를 적는다.
3. 연결된 양쪽 파일의 관계를 확인하고, 규칙의 원본 Spec과 QA 항목을 링크한다.
4. 코드·Spec·QA의 일치 여부와 검증 결과를 `WORKLOG.md`에 남긴다.
