# UF-06 — 중단과 복구

## 목적과 시작 조건

실패한 목표를 다시 열었을 때 CEO가 **왜 멈췄고 지금 무엇을 할 수 있는지** 파악해 안전한 다음 단계로 간다. 앱 재시작, 공급자 오류, 승인 대기, 작업 통합 실패, QA 실패 모두 저장된 목표 작업공간에서 다룬다.

## 사용자 흐름

프리셋을 사용한 목표가 중단되면 저장된 계획 개정과 선택 지문을 보여 준다. 카탈로그 버전 소실·스냅샷 불일치에는 예전 정의 복원 또는 명시적 재계획을 안내하고 자동 대체·승인을 하지 않는다. 승인 전 재계획은 같은 Goal의 새 카드로, 승인 후 변경은 안전 체크포인트를 거친 연결 Goal로 이동한다. 이미 통합한 결과는 파일·의존성 digest를 확인한 때만 재사용한다. 수치 측정이 없으면 복구 화면과 결과에도 `미검증`이 남는다([DM-05](../domain/DM-05-recovery.md)).

1. CEO가 목표 카드·Office·업무 현황·열린 작업에서 중단 목표를 연다. v2에서 알림을 켰다면 새 중단 순간에 짧은 신호를 받을 수 있다. 앱은 저장된 실패 이유, 멈춘 단계, 담당 업무와 마지막 확인 기록을 보여준다.
2. 엔진 상태에 맞는 한 가지 핵심 행동을 제공한다: 쓰기 전 분석 재시도, 유효한 대기 승인 열기, 승인된 미시작 계획 재개(승인 대기 중 재시작, 또는 호출 전 연결·사용 중 확인 실패 뒤 원인을 고친 경우), 또는 진행 중 작업을 보존한 새 목표 지침 작성. 카드는 이유 → 마지막 확인 사실 → 담당자 → 다음 행동 순서로 보여주고 Office에도 같은 내용이 나온다.
3. AI 연결 문제는 실제 저장 경로를 다시 검사하거나 로그인 흐름으로 간다. 중단된 Git 초기화 업무는 앱의 파일 범위 미리보기와 별도 첫 커밋 승인으로 간다. 둘 다 오류 문자열이나 AI 답변의 명령을 직접 실행하지 않는다.
4. 대화의 마지막 차수가 완료됐어도 원래 목표가 남아 있으면 대화는 진행 중으로 남는다. `이어서 하기`를 누르면 CTO가 버전 기록·현재 프로젝트 변경·같은 프로젝트의 이후 목표를 보고 원래 목표가 달성됐는지 판단한다. 달성됐으면 근거와 함께 대화를 닫고(`다시 열기` 가능), 남았으면 남은 일로 다음 차수를 계획해 승인을 받는다([ADR-0059](../architecture/decisions/ADR-0059.md)).
5. 재개 뒤 목표·업무·승인·QA의 새 상태를 확인한다. 이미 통합된 파일은 기록을 보존하고, 미통합 결과는 완료로 표시하지 않는다.

## 종료와 분기

변경 0건으로 멈추면 CEO는 엔진이 확인한 근거를 보고 `충족 처리` 또는 `재계획`을 선택한다. 확인 근거가 없으면 충족 처리는 완료로 바꾸지 않고 필요한 자료를 안내한다. 충족 처리 뒤 남은 승인된 업무를 이어서 실행하고 모든 원래 산출물을 QA가 판정한다. 같은 파일 집합의 차단이 두 번 반복되면 자동 재계획 대신 직접 지시를 받는다([ADR-0072](../architecture/decisions/ADR-0072.md)).

복구 가능 여부는 실패 문구의 단어가 아니라 저장된 작업·승인·지침 상태로 결정된다. 명령이 실패하면 목표 작업공간에 이유를 남기고 성공으로 표시하지 않는다. 앱 재시작도 승인이나 완료를 추정하지 않는다. 기존 목표를 직접 재개할 수 없는 경우 연결된 새 목표 버전에서 계획과 승인을 다시 검토한다.

CEO가 직접 멈춘 실행 목표는 실패 차단과 구분해 `일시정지`로 보인다. 재개와 취소를 같은 목표 대화에서 고른다. 아직 끝나지 않은 AI 호출이 있으면 결정을 기록하되 결과 정리가 끝날 때까지 재개·취소를 거절하고 다시 시도하도록 안내한다. 원본 파일에 이미 반영된 변경은 취소 뒤에도 남는다([DM-04](../domain/DM-04-lifecycle.md)).
