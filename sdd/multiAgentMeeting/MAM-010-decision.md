# Office 캐릭터 회의의 전송 기준과 승인 단위 결정

이 문서는 사용자가 [MAM-009](MAM-009-revision.md)의 두 결정에 답한 기록이다. **제품 방향에 대한 결정**이며, 지금 프로젝트 파일을 수정하거나 AI 제공자에게 자료를 보내라는 승인이 아니다. 현행 승인 규칙은 [Security](../security.md)가 소유하고, 이 결정은 소유 Spec·ADR로 이관된 뒤에만 실행 규칙이 된다.

## 결정 배경 (대화 요약)

- 사용자는 기존 Office 팀원 캐릭터가 회의를 하고, PM·CTO 같은 상위 캐릭터가 토론 목표·제약·시행 횟수·참여자 배치를 정하는 구조를 원했다.
- 사용자는 "캐릭터 실제 AI 연결은 구현이 돼 있다"고 지적했다. 실행 목표가 이미 Claude·Codex CLI를 읽기 전용으로 호출하고 있는데, 회의에만 더 엄격한 전송 차단이 걸려 있었다.
- Claude Cowork는 두 가지를 추천했다. 회의를 실행 목표와 같은 신뢰 경계로 두는 것과, 계획 1회 승인을 기본으로 하는 것이다.

**사용자 원문:** "좋아. 추천 기준으로 작성해줘."

## D3 — 회의 전송 기준

**결정:** 회의 호출은 실행 목표의 읽기 전용 호출(CTO 분석, PM 계획, 목표 대화)과 같은 신뢰 경계를 쓴다.
- Claude·Codex CLI 팀원은 읽기 전용 인자(`plan` / `read-only`)로, 프로젝트 폴더를 작업 폴더로 하여 회의에 참여할 수 있다.
- 참여 AI가 선택 자료 밖의 프로젝트 파일을 읽을 수 있다는 사실을 계획 카드에 표시한다.
- 읽기 전용 인자를 실제로 반영하지 않는 연결은 회의에 참여할 수 없다. 이 연결의 결함이 고쳐질 때까지 그렇다.
- 이 결정으로 회의 전송의 "닫힌 텍스트 검증 전 금지" 조건은 없어진다([ME-02](../meeting/ME-02-packets.md), [AI-03](../aiIntegration/AI-03-adapter.md), [ADR-0035](../architecture/decisions/ADR-0035.md) 개정 필요).

## D4 — 승인 단위

**결정:** 기본은 CEO가 의장의 회의 계획을 **한 번** 승인하는 것이다.
- 계획에는 참여자, 연결·모델, 자료 해시, 프로토콜, 라운드·호출 상한이 들어간다.
- 계획 범위를 벗어나는 호출, 연결·자료 변경, 재시작 후 재개에는 다시 승인을 받는다.
- 계획 카드에서 `건별 확인`을 켜면 단계마다 실제 패킷을 승인받는다.
- 이 결정은 [MAM-005](MAM-005-decision.md)의 **D1(건별 승인 기본 + 회의별 미리 승인)을 대체**한다. 패킷 바이트·SHA-256 기록, 전송 직전 재검사, 중단·철회 직렬화, 결과 불명 호출 재전송 금지는 유지한다.
- MAM-005의 **D2(v2 회의 먼저 검증 → v3 정리·자기 구현)는 그대로 유지**한다.

## 유지되는 경계

- 어떤 회의 승인도 프로젝트 파일 쓰기, 배포, 외부 게시, 새 실행 파일 등록의 승인이 아니다.
- 회의 결과 채택은 편집 가능한 실행 목표 초안만 만든다. CEO가 제출해야 실행 Goal이 생기고, 파일 변경은 별도 승인을 받는다.
- 결정 자료의 주장·비판·근거는 엔진이 기록한 원본에서 추적 가능해야 한다([MAM-009 §5](MAM-009-revision.md#5-결과물의-추적성-r4)).
