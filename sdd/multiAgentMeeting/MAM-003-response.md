# MAM-002 비판에 대한 응답

이 문서는 [MAM-002](MAM-002-critique.md)의 C1~C9를 [MAM-001](MAM-001-proposal.md)의 작성자로서 재검토한 기록이다. 2026-10-09 현재 코드와 소유 SDD를 직접 읽었다. **확인 사실**은 아래 함수·줄 또는 문서에 연결하고, 새 구조의 효과와 구현 난도는 **설계 판단/추론**으로 구분한다. `.run-data`의 실제 사용량, 모델의 인용 정확도, CLI별 파일 격리 성능, 데스크톱 회의 흐름은 이번 문서 작업에서 측정하지 않았다. 이 응답은 현행 Spec이나 승인 권한이 아니다.

## MAM-002#C1 — 회의와 Goal의 관계

**판정: 수용.** `Goal`에 회의 종류를 명시하고 `Meeting`을 1:1로 연결하는 안을 첫 개정의 기준으로 삼는다.

**근거(확인 사실):** [`TokenUsageRecord.goal_id`는 필수 문자열](../../src-tauri/src/model.rs#L136)이고 [`execute_tracked()`](../../src-tauri/src/engine.rs#L208)가 모든 엔진 호출에 goal ID를 기록한다. 현재 [`Goal`](../../src-tauri/src/model.rs#L51)에는 `kind`가 없다. [`run()`](../../src-tauri/src/engine.rs#L382)은 CTO·PM·개발자·QA를 전제로 하며, [`answer_goal_message()`](../../src-tauri/src/engine.rs#L266)의 `direction`과 `continue`는 각각 새 개발 목표 계획과 `start()`로 이어진다(280–296행). [DM-04](../domain/DM-04-lifecycle.md)의 목표 완료는 파일 통합·QA 흐름이다. 한편 저장소의 [`objects(kind,id,payload)`](../../src-tauri/src/storage.rs#L407)는 새 kind 저장을 허용하지만, 새 객체를 [`snapshot()`](../../src-tauri/src/storage.rs#L169)과 UI에 노출하는 작업까지 자동으로 해결하지는 않는다.

**MAM-004 반영:** `Goal.kind=deliberation`과 필수 Meeting 연결을 제안한다. 기존 목표에는 마이그레이션 기본값 `execution`을 둔다. 회의의 세부 단계·참여자·결정 자료는 Meeting에 두고, Goal의 완료는 **결정 자료가 생성되어 검토 가능함**만 뜻하게 하며 품질 통과나 사용자 채택으로 표시하지 않는다. 회의 Goal의 대화는 첫 구현에서 토론 기록 조회와 읽기 전용 질문만 허용한다. `direction/continue/git_bootstrap` 라우팅은 엔진에서 막고, 인계는 별도 실행 Goal의 lineage로 만든다. Goal 상태·알림·화면 문구가 실제로 이 의미를 표현하는지 수용 테스트가 필요하다.

## MAM-002#C2 — 공유 팀원 풀의 역할 충돌

**판정: 수용.** 첫 구현의 회의 역할은 전역 `Agent`를 만들지 않고 Meeting에 고정한 슬롯 스냅샷으로 둔다.

**근거(확인 사실):** [`Agent`](../../src-tauri/src/model.rs#L22)에 팀·프로젝트 소속 필드가 없다. [`seed_agents()`](../../src-tauri/src/storage.rs#L327)는 한 전역 목록의 다섯 명을 만들고 [`snapshot()`](../../src-tauri/src/storage.rs#L169)도 `agent` 전체를 읽는다. [`run()` 389–392행](../../src-tauri/src/engine.rs#L389)은 고정 ID 우선·역할 부분 문자열 대체로 CTO/PM/QA를 찾고 `implement` 문자열로 개발자를 고른다. [`resume_approved()` 93행](../../src-tauri/src/engine.rs#L93)과 [`execute_planned()` 565행](../../src-tauri/src/engine.rs#L565)에도 같은 충돌 가능성이 있다. [DM-01](../domain/DM-01-workspace-team.md)은 Organization을 프로젝트 범위라고 정의하지만 현재 코드의 Agent 저장·조회는 전역이다. 이 문서/구현 차이는 MAM-004에서 새 동작의 근거로 숨기지 않는다.

**MAM-004 반영:** 회의 슬롯은 `participant_id`, 관점, 지침, 연결·모델 스냅샷을 가진다. 사용량에는 `meeting:<meeting-id>:<slot-id>`처럼 기존 Agent ID와 충돌하지 않는 식별자를 기록하되, 현행 Office와 토큰 화면은 [`agentId`로 표시·집계](../../src/OfficeActivity.tsx#L17)하므로 회의 참가자 이름을 별도 매핑해야 한다. Office 캐릭터가 곧 생긴다고 주장하지 않는다. 전역 Agent와 DM-01의 소속 불일치는 WORKLOG에 독립 부채로 남긴다.

## MAM-002#C3 — 최소 참여 역할과 호출 수

**판정: 부분 수용.** 1라운드·결정적 진행·기준선 비교는 수용한다. 제안자 두 명으로 줄이는 권고는 첫 제품 사례에는 부족하다고 본다.

**근거(확인 사실):** [`run()`의 CTO·PM 호출](../../src-tauri/src/engine.rs#L422)은 프로젝트 루트를 `cwd`로 받으므로 프롬프트 길이만으로 전체 모델 사용량을 예측할 수 없다. [AI-04](../aiIntegration/AI-04-telemetry.md)는 호출별 보고/추정 토큰을 구분하며 계정 한도·금액으로 표시하지 않는다. MAM-002의 “`.run-data` SQLite 4개에 사용량 0건”은 이번 검토에서 DB를 열어 재확인하지 않았으므로 실측 근거로 반복하지 않는다. 사용자의 요청은 두 전문가를 넘는 **여러 관점의 상호 토론**이다.

**MAM-004 반영:** 첫 수직 사례는 **독립 제안자 3관점 + 분리된 평가자 1명**, 엔진이 정하는 1라운드로 제한한다. 제안 3·상호 비판 3·수정 3·평가 1로 정리 호출 없이 **최대 10회**를 목표로 한다. 두 제안자 안은 7회로 더 싸지만 사용자 요청의 최소 관점 폭을 재현하지 못한다는 설계 판단이다. 각 역할의 연결·모델을 공개하고 동일 연결 재사용 시 독립성 저하를 표시한다. 같은 안건을 단일 호출로 수행한 기준선과 근거 연결, 발견한 중대 쟁점, 호출·토큰 사용량을 비교한다. 회의가 기준선보다 나은지 실측하기 전에는 라운드·참여자를 확대하지 않는다.

## MAM-002#C4 — 품질 판정의 신뢰성

**판정: 부분 수용.** 엔진의 형식·근거 검사와 모델 평가를 분리한다. 그러나 인용문 일치나 미해결 반론 0건을 **실제 품질의 증명**으로 보지는 않는다.

**근거(확인 사실):** 현행 [`execute_planned()` 553–558행](../../src-tauri/src/engine.rs#L553)은 QA 응답의 `PASS` 접두어로 합격을 판정한다. 그 결과는 파일 통합 후 검사이지만 증거의 의미까지 엔진이 판별하지는 않는다. [`parse_plan()`](../../src-tauri/src/engine.rs#L673)은 JSON 구문만 검사하므로 이를 그대로 재사용해도 인용의 진위를 보장하지 않는다. [DM-03](../domain/DM-03-execution.md)의 파일 해시는 통합 사실의 증거이고 QA를 대신하지 않는다.

**MAM-004 반영:** 구조화된 주장·반론·수정 ID를 요구하고, 로컬 자료의 경로·스냅샷 해시·인용 위치·짧은 인용문이 실제 바이트와 맞는지 엔진이 확인한다. 이는 **출처 연결 확인**이지 주장의 해석이 맞다는 판정이 아니다. 반론마다 `수용/근거를 든 반박/보류`를 남기고, 평가자 연결·모델이 제안자와 같으면 독립성 제한을 표시한다. `기준 충족` 같은 객관적 품질 인증 라벨은 없애고 `결정 자료 준비`, `근거 미확인`, `미해결 반론`을 구분한다. 미해결 반론이 있어도 결정 자료는 생성할 수 있지만 상단에 노출하고 사용자의 채택 전에는 합의로 표시하지 않는다. 1라운드 첫 구현에는 정체 감지를 넣지 않는다. 후속 다중 라운드에서는 새 검증 출처와 주장 상태의 실질 변경이 모두 없는 경우만 정체 후보로 삼고 실제 오판을 시험한다.

## MAM-002#C5 — 복수 제공자 전송 승인 범위

**판정: 부분 수용.** 목적지와 자료를 묶은 별도 전송 승인은 필요하다. 아직 생성되지 않은 발언의 정확한 내용까지 계획 시점의 한 번의 승인으로 포괄할 수 있다는 부분은 보류한다.

**근거(확인 사실):** [`Approval`](../../src-tauri/src/model.rs#L186)은 `goal_id/operation/reason/status/created_at`만 저장해 목적지·자료 해시·교차 전달을 나타내지 못한다. [`project_context()`](../../src-tauri/src/engine.rs#L660)는 다섯 문서의 앞 6천 자씩을 읽고 [`run()` 422–424행](../../src-tauri/src/engine.rs#L422)이 배정된 AI에 전달한다. [Security](../security.md)는 외부 전송에 CEO 승인을 요구하고, 외부 SDD 이식의 AI 전송에는 정확한 내용·제공자 목적지의 사후 승인을 명시한다. [제공자 조사 기록](../provider-runtime-investigation.md)은 저장 목표·문서의 Codex 전송이 승인 부족으로 자동 검토에서 거절됐음을 기록한다. 따라서 현행 일반 목표 호출이 이미 전송 승인 계약을 완성했다고 볼 수 없다. MAM-002의 “SQLite에 무기한 저장”은 **현재 명시적 보존·삭제 규칙이 없다는 뜻**으로는 맞지만, 영구 보존이 설계상 보장된다는 뜻은 아니다.

**MAM-004 반영:** 초기 자료의 목적지·파일·해시·범위와 교차 전달 가능 여부를 별도 승인 객체의 후보로 정의한다. 실행 직전 자료 바이트가 달라지면 멈춘다. 제공자 A가 생성한 문장을 B에게 보낼 때의 동적 내용은 별도 정책 결정을 요구한다. 첫 구현은 **B에게 실제 보낼 묶음을 사용자에게 보여 승인받는 방식**을 추천한다. 향후 자율 루프를 원한다면 생성물 종류·최대 길이·목적지·회차·민감정보 처리까지 제한한 사전 승인을 Security 개정과 ADR로 설계해야 한다. 비밀값 패턴 마스킹은 보조 방어일 뿐, 승인과 범위 검사를 대신하지 않는다. 로컬 기록의 보존·삭제도 같은 설계에서 명시한다. 이번 응답은 Security 자체를 변경하지 않는다.

## MAM-002#C6 — 읽기 전용·입력 범위가 강제되지 않음

**판정: 수용.** MAM-001의 “읽기 전용·선택 자료만 근거”는 현행 런타임에 적용되는 사실이 아니라 새 기능의 수용 조건이어야 한다.

**근거(확인 사실):** [`run_cli()`](../../src-tauri/src/provider.rs#L65)는 Codex에 `--sandbox read-only`, Claude에 `--permission-mode plan`을 넘기지만 프로젝트 루트를 `cwd`로 쓴다(69–90행). Gemini·OpenCode·사용자 정의 CLI 분기에는 `writable`의 강제 반영이 없다(76–89행). [`HttpProvider::execute()`](../../src-tauri/src/provider.rs#L34)은 명시된 프롬프트만 전송하지만 현재 본문에는 출력 길이 상한이 없다(39행). [`run_plugin()`](../../src-tauri/src/runtime.rs#L162)은 `writable`을 프로세스에 **선언**할 뿐 별도 OS 격리로 검증하지 않는다(181행). [AI-01](../aiIntegration/AI-01-model-runtime.md)은 모델과 파일 도구 런타임을 구분한다.

**MAM-004 반영:** 입력은 사용자가 선택한 자료의 고정 스냅샷으로 만든다. 단순히 스냅샷 폴더를 `cwd`로 주는 것만으로 다른 경로 읽기가 막힌다고 주장하지 않는다. 첫 구현에서 텍스트 전용 호출은 실제 전송 프롬프트를 확인하고, 도구형 CLI는 **선택 폴더 밖 읽기와 모든 쓰기를 OS/제공자 경계에서 거부함이 검증된 연결만** 허용한다. 검증되지 않은 Gemini·OpenCode·custom/plugin은 회의에서 거부한다. 목록 밖 표식이 출력되지 않는 시험뿐 아니라 실제 파일 열기 시도가 거부되는 시험이 필요하다. 그 검증이 없으면 Claude/Codex CLI도 “자료 범위 강제” 기능으로 광고하지 않는다. 기존 대화 경로의 느슨한 `writable` 처리 역시 별도 결함으로 WORKLOG에 남기되 이번 문서만으로 수정됐다고 하지 않는다.

## MAM-002#C7 — 토큰 방어의 실제 보장 수준

**판정: 부분 수용.** 보장 수준을 나누는 권고를 수용한다. “강제 가능한 것은 호출 수뿐”이라는 표현은 현재 **호출당 타임아웃**을 빠뜨렸다.

**근거(확인 사실):** [`provider::run_cli()` 91행](../../src-tauri/src/provider.rs#L91)은 CLI에 30분 기한을 넘기고 [`capture_with_timeout()` 84–89행](../../src-tauri/src/runtime.rs#L84)은 기한 초과 시 자식을 종료한다. [`send_json()` 150–159행](../../src-tauri/src/runtime.rs#L150)은 HTTP 전역 120초 제한을 건다. 다만 회의 전체 시간/토큰 상한, 진행 중 토큰 초과 중단은 없고 `usage_progress`가 반환값 없는 콜백이다([`capture_with_timeout()` 64–71행](../../src-tauri/src/runtime.rs#L64)). [`execute_tracked()` 210·226–235행](../../src-tauri/src/engine.rs#L208)의 입력은 프롬프트 글자 수 추정 후 결과의 보고값으로 대체된다. [`recover_interrupted()` 376–380행](../../src-tauri/src/storage.rs#L376)은 진행 중 기록을 `interrupted`로 바꿀 뿐 실제 최종 소진량을 모른다. [AI-04](../aiIntegration/AI-04-telemetry.md)는 토큰을 금액·계정 한도로 표현하지 않는다.

**MAM-004 반영:** `강제`(라운드·호출 수와 제공자 호출당 타임아웃), `다음 호출 차단`(누적 보고/추정 사용량·회의 시간), `추정만`(CLI 내부 도구 사용량·구독 잔량)을 분리 표시한다. 중단/실패 호출은 관측치 0으로 되돌리지 않고 예약한 최댓값 또는 보수적 추정으로 다음 호출 판단에 반영한다. 실제 금전 하드캡은 약속하지 않는다. 진행 중 취소 경로와 HTTP 출력 상한은 별도 설계·검증 항목이다. 실측 회의 결과를 얻기 전 토큰 기본값을 확정하지 않는다.

## MAM-002#C8 — 첫 구현 단위

**판정: 부분 수용.** 단계적 구현과 QA-36 확인을 수용한다. `start()`에 kind 분기 하나만 더하면 기존 엔진이 보존된다는 영향 평가는 지나치게 좁다.

**근거(확인 사실):** [WORKLOG](../../WORKLOG.md)의 v2 UI 항목은 QA-36 실제 Windows/Ubuntu 검증이 열려 있고 알림 항목은 QA-37 설치 앱 검증이 열려 있다. [`Goal`](../../src-tauri/src/model.rs#L51)과 [`Snapshot`](../../src-tauri/src/model.rs#L197)에 회의 구분·상세 기록이 없으며, [`storage::snapshot()`](../../src-tauri/src/storage.rs#L169)도 이를 읽지 않는다. [`answer_goal_message()` 280–296행](../../src-tauri/src/engine.rs#L280)은 회의 목표에 위험한 기존 라우팅을 수행할 수 있다. [GC-01](../goalConversation/GC-01-turns.md)·[GC-02](../goalConversation/GC-02-guidance.md)는 그 라우팅을 목표 대화의 현행 규칙으로 정한다. 오프라인 mock 검증은 실제 CLI 파일 격리나 외부 전송 승인 UX의 증거가 아니다.

**MAM-004 반영:** (0) 열린 v2 QA-36을 실제 앱에서 확인하고 회의 영향 경계를 정한다. (1) 오프라인 픽스처로 회의 상태·호출 수·중복 전송 방지·구조화 기록을 시험한다. (2) 승인·파일 격리가 증명된 연결로 3관점·1라운드의 최소 수직 흐름과 실제 데스크톱 UI를 확인한다. 프리셋 편집기, 모델 진행자, 다중 라운드, Office 연출, 자동 개발 인계는 뒤로 둔다. `start()` 외에도 goal kind 분기, 대화 라우팅, 저장 스냅샷, 사용량 표시, 알림/복구/UI를 검증해야 한다. QA-37은 알림을 이 사례에 추가할 때 별도 게이트로 둔다.

## MAM-002#C9 — v3 비코드 산출물 계약과의 중복

**판정: 수용.** 근거·가정·미확인·인수 자료의 공통 계약을 먼저 정의해야 한다. 어느 파일럿을 첫 소비자로 삼을지는 사용자 결정이다.

**근거(확인 사실):** [v3 개선안](../v3-improvement-plan.md)의 “첫 구현 단위”는 `고객·문제 가설`, `제안·메시지 초안`, `출시 전 확인 목록`을 **명시된 파일로 만들고** 독립 검토 후 인수하는 비코드 작업이다. [WORKLOG의 v3 audit](../../WORKLOG.md)은 “evidence-bearing non-code deliverable contract”를 말한다. 따라서 MAM-002의 `비파일 산출물` 표현은 정확하지 않다. 현행 [`Task.files`](../../src-tauri/src/model.rs#L157)와 [DM-04](../domain/DM-04-lifecycle.md)는 파일 변경을 요구하지만, 두 제안은 **근거 연결과 인수 판단**이라는 공통 문제를 갖는다는 비판은 맞다. 회의의 앱 내부 결정 자료와 v3의 승인된 프로젝트 파일은 저장·승인·완료 증거가 서로 다르다.

**MAM-004 반영:** `Claim/SourceRef/Assumption/Unknown/Acceptance` 같은 공통 증거 어휘와 출처 검증 계약을 제안하되, 회의 결과의 앱 내부 저장과 v3 파일 통합·QA는 별도 어댑터/완료 조건으로 둔다. 같은 화면·데이터 모델을 무조건 공유한다고 약속하지 않는다. 개정 문서에는 두 파일럿의 공통 계약과 분리 지점을 명시하고, 사용자 결정 전 어느 쪽이 첫 구현인지 확정하지 않는다. 채택 후 소유 Spec·ADR·Validation에 한 번만 규칙을 이관한다.

## MAM-003#N1 — 중단·승인 철회와 진행 중 호출

**새 쟁점(설계 추론):** 사용자가 회의를 중단하거나 전송 범위 승인을 철회해도 이미 시작한 제공자 호출을 즉시 취소할 수 있다고 약속할 수 없다. 이 구별은 MAM-002의 사용량·전송 범위 논의에 명시돼 있지 않다.

**근거(확인 사실):** [`capture_with_timeout()`](../../src-tauri/src/runtime.rs#L36)은 내부 기한 초과에서만 `child.kill()`을 호출하고 외부 취소 신호를 받지 않는다. [`send_json()`](../../src-tauri/src/runtime.rs#L150)은 동기 요청이다. [Security](../security.md)는 실행 중인 제공자 호출을 소급 수정할 수 없다고 명시한다.

**MAM-004 반영:** 첫 구현의 `중단`은 **새 호출 금지와 현재 호출의 결과를 미확정으로 기록**하는 의미로 제한한다. 이미 외부로 보낸 자료를 회수했다고 표시하지 않는다. 진짜 진행 중 취소는 런타임 취소 인터페이스와 각 제공자별 확인을 거쳐 별도 수용 기준으로 둔다.

## 사용자 결정 요청

1. **C5 — 생성된 회의 발언의 다른 제공자 전달 승인.** A: 첫 구현에서는 **실제 전송 묶음마다 미리보기·승인**(추천: 범위가 정확하고 현행 Security 경계와 충돌하지 않음). B: 목적지·생성물 종류·길이·라운드를 제한한 **회의 시작 시 일괄 승인**(자율 루프가 자연스럽지만 Security의 전송 승인 계약과 별도 검증이 선행돼야 함). 어느 선택도 이미 승인됐다고 해석하지 않는다.
